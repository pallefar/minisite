## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (clinic admin browser) → SECDEF call → Postgres | Untrusted jsonb steps cross here; permission decision happens server-side via has_permission() in Postgres. |
| client (patient browser) → mark_onboarding_complete SECDEF → Postgres | Untrusted no-arg call; SECDEF restricts mutation to auth.uid() row only. |
| anonymous client → public RPC surface | NOT crossed by this plan — no public RPCs added. (Phase 31-03 owns the public anon RPC `resolve_clinic_branding`.) |
| cross-tenant: User in Org X → Org Y's org_onboarding_flows row | Blocked at RLS layer (SELECT policy joins on org_members) + SECDEF permission gate. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-04-01 | Tampering | client → save_org_onboarding_flow steps jsonb | mitigate | `_validate_onboarding_steps(p_steps)` runs INSIDE the SECDEF body before any INSERT; raises structured error codes (`MISSING_MANDATORY_STEP`, `UNKNOWN_STEP_TYPE`, `INVALID_CUSTOM_ON_LOCKED_STEP`, `INVALID_STEPS_NOT_ARRAY`). | T-31-04-03 | Tampering | user marks another patient's onboarding complete | mitigate | `mark_onboarding_complete()` takes NO arguments and writes WHERE `id = auth.uid()`. There is no path for user A to mark user B's completion. Cross-tenant RLS test Assertion 6 proves the isolation. |
