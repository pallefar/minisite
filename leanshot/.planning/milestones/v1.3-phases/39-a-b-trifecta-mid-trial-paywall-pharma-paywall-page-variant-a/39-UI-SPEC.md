## Typography

**Source ramp:** DSv2 `--text-*` ladder in `src/index.css`. This phase uses exactly **4 sizes** and **2 weights** to pass [[reference_ui_checker_dimension_traps]] preflight.

| Role | Size | Token | Weight | Line Height | Where used |
|------|------|-------|--------|-------------|------------|
| Label | 13px | `text-sm` (`--text-sm`) | 400 | 1.5 | Tab `Pill` labels, table cell labels, Bayesian badge text, Slack channel hint, version-list metadata |
| Body | 16px | `text-base` (`--text-base`) | 400 | 1.55 | Paywall value-pillar body, pharma summary copy, dashboard table rows, drawer form inputs, error/empty body |
| Heading | 22px | `text-xl` (`--text-xl`) | 700 | 1.35 | Card titles (`CardHeader title`), modal headings, per-screen paywall headings (screens 1–5), tab section headings |
| Display | 26px | `text-2xl` (`--text-2xl`) | 700 | 1.25 | Pricing-row $-amount (paywall screen 5), final-CTA screen heading (paywall screen 6), dashboard hero metric |

**Skipped intentionally (NOT used anywhere in this phase, must NOT appear):**
- `text-caption` (10px), `text-micro` (11px), `text-xs` (12px) — preempts checker complaint about font-size proliferation.
- `text-md` (16px duplicate alias), `text-lg` (18px), `text-3xl` (32px), `text-4xl` (42px), `text-5xl` (56px), `text-display` (64px).
- Weight 600 (semibold) — collapsed into 700 (bold) to enforce strict 2-weight ramp. **Documented guarded exception:** if a downstream design need forces 600 (e.g., per-screen "Step N of 6" indicator), it MUST be approved by gsd-ui-checker in iter-2 with fallback rationale logged in `<phase>-UI-EXCEPTIONS.md`.

**Heading family:** `Geist` (sans) for all surfaces. `Fraunces` (`.font-display`) reserved for one place only: the final-CTA screen heading in surface B (per Phase 22 hero-card precedent). Marketing-grade serif accent on the conversion moment.

**Forbidden in this phase:**
- Any inline `text-[Npx]` arbitrary value. Hard-coded font-size lint rule MUST be encoded in plan task `must_haves`.
- `font-semibold` (600). Only `font-normal` (400) and `font-bold` (700) classes allowed.

### Accent (`--color-primary`) reserved-for list (EXPLICIT)

The teal accent appears ONLY on:
1. Primary CTA buttons (paywall "Start subscription", "Ship Winner", "Save variant", "Create variant", "Promote to control").
2. Active `Pill` tab indicator in surface E (3-tab dashboard nav).
3. Active per-screen progress dot in surface B (current step indicator only — inactive dots use `--color-text-tertiary` at 30% opacity).
4. `<link rel="canonical">` admin-preview marker chip on variant page-editor (per PAGEAB SEO contract).
5. Active focus ring on focusable elements (via existing `:focus-visible` global rule — already in `index.css`, no per-component override).
6. Bayesian ≥95% badge background-soft (`--color-primary-soft`, teal-100) when paired with success-tone text for "Ship at 95% confidence" affordance.

### Accent NOT-used-for list (EXPLICIT — surfaces checker will scan for violations)

The teal accent MUST NOT appear on:
- Secondary buttons ("Maybe later", "Cancel", "Dismiss") — use `variant="ghost"` or `variant="secondary"`, NOT primary.
- Inactive Pill tab labels — use `--color-text-secondary`.
- Stat cards on the dashboard — use neutral surface + numeric in `--color-text`.
- Table row hovers — use `--color-admin-table-row-hover` (cream-200).
- Pharma "always-free" safety-info badge — use `--color-success-soft` background + `--color-success` text (sage, not teal — reinforces SAFE not CTA).
- Variant-archived rows — use `--color-surface-soft` with `--color-text-tertiary` text.
- Drawer scrim — uses `--color-surface-overlay` (rgba teal-tinted at 45% opacity, NOT solid accent).

### Dark-mode parity

All semantic tokens have dark-mode counterparts already declared in `[data-theme='dark']` (verified in `src/index.css:232-317`). This phase MUST NOT introduce any color reference that bypasses the semantic-token layer. **No hex literals in component source.** Tokens-only enforcement encoded in plan `must_haves`.

## Hard Constraints (encoded for ui-checker + executor)

The following constraints are HARD: violations BLOCK plan-check + execute.

1. **Typography:** exactly 4 sizes (`text-sm`, `text-base`, `text-xl`, `text-2xl`) and 2 weights (400, 700) across ALL 5 surfaces. ZERO inline `text-[Npx]` or `font-[Nnnn]`.
2. **Spacing:** all `p-*`, `m-*`, `gap-*`, `space-*` values resolve to one of {1, 2, 4, 6, 8, 12, 16} (Tailwind units → 4/8/16/24/32/48/64px). ZERO arbitrary `[Npx]` values.
3. **Color:** ZERO hex literals in component source. ALL color references go through DSv2 semantic tokens (`bg-primary`, `text-text-secondary`, `border-border`, etc.).
4. **Accent reservation:** `--color-primary` only on the 6 elements in the reserved-for list. Checker scans for `bg-primary` / `text-primary` occurrences outside that allowlist.
5. **State management:** NO `useQuery` / `useMutation` / `QueryClient` imports. All async state via `useEffect + useState` + project's `supabase.functions.invoke()` per `CACDashboardPage` precedent.
6. **Cookie consent:** `PaywallModal` + `OnboardingFlowPaywall` MUST short-circuit if `cookieConsent.tracking !== true` (Phase 22 gate). Test enforces this.
7. **Safety-info carveout:** `PharmaContentBlock` + `PaywallGate` MUST call `phaCheck(content)` before any paywall render. ESLint rule `no-paywall-on-safety-category.cjs` enforces at build time (D-06).
8. **Ship-Winner verbatim reuse:** `ExperimentDashboardPage` Ship-Winner button MUST use the same `data-action="ship-winner"` attribute hook + `ship-winner-flag` Edge Fn call as `OnboardingABPanel.tsx`. No new Ship-Winner flow.
9. **6-screen template:** OnboardingFlowPaywall renders exactly 6 screens in fixed order: value-pillar-1 / value-pillar-2 / value-pillar-3 / social-proof / pricing / final-CTA. NO admin-configurable count.
10. **Admin module manifest + router parity:** new `growth/experiments` entry in `modules.ts` requires corresponding URL-prefix branch in `AdminShell.tsx` (mitigates [[feedback_admin_module_manifest_vs_router_branch_drift]]). Test enforces parity.
