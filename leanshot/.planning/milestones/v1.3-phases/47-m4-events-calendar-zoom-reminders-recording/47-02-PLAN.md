    Schema:
    ```
    create table if not exists public.event_rsvps (
      id                uuid primary key default gen_random_uuid(),
      event_id          uuid not null references public.events(id) on delete cascade,
      user_id           uuid not null references auth.users(id) on delete cascade,
      status            text not null check (status in ('going','maybe','not_going','waitlist')),
      waitlist_position integer,
      created_at        timestamptz not null default now(),
      updated_at        timestamptz not null default now(),
      constraint event_rsvps_unique unique (event_id, user_id),
      constraint event_rsvps_waitlist_pos_chk check ((status = 'waitlist' and waitlist_position is not null) or (status <> 'waitlist' and waitlist_position is null))
    );
    create index if not exists event_rsvps_event_status_idx on public.event_rsvps (event_id, status);
    create index if not exists event_rsvps_event_waitlist_idx on public.event_rsvps (event_id, waitlist_position) where status = 'waitlist';
    ```
    Comment on table per D-02: "RSVP rows; capacity invariant enforced by SECDEF event_rsvp_create; waitlist promotion via AFTER trigger."

    RLS policies (4 total):
    ```
    alter table public.event_rsvps enable row level security;

    create policy event_rsvps_select_self_or_staff on public.event_rsvps
      for select to authenticated
      using (user_id = auth.uid() or public.is_staff());

    create policy event_rsvps_insert_self on public.event_rsvps
      for insert to authenticated
      with check (user_id = auth.uid());

    create policy event_rsvps_update_self_or_staff on public.event_rsvps
      for update to authenticated
      using (user_id = auth.uid() or public.is_staff())
      with check (user_id = auth.uid() or public.is_staff());

    create policy event_rsvps_delete_self_or_staff on public.event_rsvps
      for delete to authenticated
      using (user_id = auth.uid() or public.is_staff());
    ```

    NOTE: The SECDEF RPC `event_rsvp_create` (47-03) bypasses RLS by definition; these client-level policies exist as defense-in-depth so a malicious client cannot fabricate a 'waitlist' row directly (status text CHECK alone wouldn't stop that, but `event_rsvps_insert_self` with the RPC enforcing "client requests going/maybe/not_going only" closes the gap).
