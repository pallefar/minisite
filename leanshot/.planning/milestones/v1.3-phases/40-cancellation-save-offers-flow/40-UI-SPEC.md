# Phase 40 — UI Design Contract

> Visual and interaction contract for Phase 40: Cancellation Save-Offers Flow.
> Generated by gsd-ui-researcher (inline orchestration). Three distinct UI surfaces.
> Design tokens derive from the project's canonical design system at `src/index.css`.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Tailwind v4 `@theme` tokens + hand-authored primitives |
| Preset | not applicable |
| Component library | Custom (`src/components/ui/` — Button, Card, Modal, Sheet, Input, Toast, Badge, Pill, ProgressRing, Skeleton, EmptyState) |
| Icon library | lucide-react ^0.460.0 |

## Spacing Scale

Project 4 px base, no phase-specific exceptions to the canonical scale.

| Token | Value | Usage in Phase 40 |
|-------|-------|--------------------|
| xs | 4 px | Icon gaps in modal CTAs, chip internal padding (reason pills) |
| sm | 8 px | Gap between modal step indicator + step content |
| md | 16 px | Default element spacing, card padding, modal body padding |
| lg | 24 px | Section padding inside the 3-step modal; admin rule-editor row padding |
| xl | 32 px | Vertical gap between modal step body and CTA row |
| 2xl | 48 px | ROI dashboard hero metric row breathing room |
| 3xl | 64 px | Not used in Phase 40 |

**Exceptions:**
- Modal step-indicator dots: 8 × 8 px circle (visual primitive, below scale; sits on the 4 px grid).
- Loss-summary chart preview: fixed 280 × 120 px viewport (matches `MedLevelChart` thumbnail spec from P35).

## Typography

Phase 40 inherits the project type scale verbatim and uses exactly 4 sizes across all 3 surfaces. No new sizes are introduced.

| Role | Token | Size | Weight | Line Height | Usage |
|------|-------|------|--------|-------------|-------|
| Body | `--text-sm` | 13 px | 400 | 1.5 | Reason picklist labels, offer-card body copy, modal subheading copy, admin rule-row metadata, ROI table cells, loss-summary stat captions |
| Label | `--text-base` | 16 px | 600 | 1.4 | Form field labels, offer-card title, ROI metric values, admin rule-row primary text |
| Subhead | `--text-lg` | 18 px | 600 | 1.4 | Modal step heading ("Why are you cancelling?", "Before you go", "We'd love to keep you"); admin tab section H1; ROI dashboard "Cohort breakdown" section heading |
| Display | `--text-xl` | 22 px | 600 | 1.35 | Loss-summary hero numbers (streak length, projected curve label); ROI dashboard hero KPI ("Revenue Recovered" tile) |

**Strict 4-size ceiling for Phase 40 surfaces.** The `--text-display` font family (`Fraunces`) is reserved for the ROI dashboard hero KPI tile only — every other surface uses `--font-sans` (Geist). Free-text reason input ("Other") uses Body (`--text-sm`).

**Mono exception:** Stripe coupon code preview chips in the admin rule editor render `var(--font-mono)` at 13 px / weight 400 — so coupon strings (`SAVE-25-3MO`) are scannable.

## Color

Derived from `src/index.css` `@theme` tokens. No new color values are introduced.

| Role | Token | Value (light) | Usage |
|------|-------|--------------|-------|
| Dominant (60%) | `--color-bg` | `#f2ede0` (cream-100) | Modal overlay backdrop tint, admin page background, ROI dashboard page background |
| Secondary (30%) | `--color-surface` | `#fefcf7` (cream-card) | Modal panel, offer card, admin rule rows, ROI metric tiles |
| Accent (10%) | `--color-primary` | `#1b4842` (teal-700) | See reserved list below |
| Destructive | `--color-danger` | `#cf5454` (clay) | Final "Cancel anyway" CTA on Step 3; "Delete rule" action in admin rule editor |
| Warning soft | `--color-warning-soft` | `#fbe4dc` (rose-soft) | Stacking-cap notice strip in admin rule editor + cancellation modal when D-15 cap fires |

**Accent (`--color-primary`) reserved for:**
- Primary CTAs that **retain** the subscription: "Accept offer" (Step 2), "Keep my account" (Step 3).
- Modal step-indicator: active dot fill + completed-dot fill.
- Reason-picklist selected state: pill background (`--color-primary-soft`) + checkmark icon (`--color-primary`).
- Save-offer modal coupon-applied badge (`Badge tone="info"` derives from primary-soft).
- ROI dashboard active filter chip + chart line color for `accepted` series.
- Admin rule-editor "Save rule" CTA + active-rule pill border.

**Destructive (`--color-danger`) reserved for:**
- Step 3 "Cancel anyway" CTA (ghost button with `--color-danger` text + `--color-danger-soft` hover bg).
- Admin "Delete rule" `<IconButton>` (Trash2 icon, danger color).
- "Pause limit reached" anti-gaming inline error in cancellation modal.

**NOT accent:**
- "Decline (continue cancellation)" link on Step 2 — uses `--color-text-secondary`, underlined on hover. Decline is intentionally visually quieter than "Accept offer" but never disguised (always plainly readable, no truncation, no off-screen positioning).
- Reason-pill unselected state — neutral border + body text.
- ROI dashboard `shown`/`declined` chart series — use semantic neutral + `--color-text-tertiary`.

**Clinic-org variant (D-04):**
- Same token palette. Step 2 offer card on `clinic-org` cancellations renders a single `OfferCard variant="contact-csm"` using `--color-info` (`teal-700`) for the icon + heading, NEVER `--color-danger`. Clinic-org cancellations are a relationship event, not an alert.

## Surface 1: Three-Step Cancellation Modal

**File (new):** `src/components/dashboard/settings/cancellation/CancellationModal.tsx` (single chunked component — per CONTEXT specifics, NOT three separate routes).

**Mount point:** Triggered from `SettingsPage` → "Account" section → "Cancel subscription" `<Button variant="ghost" tone="danger">`. Renders via `React.lazy()` (cancellation chunk; counts toward the lazy-route budget per `[[project_phase5_bundle_regression]]`).

**Container:** `<Modal>` primitive, `size="lg"` (480 px wide on desktop; full-bleed on mobile ≤640 px). `role="dialog"` `aria-modal="true"` `aria-labelledby="cancel-step-title"` `aria-describedby="cancel-step-body"`. Locks body scroll; ESC closes only on Step 1; Steps 2 + 3 require explicit dismiss via `Close` button or completing the flow (so the user can't accidentally drop mid-funnel and lose the captured reason).

**Step indicator:** Top of modal, 24 px below the modal heading. Three 8 × 8 px dots (`flex gap-2`). Active dot: `--color-primary` fill. Completed dot: `--color-primary` fill + 12 × 12 px ring around it (`box-shadow: 0 0 0 2px var(--color-primary-soft)`). Pending dot: `--color-border` fill. `aria-label="Step {N} of 3"` on the wrapper; each dot has `aria-current="step"` when active.

**Visual focal point:** The **modal body content** is the primary anchor on every step. The step-indicator and `Close` icon are secondary. CTAs always live in a fixed footer band (24 px padding, top `border-t border-[var(--color-border)]`).

### Step 1 — Reason picklist

**Heading:** "Why are you cancelling?" (`Subhead`, `id="cancel-step-title"`).
**Sub-label:** "Help us understand — your answer shapes what we offer next." (`Body`, `--color-text-secondary`, `id="cancel-step-body"`).

**Picklist layout:** Vertical stack of 7 `<Pill role="radio">` rows (NOT a horizontal pill-group — vertical stacking gives each option full width + room for the helper text). Each row:
- 48 px tall (touch target).
- `aria-checked={selected}` + `tabIndex={selected || (index === 0 && !any selected) ? 0 : -1}` (roving tabindex via existing `usePillGroup` pattern from `Pill.tsx`).
- Selected state: `bg-[var(--color-primary-soft)]` + `border border-[var(--color-primary)]` + leading `Check` icon (16 px, `--color-primary`).
- Unselected state: `bg-transparent` + `border border-[var(--color-border)]`.
- Hover: `bg-[var(--color-surface-soft)]` (unselected only).

**Reason rows in display order (D-18 verbatim):**
1. Too expensive
2. Not using it enough
3. Found an alternative
4. Health goals changed
5. Temporary break needed
6. Service quality issue
7. Other (free-text)

**"Other" expansion:** When row 7 is selected, a `<Textarea>` slides in below it (`animate-fade-in`, respects `useReducedMotion()`). Required: at least 4 trimmed characters before "Continue" enables. Max 280 chars (character counter shown at 240+, identical pattern to P31 OnboardingTab step editor). Helper: "We read every response." `aria-required="true"`. Placeholder: "Tell us what we could do better."

**Footer CTA row:**
- Right-aligned `<Button variant="primary">` "Continue" — disabled until a reason is selected (and "Other" textarea is valid when row 7 chosen). `aria-disabled` mirror.
- Left-aligned `<Button variant="ghost">` "Keep my account" — closes the modal. This is the **lightweight exit hatch** that respects user agency. Always visible.

### Step 2 — Save-offer modal (server-picked, one card)

**Heading:** "Before you go — {offer-name}" where `{offer-name}` is `"have a pause on us"` | `"keep {percent}% off"` | `"extend your trial"` | `"switch to monthly"`. (`Subhead`). For clinic-orgs (D-04): "Before you go — let's talk first".
**Sub-label:** "Personalized for you based on {tenure-bucket-copy}. Take it or continue cancelling." (`Body`, `--color-text-secondary`). `{tenure-bucket-copy}` is `"your first month"` (<30d) | `"your time so far"` (30–180d) | `"your loyalty"` (>180d).

**Offer card (single, per D-19):** `<Card variant="elevated">` with 24 px padding. Inside the card:
1. **Offer icon:** 32 × 32 px lucide icon inside a 48 × 48 px `--color-primary-soft` circle. Mapping below.
2. **Offer headline:** `Label` (16 px / 600). E.g. "Pause for 2 months — no charges". Server-rendered, no client templating beyond `{percent}` / `{months}` interpolation.
3. **Offer body copy:** `Body` (13 px / 400 / `--color-text-secondary`). Two sentences max. Explains the mechanics + cost-to-user (always zero in v1.3).
4. **Offer details strip (only when applicable):** A small 32 px tall horizontal strip below the body with `bg-[var(--color-surface-soft)]` + `rounded-md`. Renders the concrete metric: "Resumes Aug 14, 2026" for pause; "Discount applies to next 3 invoices" for discount; "New billing date: Sep 14, 2026" for extended-trial; "Save $5/month" for downgrade. `Body` size, mono font for date/dollar tokens.
5. **Stacking notice strip (CONDITIONAL — D-15 mitigation):** If the user has an active affiliate discount AND accepting the save-offer would bring the combined effective discount over the 35 % cap, render a `bg-[var(--color-warning-soft)]` strip (full-card width, 12 px padding) with `Info` icon + copy: "Your existing {X}% referral discount caps this save-offer at {Y}% effective." This strip is **always informational, never blocking** — the offer can still be accepted at the clamped value.

**Offer-type → icon mapping:**
| OfferType | lucide icon | Card variant |
|---|---|---|
| `pause` | `PauseCircle` | default |
| `discount` | `BadgePercent` | default |
| `extended_trial` | `CalendarPlus` | default |
| `downgrade` | `ArrowDownToLine` | default |
| `contact_csm` (clinic-org, D-04) | `Headset` | contact-csm |

**Pause-offer expansion (D-06):** When `OfferType=pause`, the offer card includes a `<PillGroup>` directly above the details strip with three options: "1 month", "2 months", "3 months". Default-selected: 2 months (the take-rate-highest preset; surveyed value from CONTEXT specifics). Selecting a different preset updates the details-strip `Resumes` date live. `aria-label="Pause duration"`.

**Footer CTA row:**
- Right-aligned `<Button variant="primary">` "Accept offer" — copy adapts: "Pause my account" / "Keep {percent}% off" / "Extend my trial" / "Switch to monthly". For clinic-org `contact_csm`: "Yes — have a CSM contact me".
- Left-aligned `<Button variant="ghost" size="sm">` "No thanks, continue cancellation" — `aria-label` identical, never truncated. Color: `--color-text-secondary` (NOT `--color-danger` — see "NOT accent").

**Anti-gaming inline-error variant (when D-02/D-03 fires):**
When the server returns `OFFER_INELIGIBLE_LIFETIME_CAP` or `OFFER_INELIGIBLE_COOLDOWN`, Step 2 skips the offer card and renders a 200 px-tall `<EmptyState>`:
- Icon: `ShieldCheck` (`--color-text-tertiary`).
- Heading: "No more save offers available" (`Subhead`).
- Body: "You've used your save offers this year. Continuing with cancellation." (`Body`, secondary).
- Single primary CTA: "Continue" → advances to Step 3. No "Decline" link (there is nothing to decline).

### Step 3 — Loss-summary confirmation (D-20)

**Heading:** "We'd love to keep you" (`Subhead`).
**Sub-label:** "Here's what you've built with LeanShot." (`Body`, secondary).

**Loss-summary tiles** (2 × 2 grid on desktop ≥640 px, vertical stack on mobile):

| Tile | Source | Content |
|---|---|---|
| Streak | `useStreaks` (P35) | `Display` value ("28 days") + `Body` label ("Current streak") + `Flame` icon (20 px, `--color-warning`). |
| Med-level chart preview | `MedLevelChart` thumbnail | 280 × 120 px static preview of the user's projected curve (NO interactivity — `aria-label` describes the curve in text). |
| AI coach history | `ai_messages` count | `Display` value ("142") + `Body` label ("Coach conversations") + `MessageSquare` icon. |
| Data export reminder | static | `Database` icon + body text: "Your data stays available via CSV export at any time — even after cancellation." |

**No FOMO escalation, no countdown timers, no "are you sure?" emotional pressure.** Per [[P35 D-09 ethical-only positioning]]. The tiles are informational ("here's what's there"), not coercive.

**Footer CTA row:**
- Right-aligned `<Button variant="primary">` "Keep my account" — closes the modal, returns the user to `SettingsPage`. Fires `cancellation_aborted` event with the reason + step where they aborted.
- Left-aligned `<Button variant="ghost" tone="danger">` "Cancel anyway" — opens a **non-blocking confirmation `<Toast>`** (NOT a second modal — per CONTEXT-D-16 admin-fast-action pattern adapted: optimistic destruction with 6 s undo window). Toast copy: "Cancellation scheduled — your access ends Aug 14, 2026. **Undo**". After 6 s the cancellation RPC fires (`Stripe.subscriptions.update({ cancel_at_period_end: true })`); Undo restores. The Modal closes immediately on click (visual responsiveness); the toast lives in the `SettingsPage` background.

**Service-quality-issue path (D-21):** When reason = "Service quality issue" AND cancellation completes (post-undo-window), fire `create_helpdesk_ticket` Edge Fn with subject "Feedback from cancellation: {reason summary}", tags `cancellation-feedback` + sentiment-tagged (handled server-side). No UI surface here — the ticket is invisible to the user; they receive a follow-up email via P37's email-router pattern.

### Modal close affordances

| Step | ESC closes? | Backdrop click closes? | `Close` icon visible? |
|---|---|---|---|
| 1 | Yes | Yes | Yes (top-right) |
| 2 | No (would lose reason + offer assignment) | No | Yes (top-right) — closing prompts "You'll lose the personalized offer. Continue?" inline confirmation |
| 3 | Yes | Yes | Yes |

When user dismisses mid-funnel (Steps 1–2), fire `cancellation_dismissed` event with `{step, reason_picked}` payload. Distinct from `cancellation_aborted` which fires only when the user clicks "Keep my account" on Step 3.

## Surface 2: Admin Save-Offer Rule Editor

**Location:** New `/admin/cancellation/rules` route inside `AdminShell`. Add to `ADMIN_MODULES` manifest at `src/lib/admin/modules.ts`:
- `id: 'cancellation'`
- `route: 'cancellation'` (matches `/admin/cancellation/*`)
- `title: 'Cancellation'`
- `icon: 'LogOut'` (lucide)
- `minRole: 'support_admin'` (read) / `'support_lead'` (write) — gates per P24 dual-layer pattern.
- `flag: 'admin_cancellation'` (PostHog flag, default true).

**Page layout:** Two-pane tabbed page using existing `AdminTabStrip` primitive:
- **Tab 1 — Rules** (default): the rule editor (described here).
- **Tab 2 — ROI dashboard** (Surface 3).

**Visual focal point:** The LEFT rule-list panel. The right rule-editor pane is secondary (opens inline when a rule is selected; lighter elevation than the list).

### Rule list panel (left, 40 % width on `md:`, full-width on mobile)

Heading: "Save-offer rules" (`Subhead`). Sub-label: "Active rules served to cancelling patients. Sorted by priority." (`Body`, secondary).

**Rule row** (each row = one `save_offer_rules` record):
- 64 px tall row with `flex items-center gap-3 px-4 py-3 border-b border-[var(--color-border)]`.
- Drag handle: 40 × 44 px `GripVertical` icon (`cursor-grab`), `aria-label="Reorder rule {name}"`. Drag reorders `priority` (Postgres int column).
- Cohort chip: `<Badge tone="info">` showing the targeted cohort name (e.g. "Tier 2 · 30–180 d"). Truncates with ellipsis at 24 chars.
- Rule title: `Label` (16 px / 600). Free-text admin field. Truncates at 36 chars.
- Offer summary: `Body` (13 px / secondary). One line: `"{OfferType} · {coupon-or-preset-name}"`. E.g. "discount · SAVE-25-3MO" or "pause · 2 months".
- Active toggle: `<Pill aria-pressed={rule.active}>` "Active". Toggling fires immediate `update_save_offer_rule_active` RPC (optimistic) + toast confirm. No "Save" required.
- Edit `<IconButton aria-label="Edit rule {title}">` (Pencil, 16 px). Opens the rule editor pane on the right (or as a `<Sheet>` slide-over on mobile).
- Delete `<IconButton aria-label="Delete rule {title}">` (Trash2, 16 px, `--color-danger`). Uses the optimistic-delete-with-6s-undo-toast pattern (NOT a blocking modal — per CONTEXT-D-16-style admin-fast-action).

**Empty state:** `<EmptyState>` with `ShieldOff` icon, heading "No save-offer rules yet", body "Add a rule to start showing personalized offers to cancelling patients.", primary CTA "Add rule".

**"Add rule" button:** `<Button variant="primary" leadingIcon={<Plus/>}>` "Add rule" — bottom of the rule list, opens the editor pane with a blank rule.

### Rule editor pane (right, 60 % width on `md:`)

Sticky at `md:`. `<Card variant="elevated">` with 24 px padding.

Heading: `Subhead` "{rule.title || 'New rule'}".

**Form fields (vertical stack, 16 px gap):**

1. **Rule title** (`<Input>`) — `Label` "Rule title", placeholder "e.g. Tier 2 churners — 25% off". Max 60 chars.
2. **Targeting section** — heading "Who sees this rule?" (`Label` 14 px / 600).
   - Cohort `<Select>` (label "Cohort") — populated from existing P27 `cohorts` table. Each option: cohort name + member count badge (e.g. "Tier 2 · 1,247 patients"). Search-as-you-type via existing `<SearchableSelect>` primitive.
   - Tenure window `<PillGroup>` (label "Tenure window") — 4 options: "Any", "<30 d", "30–180 d", ">180 d". Multi-select allowed (e.g., select "<30 d" AND "30–180 d" — produces a rule scoped to first 180 days). Default: "Any" (which is mutually exclusive with the others).
   - Reason scoping `<PillGroup>` (label "Triggered when reason is") — 7 options matching Step 1 reasons + "Any reason". Multi-select.
3. **Offer section** — heading "What do we offer?" (`Label`).
   - Offer type `<Select>` — 4 options matching the 4 offer types in CONTEXT D-01: Pause / Discount / Extended trial / Downgrade. (Plus `contact_csm` if `editor_org_type === 'clinic'` — gated UI.)
   - Conditional sub-fields per offer type:
     - **Pause:** `<PillGroup>` for duration preset (1 / 2 / 3 months).
     - **Discount:** `<Select>` "Coupon" — populated from the fixed catalog of 6 pre-created Stripe coupons (D-12). Each option renders the coupon code in `<span class="font-mono">` + a human-readable suffix: `"SAVE-25-3MO"` `(25% off for 3 months)`.
     - **Extended trial:** `<Select>` "Extension length" — options "+ 7 days", "+ 14 days", "+ 30 days".
     - **Downgrade:** Read-only summary card: "Annual → Monthly downgrade. Effective at next renewal. Saves user ~$X/month."
4. **Priority** (`<Input type="number">`) — `Label` "Priority (1 = highest)". Numeric input, helper: "When multiple rules match, the highest-priority rule wins."
5. **Active toggle** (`<Pill aria-pressed>`) — "Active rule" (default off for new rules).

**Footer:**
- Right-aligned `<Button variant="primary">` "Save rule" — fires `upsert_save_offer_rule` SECDEF RPC. Disabled while form is invalid. On success: toast "Rule saved." + the rule list panel refreshes.
- Left-aligned `<Button variant="ghost">` "Cancel" — discards changes, closes editor pane.

### Read-only mode (when `surfaceCheck('admin.cancellation.rules.edit')` is false)

Editor pane renders the same fields but every input is `disabled` + a banner at the top: "You have read-only access. Contact a Support Lead to edit rules." (`Body`, secondary, with `Info` icon).

Below the chart, full-width `<Card variant="flat">` 24 px padding.

Heading: "Cohort breakdown" (`Subhead`). Sub-label: "Acceptance rate per cohort × offer type." (`Body`, secondary).

- Rows: one per matching cohort (filtered).
- Cells: acceptance rate `%` (`Body`, `--text-sm`), bold when ≥ 30 %.
- "Best offer" column: cell renders a `<Badge tone="info">` with the offer type icon + name.
- Sticky first column on horizontal scroll (mobile).

### Empty state (no data in range)

`<EmptyState>` with `BarChart3` icon (lucide), heading "No cancellation data yet", body "Once patients see save-offers, results appear here. Check back after some users have cancelled.".

### Export action (top-right of dashboard, header row)

`<Button variant="ghost" size="sm" leadingIcon={<Download/>}>` "Export CSV" — fires `download_cancellation_roi_csv` Edge Fn, returns a signed URL via the existing P14 export pattern. Toast confirms "Export ready — check your downloads."

## Interaction States

All interactive elements across all 3 surfaces follow the project's existing focus/hover/active/disabled patterns from `src/components/ui/*`. No new interaction patterns introduced.

### Modal focus management

- On modal open: focus moves to the first interactive element (Step 1: the first reason pill; Step 2: the "Accept offer" button; Step 3: the "Keep my account" button).
- Focus is **trapped** inside the modal (existing `<Modal>` primitive behavior).
- On close: focus returns to the "Cancel subscription" trigger in `SettingsPage`.
- Step transitions: focus moves to the new step's heading first (programmatic focus on `id="cancel-step-title"` element with `tabIndex={-1}`), then user tabs into content. Screen reader announces step change via `aria-live="polite"` on the step indicator.

### Reason picklist keyboard a11y

| Key | Action |
|-----|--------|
| Tab | Move focus to the picklist group (first option becomes tab-targetable via roving tabindex) |
| Arrow Down / Up | Move selection between reason pills |
| Space / Enter | Select focused reason |
| Tab (when selected) | Move focus to "Continue" button (or "Other" textarea if reason 7 was just selected) |

### Toast undo affordance

The "Undo" link inside the cancellation-scheduled toast and rule-delete toast is keyboard-focusable. Toast `role="status" aria-live="polite"`. Undo link has `aria-label="Undo cancellation — restores your subscription"` / `aria-label="Undo rule deletion — restores rule {title}"`. After the 6 s window expires, the link disappears and the toast dismisses; the underlying mutation commits.

### Reduced motion

When `useReducedMotion()` returns true:
- Step transitions: instant (no slide animation).
- "Other" textarea expand: instant.
- Loss-summary tile fade-in (Step 3): instant.
- Toast slide-in: instant.
- Admin chart-bar animation on first render: disabled.

### Loading states

| Surface | State | Visual | ARIA |
|---|---|---|---|
| Step 2 offer fetch | While `cancellation-decide-offer` Edge Fn pending | Skeleton card (full offer-card footprint) for ≤ 800 ms | `aria-busy="true"` on offer card region |
| Step 3 accept-offer commit | While `pause` / `apply_coupon` RPC pending | Primary button shows spinner + label flips to "Saving…" | `aria-busy="true"` on button |
| Admin rule save | While `upsert_save_offer_rule` pending | "Save rule" button shows spinner | `aria-busy="true"` on button |
| ROI dashboard fetch | While `cancellation_offers_log` aggregate query pending | Skeleton tiles + skeleton chart bar grid | `aria-busy="true"` on dashboard region |
