# Leaderboard Cohort Enable Criteria (Phase 35 D-11)

When the admin enables `cohort_definitions.leaderboard_enabled = true` for a cohort, every member of that cohort becomes eligible to opt in to a leaderboard. This is an admin responsibility — the ethical-only positioning of LeanShot's gamification (Phase 35) places the burden of "psychological fit" on the admin.

## Enable IF the cohort meets ALL of these criteria

- **Tenure ≥ 6 months on a GLP-1.** Early-stage users (< 6mo) are in a vulnerable "is this working" window; leaderboards can drive comparison shame.
- **Cohort name suggests stability.** Names like "GLP-1 Veterans 6mo+", "Maintenance Phase", "Long-Term Tracker" signal a population that can handle comparison without harm.
- **No medical-status filter implying severity.** Cohorts segmented by side-effect severity, contraindications, or weight-loss-rate variance should NOT have leaderboards — they encourage comparing data points that are clinical, not behavioral.

## Do NOT enable IF the cohort matches ANY of these patterns

- **"Newly Diagnosed"** / "First 30 Days" / "Early Adopters" → leaderboards can intensify "doing it wrong" anxiety
- **Side-effect or symptom-severity cohorts** (e.g., "High Nausea", "Plateau Stuck") — comparison amplifies distress
- **Weight-loss-rate cohorts** (e.g., "Slow Losers", "Fast Losers") — the comparison is medical, not behavioral; harmful framing
- **Cohorts with < 20 active members** — leaderboards with < 10 visible entries feel sparse + drive over-comparison

## Operational checklist before enabling

1. Confirm cohort name passes the smell test above
2. Inspect cohort_membership count: `select count(*) from cohort_membership where cohort_id = '<id>';` — require ≥ 20
3. Inspect cohort definition tree — confirm no severity filters
4. Click "Enable Leaderboard" in `/admin/gamification` → Leaderboards tab
5. Notify the support team via the internal channel (so they can field early member questions)

## Rolling back a leaderboard enable

If user feedback indicates a leaderboard is causing harm, disable in `/admin/gamification`:

- `cohort_definitions.leaderboard_enabled = false`
- Within 15 min, the leaderboard_matview refresh excludes that cohort entirely
- Existing leaderboard_optin rows for that cohort are preserved (re-enable later is friction-free)

Quarterly: review every enabled cohort against the criteria. Disable any that no longer fit. Document the decision in this file's CHANGELOG section.
