<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin SPA → get_cac_summary() RPC | SECDEF enforces is_admin(); anon clients get nothing |
| Admin SPA → ad_etl_health direct table read | RLS admin-only policy; non-admin gets 0 rows |
| Admin SPA → ad-spend-cron ETL (Backfill button) | supabase.functions.invoke uses anon key + auth JWT; Edge Fn validates service-role bearer — this creates a mismatch |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33-05-01 | Elevation of Privilege | Non-admin reads ad ETL tables | mitigate | RLS deny on all 7 tables; 8 denial tests in ad-etl-tables.test.ts prove zero-row behavior |
| T-33-05-02 | Spoofing | Backfill button triggers ETL — who can invoke? | mitigate | Edge Fn requires service-role bearer; browser anon client cannot call it directly. Backfill button must route through a SECDEF RPC or admin-authenticated Edge Fn invoke pattern. Wire via `supabase.functions.invoke` with admin JWT — add a trigger RPC `public.trigger_ad_etl_backfill(p_network, p_date)` SECDEF that calls pg_net.http_post internally with service-role key from vault. NOTE: This pattern must be added to Plan 33-01 migration or handled here via an addendum. Flag in plan-checker. |
| T-33-05-03 | Information Disclosure | CAC summary data visible to non-admin SPA routes | mitigate | get_cac_summary() has is_admin() guard; component only renders in admin shell (minRole:'admin') |
| T-33-05-04 | Tampering | CSV export contains all campaign data — could expose vendor relationships | accept | Admin-only surface; data is non-PHI (spend figures, campaign IDs); admin role implies trust |

IMPORTANT NOTE for plan-checker (T-33-05-02): The Backfill button cannot directly invoke a service-role-gated Edge Function from the browser. The correct pattern is a SECDEF `public.trigger_ad_etl_backfill(p_network text, p_date date)` SQL function that: (1) checks is_admin(auth.uid()); (2) calls pg_net.http_post to the ETL Edge Fn with the service-role key from `current_setting('app.service_role_key')`. This RPC must be added to Plan 33-01 (migration 11 or a new migration 12) or as an addendum. Flag this as a missing integration seam for plan-checker to catch.
</threat_model>
