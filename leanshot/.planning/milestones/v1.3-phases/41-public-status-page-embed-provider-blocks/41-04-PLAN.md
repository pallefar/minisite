<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Popup browser window → PageEditor opener | `postMessage` carries access token. Origin validation is the security boundary. |
| Edge Fn → Calendly OAuth token endpoint | Client secret crosses here; MUST remain server-side. |
| PageEditor → Edge Fn (start) | Authenticated user JWT; gate ensures only staff+ can start OAuth flow. |
| Browser localStorage → token | Token MUST NEVER land here (in-memory closure only). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-41-04-01 | Spoofing | Malicious page posts fake `calendly-oauth-result` to PageEditor opener | mitigate | postMessage handler FIRST guard: `if (event.origin !== 'https://calendly.com' && event.origin !== 'https://auth.calendly.com' && event.origin !== window.location.origin) return;` — Test 4 in Task 2 explicitly verifies the rejection path. |
| T-41-04-02 | Information Disclosure | Access token leaked via `postMessage` wildcard targetOrigin | mitigate | Edge Fn callback uses `LEANSHOT_APP_ORIGIN` as exact targetOrigin in `postMessage(..., targetOrigin)` — Task 1 verify gate greps for forbidden `postMessage.*'\\*'` literal pattern. |
| T-41-04-03 | Information Disclosure | Client secret bundled to browser | mitigate | Secret is `Deno.env.get('CALENDLY_OAUTH_CLIENT_SECRET')` — server-side only. Editor JS never references it; ENV var pattern verified by user_setup gate. |
