## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pg_cron→Edge Fn | pg_cron net.http_post HTTP-Bearer call to Edge Fn URL — Bearer token from vault.decrypted_secrets; non-cron callers blocked by service_role-only auth |
| Edge Fn→Resend | Outbound HTTPS call to api.resend.com with API key from Function Secret; PHI lint enforces no PHI in payload |
| Edge Fn→Realtime | supabase-js channel.send broadcast — anon key sender, HMAC channel name validates on subscriber side (Phase 28 realtime_topic_authorized) |
| Edge Fn→DB | service_role client via withOrgScope wrapper; ORG_SCOPED_TABLES Set (Plan 30-00) covers the 3 new tables |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-01-01 | Information disclosure | Resend email body leaks patient name/diagnosis | mitigate | D-02 PHI-stripped template (no patient field substitution) + CI PHI lint scans the Edge Fn directory + Task 2 test asserts body regex |
| T-30-01-02 | Information disclosure | Resend email subject leaks PHI (e.g., includes patient name) | mitigate | Subject hard-coded as `New clinical alert — ${org_name}`; PHI lint + Task 2 assertion |
| T-30-01-03 | Tampering | Replay attack: third party calls Edge Fn URL with crafted alert ID | mitigate | Edge Fn URL is Bearer-token-gated by pg_cron's service_role token from Vault; public callers without service_role token get 401 |
| T-30-01-04 | Denial of service | Resend rate-limit or outage stalls retry loop | mitigate | Per-alert try/catch; loop continues on failure; retry_count caps at 3 → status='delivery_failed' + Sentry alert; total retry window ~1h matches CLIN-04 SC |
| T-30-01-05 | Spoofing | Edge Fn sends broadcast to wrong org's channel | mitigate | channelNameFromSecret derives HMAC from `(orgId, suffix)` + Vault secret; subscriber side validates HMAC match + JWT org_ids claim (Phase 28 realtime_topic_authorized) |

| T-30-01-07 | Tampering | Edge Fn marks alert delivery_failed prematurely (network blip) | mitigate | 3-retry window over ~1h before terminal state; Plan 30-05 includes Playwright e2e proving retry recovery |
