<objective>
Ship the `generate-course-certificate` Edge Fn that (a) verifies course completion via `complete_course` SECDEF RPC, (b) renders a landscape PDF cert with jsPDF + jspdf-autotable + qrcode (all via esm.sh in Deno per the dsar-export pattern), (c) uploads to the private `certificates` Storage bucket, (d) computes the HMAC verification token using the SAME base64url replace-chain as the browser-side helper (Plan 46-03), (e) UPDATEs the certificates row with the real `verification_token` + `pdf_path`, (f) returns a 60-min signed download URL.

Purpose: COURSE-04 has three failure modes if any primitive is wrong:
1. jsPDF Deno path broken → no PDF → no cert.
2. HMAC payload format diverges from browser → /verify/<id> always fails.
3. qrcode canvas unavailable → no QR → cert is functional but PR-poor.

Therefore Wave-0-within-this-plan starts with a throwaway Deno smoke test of `esm.sh/qrcode@1.5.4?target=denonext` to determine which path (PNG via toDataURL OR SVG via toString) works in Deno Edge Runtime BEFORE writing cert-render.ts.

Output: 1 new Edge Fn (3 source files + deno.json + 2 test files) + 1 smoke-test file.
</objective>
