<objective>
Extend the two existing Mux Edge Fns (deployed in Phase 44 for community posts) to handle a new `kind: 'course-lesson'` discriminator: `mux-create-upload` adds an admin-only branch that creates SIGNED-policy uploads with a 30-min duration cap, and `mux-webhook` dispatches asset-lifecycle events to either `community_posts` (existing) or `course_lessons` (new) based on `passthrough.kind`. Both extensions preserve the existing community-post path intact.

Purpose: This is the upload + transcode + ready notification half of COURSE-02. Without it, admins can't upload course videos, and even if they could, the webhook wouldn't know to update `course_lessons` rows (it would keep updating `community_posts`).

Critical divergences from community-post path (per RESEARCH corrections 7, 9 + Pitfall 1):
1. `playback_policies: ['signed']` — community uses `['public']`; courses MUST use `['signed']` so Plan 46-04's JWT Fn is actually required.
2. Admin-only gate via `public.is_staff()` — community accepts any Pro/Lifetime/Trial user.
3. `max_duration_seconds: 1800` — community caps at 300 (5 min).
4. NO `video.view` handler in webhook — this Mux event does not exist.

Output: Both Edge Fns modified in-place; both test files extended with new branches.
</objective>
