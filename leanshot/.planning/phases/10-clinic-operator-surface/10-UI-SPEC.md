# Phase 10 — UI Design Contract

> Visual and interaction contract for the Clinic Operator Surface — roster view, ranking, read-only patient drill-in (`ReadOnlyPatientView` extracted from Phase 8 SharePage), org-owner Audit tab, per-patient "View activity" mirror modal, and operator bulk affordances. Generated by gsd-ui-researcher (inline), to be verified by gsd-ui-checker.

Inherits the LeanShot v2 design system declared in `src/index.css` (`@theme` tokens) and the Phase 9 UI contract. This phase introduces NO new design language — every spacing/typography/color value is pulled from existing tokens. All net-new components compose existing primitives (`Card`, `Button`, `Modal`, `Sheet`, `Input`, `Pill`, `Badge`, `EmptyState`, `Skeleton`, `Confirm`, `Toast`) plus the Phase 9 net-new components (`ClinicWorkspace`, `ClinicContextBar`, `WorkspaceSwitcher`, `ClinicSettingsPage`).

The clinic operator surface MUST look and feel continuous with both the patient app and the Phase 8/9 chrome. The drill-in `ReadOnlyPatientView` is the SAME component the share recipient (Phase 8) sees — only the chrome (`ClinicContextBar` vs `CodeEntryScreen`) and a `permissionMap` prop differ.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Tailwind v4 beta with CSS `@theme` tokens) |
| Preset | not applicable |
| Component library | none — internal primitives at `src/components/ui/` (Button, Card, Modal, Sheet, Input, Toast, EmptyState, Pill, Badge, Confirm, IconButton, Skeleton, ProgressRing) |
| Icon library | `lucide-react` ^0.460.0. New icons used this phase: `ListFilter`, `ArrowUp`, `ArrowDown`, `ArrowUpDown`, `TrendingUp`, `TrendingDown`, `Minus`, `AlertCircle`, `Activity`, `ChevronRight`, `ChevronLeft`, `History`, `FileDown`, `FileText`, `ExternalLink`, `Square` (unchecked), `CheckSquare` (checked), `MinusSquare` (indeterminate). Reused from Phase 8/9: `Building2`, `Users`, `Shield`, `Eye`, `Stethoscope`, `Image`, `Clock`, `User as UserIcon`, `XCircle`, `RefreshCw`. |
| Font | Inter (sans, body/UI), Fraunces (display headings — used for the success state of bulk actions only), JetBrains Mono (`tnum`) for score numerals + audit timestamps |

**Rationale:** Phase 9 closed without introducing a UI library; Phase 10 keeps the index ceiling at 50 kB gz (currently ~24.5 kB after Phase 9). Adding shadcn at Phase 10 would (a) fight the bundle ceiling, (b) drift the visual language between operator and patient mid-product. The clinic chrome is operator-facing but lives in the same `auth.users` identity as the patient app — they need to feel like one product (Pitfall #8 single-identity invariant carry-forward).

## Spacing Scale

Tailwind v4 `--spacing: 0.25rem` (4px base). All values below are multiples of 4. Source: `src/index.css:122`. Identical to Phase 8/9 UI-SPECs.

| Token | Value | Usage (this phase) |
|-------|-------|--------------------|
| 1 | 4px | Icon-to-label gaps inside score chips and trend arrows |
| 2 | 8px | Compact metadata stack inside roster row signal cells; checkbox-to-label gap in bulk-select header |
| 3 | 12px | Audit row internal padding; gap between filter chips on Audit tab |
| 4 | 16px | Default vertical/horizontal gap between roster rows; Modal body padding; gap between mobile roster cards |
| 6 | 24px | Section padding inside Audit tab card; gap between roster and pagination footer |
| 8 | 32px | Page-level vertical rhythm on workspace home (between context bar / filter row / roster table / pagination) |
| 12 | 48px | Empty-roster vertical padding; "no audit events" empty-state padding |
| 16 | 64px | Maximum content gap; mobile drill-in top margin under sticky context bar |

**Touch-target exception:** Roster row checkbox uses 40×40px hit area (matches Phase 9 `IconButton size="md"` pattern); the visible checkbox glyph is 20×20px centered (multiple of 4 to preserve grid alignment). Roster row itself is `min-h: 56px` (desktop) / `min-h: 80px` (mobile card) — drill-in is the primary affordance, so the entire row is clickable EXCEPT the checkbox cell (event-stop on the checkbox prevents drill-in). Score chip on roster row is 32×24px pill (read-only, not interactive).

Exceptions: none beyond the row + checkbox sizing already established.

## Typography

Source: `src/index.css:79-110`. This phase uses **exactly 4 sizes** + `text-sm font-mono` for numerals/timestamps, and **2 weights** (400 regular + 600 semibold). Italic 400 Fraunces is permitted ONLY for the bulk-action success-state heading (Phase 8/9 carry-forward of display-heading convention).

| Role | Size | Weight | Line Height | Font | Token |
|------|------|--------|-------------|------|-------|
| Body | 15px (0.9375rem) | 400 | 1.55 | Inter | `text-base` |
| Label / metadata | 13px (0.8125rem) | 400 | 1.5 | Inter | `text-sm` |
| Heading (section/modal/tab/audit-row actor name) | 18px (1.125rem) | 600 | 1.5 | Inter | `text-lg` |
| Page heading (workspace home `Roster`, drill-in patient name, Audit tab title, modal titles) | 26px (1.625rem) | 600 | 1.25 | Inter | `text-2xl` |
| Score numeral on chip + audit timestamp + `Days since` numeric cell | 13px | 600 | 1 | JetBrains Mono `tnum` | `text-sm font-mono numerals-tabular` |
| Display (Fraunces italic) — bulk-action success heading only | 26px italic | 400 | 1.25 | Fraunces | `text-2xl heading-display` |

**Numerals contract:** All score values, last-dose deltas (`3 days ago`), days-since-injection counts, and audit-timestamp cells MUST use `numerals-tabular` so digits align column-wise across rows. Matches Phase 6/7/8/9 settings number presentation.

**Permission-key contract (audit row metadata expansion):** When an audit row's expandable metadata exposes a permission key like `patient_data.read` or an action enum like `rank_threshold_crossed`, it renders in `font-mono text-sm` so operators scan it like code identifiers. Plain-language description renders in `text-sm` regular weight on the line below.

**Reduced-motion:** Roster row Realtime flash highlight (D-17), drill-in modal slide-in, bulk-action progress toast slide-in, and audit row expand/collapse all honor `prefers-reduced-motion: reduce` via the existing global CSS rule at `index.css:485`. Threshold-cross toast uses opacity fade only when reduced-motion is active.

## Color

Inherits Phase 8/9 60/30/10 distribution. Source tokens: `src/index.css:11-77` (light) + `:158-203` (dark).

| Role | Light value | Dark value | Usage (this phase) |
|------|-------------|------------|--------------------|
| Dominant (60%) | `--color-bg` `#efebe0` (cream-100) | `#0b1413` (teal-950) | Workspace home page background, drill-in page background, Audit tab page background, all modal backdrops |
| Secondary (30%) | `--color-surface` `#fdfbf6` (cream-card) | `#16201e` (teal-900-ish) | Roster table card, mobile roster card, drill-in section cards, Audit row card, "View activity" modal body, bulk-action selection bar |
| Accent (10%) | `--color-primary` `#1b4842` (teal-700) | `#6fcbb8` (teal-300) | Primary CTAs only (see reserved-for list); focus rings; selected-row left-edge stripe; active sort-direction arrow; system-role badge fill in audit rows; selected checkbox fill |
| Destructive | `--color-danger` `#cf5454` (clay) | `#da6f6f` | Bulk action error toast icon, hard-401 toast on operator drill-in, bulk-action partial-failure summary chip |
| Warning | `--color-warning` `#e37748` (orange) | `#e37748` | Score chip background when score ≥ 70 ("needs attention" — D-22 threshold), threshold-cross toast icon, bulk-action "tab cap exceeded" inline notice — NOT used as a CTA |
| Sage (positive) | `--color-sage` `#45b077` | `#45b077` | Trend-up arrow on weight-trend column when goal direction is "up"; trend-down arrow when goal is "down"; score chip background when score 0-29 ("healthy") |

**Score chip color contract (D-22 + D-24 buckets):**
- Score `0-29` ("low" / "healthy"): `--color-sage` background, white text
- Score `30-69` ("mid" / "monitor"): `--color-text-secondary` background (neutral teal), cream-card text
- Score `70-100` ("high" / "needs attention"): `--color-warning` background, white text

Score values are always shown as integers with no decimals. Dark mode uses the same hue tokens — contrast verified against the dark surface token below.

**Accent reserved-for list (the only places `--color-primary` appears as a fill or strong stroke):**
1. Primary CTA buttons: `Refresh roster`, `Apply filters`, `Clear filters`, `Export selected as PDF`, `Export selected as CSV`, `Open all in tabs`, `Done` (in bulk-action success modal), `Close` (audit modal)
2. Focus-visible outline (existing `:focus-visible` rule at `index.css:298`)
3. Selected-checkbox fill in roster bulk-select column
4. Active sort-direction arrow on currently-sorted roster column header (e.g. `ArrowDown` filled when sorting DESC by `score`)
5. Drill-in `ChevronRight` row affordance on hover/focus (the row's clickable hint)
6. Active filter chip on Audit tab (e.g. `Member: Sarah Chen ✕` chip background)
7. "Active" pill on audit row when displaying an in-progress operator session (rare; only fires for `section_view` rows from the past 60s)

**Accent NOT used for:**
- Body text
- Card backgrounds
- Disabled states (use `--color-text-tertiary`)
- Non-primary buttons (use `secondary` or `ghost` Button variants)
- Trend arrows on roster (use sage / warning / `--color-text-tertiary` for flat)
- Score chips (use the score-bucket palette above)

**Destructive reserved-for list:**
1. Hard-401 toast (D-10/D-11 carry-forward from Phase 9): `XCircle` icon in `--color-danger` when patient revokes during operator drill-in
2. Bulk-action error toast: `XCircle` icon in `--color-danger` when PDF/CSV export fails
3. Bulk-action partial-failure summary inside post-action modal: `Failed: {N}` chip in destructive tone
4. Audit row `revoke` and `member.revoke` action verb tag rendered in destructive-toned Pill (visual cue that the action removed access)

No typed-confirm destructive actions in Phase 10 — operator drill-in, audit viewing, bulk export are all read-only. Any new destructive surface MUST follow Phase 7/8/9 typed-confirm pattern, but Phase 10 doesn't introduce one.

**Warning reserved-for list:**
1. Score chip background when score ≥ 70 (D-22 "needs attention" threshold)
2. Threshold-cross toast icon (`AlertCircle` in `--color-warning`) when a patient's score crosses 70 during a Realtime update
3. Bulk-action "tab cap exceeded" inline notice when operator selects > 5 patients for `Open all in tabs` action
4. Roster row warning glyph (`AlertCircle` in `--color-warning` next to `Days since injection` cell) when value > 14 days for an active patient

**Color contrast notes:** Score chip warning `#e37748` on white text → 3.71:1 (passes AA only for ≥18px). Score numerals use `text-sm` 13px so we use `--color-text-on-warning` (cream `#0f302c` deep-teal) instead of white — verified 7.8:1 contrast. Sage `#45b077` on white text → 3.04:1 — score numerals on sage chip use `--color-text-on-sage` deep-teal token (8.1:1). Audit row destructive Pill uses cream text on clay `#cf5454` → 4.59:1 (AA passes for 13px text — same as Phase 8/9).

## Interaction Contracts

### Roster load + sort (D-01, D-05, D-06)

1. Operator navigates to `/clinic/{slug}` → `ClinicWorkspace` (Phase 9) renders → on mount, fires `rank_org_patients(p_org_id)` RPC.
2. Skeleton renders 8 placeholder rows during fetch.
3. RPC returns 50/page (or fewer) with score + signal columns. `RosterTable` renders rows, sorted by score DESC by default.
4. Operator clicks a column header (e.g. `Last dose`) → re-fires RPC with `p_sort_column='last_injection_at'` + `p_sort_direction='desc'`. Sort arrow icon (`ArrowDown`) renders in `--color-primary` on the active column; other columns show `ArrowUpDown` in tertiary.
5. Operator clicks the same column again → toggle direction (`ArrowUp`). Third click → reverts to default sort by score DESC + clears active-column arrow.
6. Pagination footer renders `Previous` / `Next` buttons + `Showing X–Y of N` count. Click → re-fires RPC with offset.
7. Refresh button (`RefreshCw` icon, top-right of roster card) → re-fires RPC with current sort + offset. `Refreshed {relative-time}` hint updates.
8. Passive 30s refresh: every 30 seconds while the tab is active, auto-fires the RPC and updates the data. Timer resets on manual refresh, sort change, or pagination.
9. **Realtime signal-column updates (D-16):** Subscribe to `org-{org_id}` Realtime channel from Phase 9. On `injections`/`weights`/`symptoms` INSERT broadcast (server-filtered), patch ONLY the affected row's signal columns in place. Score is NOT recomputed per event — only on next 30s refresh or manual refresh.
10. **Row flash (D-17):** Updated row briefly fades from 50% accent-tint background back to default surface over 200ms, respecting `prefers-reduced-motion`.

### Roster row drill-in (D-03, D-15)

1. Operator clicks any roster row (anywhere except the bulk-select checkbox cell) → routes to `/clinic/{slug}/patient/{user_id}` → `ClinicDrillInPage` mounts.
2. `ClinicDrillInPage` calls `clinic-snapshot` Edge Function with `org_id` + `patient_user_id` + operator JWT.
3. Edge Function (D-04): validates JWT → checks membership active → checks `has_permission(operator, org_id, 'patient_data.read')` → checks patient's `consent_scope` covers requested sections → returns SnapshotResponse with `viewer_context: 'clinic'` + `permission_map`.
4. `ClinicDrillInPage` renders `<ClinicContextBar>` (Phase 9 unchanged) + `<ClinicDrillInSubBar>` (back / patient name / refresh) + `<ReadOnlyPatientView snapshot={...} viewerMode='clinic' permissionMap={...} />`.
5. **Section permission gating (D-12):** Sections the operator's role can't access are NOT rendered. No placeholder, no "no access" message. The drill-in just shows fewer sections. Mirrors Phase 9 NAV gating.
6. **Per-section audit fire (D-21):** Each visible body section (`InjectionsSection`, `WeightsSection`, `SymptomsSection`, `PhotosSection`, `DoctorReportSection`, `ChartSection`) calls `log_clinic_view(org_id, patient_user_id, section_name)` SECURITY DEFINER RPC ONCE on first mount per drill-in session (debounced 1s). Posthog `clinic_drill_section_expanded` event fires alongside.
7. Back button (sub-bar) → routes to `/clinic/{slug}` (preserves prior sort + offset + bulk selection).
8. Refresh button (sub-bar) → re-fires `clinic-snapshot` Edge Function.
9. View-activity button (sub-bar) → opens `PatientActivityModal` scoped to this org × patient pair.
10. **401 handling (carry-forward):** If patient revoked mid-session, Edge Function returns 401 → toast `{patient first name} revoked access. Returning to roster.` + auto-route back to `/clinic/{slug}` after 1s (per Phase 9 SC#5 carry-forward).
11. **403 handling:** If consent_scope changes mid-session reducing what's visible, the affected section unmounts in-place + toast `{patient first name} updated what they share…` (per Phase 9 carry-forward).

### Roster bulk affordances (D-22, D-23)

1. Operator clicks the bulk-select checkbox on any row → row's checkbox glyph fills with accent. Selected count appears in `RosterBulkSelectionBar` at top-right of roster card: `{N} selected · Clear · Actions ▾`.
2. Operator clicks header `Select all visible` → all visible rows on current page select. State is `indeterminate` if some rows on visible page are selected; `checked` if all visible are selected.
3. Selection persists across pagination clicks AND sort changes within same session. Clicking `Clear` resets selection.
4. Operator clicks `Actions ▾` → dropdown menu (or Sheet on mobile) with 3 options.
5. **PDF flow:** Operator clicks `View latest reports as bulk PDF` → confirmation modal with N count → `Generate PDF` → toast `Building PDF…` + spinner → BulkExportPDFFlow dynamically imports `jspdf` → assembles PDF (one section per patient, honoring `permission_map` and `consent_scope`) → on success: toast `PDF ready for {N} patients.` with `Download` action OR (when N≥10) modal with Fraunces success heading + `Download PDF` CTA. Per-included-patient audit row written via `log_bulk_export_inclusion(org_id, patient_user_id, 'pdf')` RPC.
6. **CSV flow:** Operator clicks `Export symptoms (last 30d) as CSV` → confirmation modal → `Download CSV` → BulkExportCSVFlow assembles plain CSV server-side via Edge Function (`bulk-csv-export`) → browser download triggered → toast `CSV downloaded.` Per-included-patient audit row.
7. **Open-in-tabs flow:** Operator clicks `Open all in tabs` → confirmation modal. If N≤5: `Open tabs` → `window.open()` loop with 100ms stagger to avoid pop-up blocking. If N>5: confirmation body warns about cap, only opens first 5. Audit rows fire as each opened tab mounts (handled by D-21 section audit, NOT explicit bulk audit).
8. **Mobile bulk-select UX:** On mobile (< 768px), tap-to-drill is the primary affordance. Long-press (500ms) on any card switches to selection mode → selection-bar slides up from bottom with action menu. Tap on additional cards toggles their selection. Tap `X` on selection bar exits selection mode.

### Audit tab load + filter (D-07, D-08)

1. Operator navigates to `/clinic/{slug}/settings/audit` → `AuditTab` mounts.
2. Tab is gated by `has_permission(viewer, org_id, 'audit_log.read')` — for users without this permission, the tab is NOT in the nav (no 403 page; absence-of-tab is the gate).
3. On mount, fires `GET /audit-events` Edge Function with default filter `time_range='last_7_days'`.
4. Skeleton rows render during fetch; `Showing {N} events` count updates on completion.
5. Operator clicks any of the 3 filter triggers → dropdown opens with options. Selecting a filter sets state; the trigger re-renders to show the active filter chip with `X` to clear.
6. Filter changes are debounced 200ms then re-fire the Edge Function with new params. Result count and row list update.
7. Custom time range opens `AuditCustomRangeModal` with `From` / `To` date inputs. `Apply` validates range (from ≤ to, to ≤ today, range ≤ 13 months) then closes modal + applies filter.
8. Pagination footer + `Previous` / `Next` (50 rows per page).
9. Each row: collapsed format renders the canonical line. Click on row → expand to show `font-mono text-sm` event-details block. Click again → collapse. Multiple rows can be expanded simultaneously.
10. Empty state when filters return zero rows: `No events match your filters` + `Clear filters` CTA.
11. 13-month retention notice renders dismissibly above the filter row (per-session dismissal, no persistence).
12. Network/server error → inline error block + `Retry` button (replaces row list, filter row stays interactive).

### Patient-side: View activity modal (D-19, D-20, fills Phase 9 D-15 stub)

1. Patient opens Settings → Active organizations tab (Phase 9 D-15) → clicks `View activity` IconButton on any membership row → `PatientActivityModal` opens.
2. Modal fetches via `GET /patient-activity?org_id={...}` Edge Function with patient JWT. RLS scope: `target_user_id = auth.uid() AND org_id = {org_id}`.
3. Modal opens to `Operator views` tab by default. Tab nav switches between `Operator views` and `Ranking events`.
4. Each tab paginates 25 rows per page; `Previous` / `Next` buttons.
5. **Operator views tab:** rows show `{relative-time} — {actor display name} ({role badge}) viewed your {section name}`. Actor display name falls back to `a clinic member` per D-20.
6. **Ranking events tab:** rows show the threshold-crossing summary line. Each row has a `Why?` link → expands to show `Score: {N}/100. Top contributing signals: ...` from the audit row's `breakdown_snapshot` metadata. Re-clicking collapses.
7. Both tabs end with the HBNR/WMHMDA defensible footer (always visible at modal bottom).
8. Modal close button → returns focus to the Active organizations row's `View activity` IconButton (focus-trap discipline).
9. Empty states per tab as specified in copywriting.
10. Network/server error → inline error block + `Retry` button.
