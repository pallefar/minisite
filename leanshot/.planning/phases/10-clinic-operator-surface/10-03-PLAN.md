    Author `supabase/migrations/20260901000004_clinic_realtime_broadcast_triggers.sql`:

    ```sql
    CREATE OR REPLACE FUNCTION public.broadcast_patient_signal_change()
    RETURNS TRIGGER
    LANGUAGE plpgsql
    SECURITY DEFINER
    SET search_path = public, extensions, pg_catalog
    AS $$
    DECLARE
      v_section text := TG_ARGV[0];  -- 'injections' | 'weights' | 'symptoms'
      v_org_id uuid;
      v_payload jsonb;
    BEGIN
      v_payload := jsonb_build_object(
        'event', 'patient_signal_change',
        'user_id', NEW.user_id,
        'section', v_section,
        'changed_at', COALESCE(NEW.created_at, NEW.recorded_at, now())
      );

      FOR v_org_id IN
        SELECT m.org_id
        FROM public.memberships m
        WHERE m.user_id = NEW.user_id
          AND m.revoked_at IS NULL
          AND COALESCE((m.consent_scope ->> v_section)::bool, false) = true
      LOOP
        PERFORM realtime.send(
          v_payload,
          'patient_signal_change',
          'org-' || v_org_id::text,
          true  -- broadcast (private)
        );
      END LOOP;

      RETURN NEW;
    END;
    $$;

    -- Three AFTER INSERT triggers, one per table
    DROP TRIGGER IF EXISTS injections_clinic_broadcast ON public.injections;
    CREATE TRIGGER injections_clinic_broadcast
      AFTER INSERT ON public.injections
      FOR EACH ROW EXECUTE FUNCTION public.broadcast_patient_signal_change('injections');

    DROP TRIGGER IF EXISTS weights_clinic_broadcast ON public.weights;
    CREATE TRIGGER weights_clinic_broadcast
      AFTER INSERT ON public.weights
      FOR EACH ROW EXECUTE FUNCTION public.broadcast_patient_signal_change('weights');

    DROP TRIGGER IF EXISTS symptoms_clinic_broadcast ON public.symptoms;
    CREATE TRIGGER symptoms_clinic_broadcast
      AFTER INSERT ON public.symptoms
      FOR EACH ROW EXECUTE FUNCTION public.broadcast_patient_signal_change('symptoms');

    REVOKE ALL ON FUNCTION public.broadcast_patient_signal_change() FROM public;
    -- Trigger function does NOT need GRANT EXECUTE — it's invoked by trigger system, not directly by clients.
    ```

    **Critical implementation notes:**
    - The `realtime.send` API signature in Supabase 2.x is `realtime.send(payload jsonb, event text, topic text, private bool)`. If the local Supabase version uses `realtime.broadcast` instead, executor MUST adapt — check `\df realtime.*` against the live DB before authoring.
    - The NEW row's timestamp column varies: `injections.created_at`, `weights.recorded_at`, `symptoms.recorded_at`. Use COALESCE to pick the right one without per-table conditional code.
    - Server-side filter on consent_scope is the security floor — no client-side filtering. If consent_scope is missing (default null), the COALESCE returns false and the broadcast is suppressed.
    - The Phase 9 RLS on `realtime.messages` (`20260801000012_realtime_messages_rls.sql`) already gates SUBSCRIBE — operators without `org.read` permission on a given org can't subscribe to `org-{org_id}` anyway. The trigger is server-emit; the RLS is subscribe-side. Together they form defense in depth.
