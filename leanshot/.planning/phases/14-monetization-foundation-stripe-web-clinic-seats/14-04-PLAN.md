<objective>
Ship the `stripe-checkout` Edge Function — a single Deno.serve dispatcher with two JWT-authenticated POST endpoints:

1. `/session` — creates a Stripe Checkout session for either web (`plus_monthly` | `plus_yearly`) or clinic (hybrid base + metered overage per D-01), enforcing `trial_period_days=7` + `payment_method_collection='always'` (D-13, Pitfall 4).
2. `/portal` — creates a Stripe Customer Portal session for managing payment method, plan changes, and cancellation (MONEY-03).

Purpose: Deliver the first user-observable monetization slice — an authenticated user can POST `/session`, receive a Checkout URL, visit it, enter a card, and land on the in-app success page (tier flip itself comes from the webhook in 14-03 + Wave 3 tier slice; this plan ships the doorway).

Output: 4 new files in `supabase/functions/stripe-checkout/` + a Wave-0 A3 sandbox confirmation artifact under `.planning/phases/14-.../14-04-A3-RESULT.md`.

Implements: **D-01** (hybrid clinic billing structure), **D-12** (Checkout not Elements), **D-13** (7-day card-required trial), **D-15** (RLS not exposed — function uses admin client + JWT for user identity).
</objective>

- **Pitfall 5 (manual step in SUMMARY):** Customer Portal `return_url` must be in Stripe Dashboard Portal allow-list. Phase 14 plan SUMMARY surfaces this as a post-deploy manual checkpoint. Pre-canonical URL: `${PUBLIC_APP_ORIGIN}/settings?from=portal`.

- **D-01 (clinic hybrid):** Clinic-mode session MUST attach BOTH `STRIPE_PRICE_CLINIC_BASE` and `STRIPE_PRICE_CLINIC_OVERAGE` in `line_items`, each with `quantity: 1`. Metered price ignores quantity at billing; the explicit `quantity: 1` is required by the Stripe Node SDK type signature per RESEARCH Pattern 2.
- **A3 sandbox confirmation (Wave-0):** Before writing the implementation, run a 30-min manual sandbox check (Stripe test mode) that the combined-line_items Checkout renders cleanly. - **Webhook is source of truth (D-14):** `/session` MUST NOT pre-create rows in `subscriptions`. The webhook (14-03) is responsible for writing `subscriptions` on `checkout.session.completed`. This function only ensures the `stripe_customers` / `clinic_stripe_customers` mapping exists (so we have a stable Stripe customer ID for repeat checkouts).
- **JWT auth NEVER cookies (Pitfall #11 inherited from clinic-invite):** No `Set-Cookie`. CORS wildcard origin OK. Web app calls via `fetch(... , { headers: { Authorization: 'Bearer ' + accessToken }})`.

- **Pathspec discipline (Wave 2 parallel with 14-03 per Pattern F):** All commits in this plan use `git commit -- supabase/functions/stripe-checkout` to isolate from the parallel 14-03 (`supabase/functions/stripe-webhook`) plan.

|----------|-------------|
| Browser → Edge Function | Untrusted JWT-bearing POST from the React app; Authorization header is the only auth signal |
| Edge Function → Stripe API | Outbound HTTPS bearing `STRIPE_SECRET_KEY`; treated as trusted vendor |

| Stripe → Browser (Checkout / Portal redirect) | Vendor-hosted; return URLs must be on Stripe Dashboard allow-list (Pitfall 5) |
