<objective>
Close **CR-04** — both `invoice.*` webhook handlers read `invoice.subscription_status`, a field that does NOT exist on any Stripe Invoice object in any API version. The `as unknown as { subscription_status?: string }` cast suppresses the type error; at runtime the field is always `undefined`, so the local `subStatus` always defaults to `'active'`.

The concrete consequence in `invoice-payment-failed.ts`: `mapStripeStatusToUxTier('active')` returns `'paid'`, so a real `invoice.payment_failed` webhook writes `ux_tier='paid'` and `status='active'` — the **exact inverse** of the dunning trigger. A card failure *clears* the past_due state instead of setting it.

`invoice-paid.ts` is benign by luck (paid maps to active maps to `'paid'`), but it is structurally broken the same way and carries dead code (`invoiceObj` + `void invoiceObj`).

The fix follows the VERIFICATION.md "missing:" prescription: do NOT derive tier from a non-existent field. `invoice.payment_failed` *by definition* means dunning has started — write `ux_tier='past_due'` directly. `invoice.paid` *by definition* means the payment succeeded — write `ux_tier='paid'` directly. Both events carry the real `invoice.subscription` ID, which is all that is needed to scope the UPDATE.

Purpose: Re-satisfy MONEY-09 (card failure → past_due banner; clears on retry — server flip) and the MONEY-01 webhook-correctness portion. Unblocks SC#4.

Output: 2 surgical handler rewrites + their 2 Deno test files updated.
