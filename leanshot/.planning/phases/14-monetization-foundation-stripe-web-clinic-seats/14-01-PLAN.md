## RLS policies

All 4 tables `ENABLE ROW LEVEL SECURITY`. Policies:

- **`subscriptions`** — SELECT only (no INSERT/UPDATE/DELETE from authenticated; webhook writes via service_role):
  ```
  CREATE POLICY "users read own sub" ON public.subscriptions FOR SELECT TO authenticated
    USING (
      auth.uid() = user_id
      OR (clinic_id IS NOT NULL
          AND public.has_permission(auth.uid(), clinic_id, 'billing'))
    );
  ```
  Note: D-15 + CONTEXT line 161 require `has_permission` from Phase 9 — confirm the permission key. Phase 9 used `members.list`/`org.update`/etc. For billing-read use `'billing'` (new permission key); if not yet registered in Phase 9's permission catalog, fall back to a `clinic_memberships` EXISTS check on `role IN ('owner','admin')` mirroring 14-RESEARCH.md lines 660-666. **Executor decision:** check `public.has_permission` exists by name AND test it accepts `'billing'` as the third arg via a one-off `select public.has_permission('00000000-...'::uuid, '00000000-...'::uuid, 'billing')`; if it errors with `permission_not_found` or similar, use the EXISTS clinic_memberships fallback. Pick one approach for this migration and stay consistent.

- **`stripe_customers`** — SELECT only:
  ```
  CREATE POLICY "users read own customer" ON public.stripe_customers FOR SELECT TO authenticated
    USING (auth.uid() = user_id);
  ```

- **`clinic_stripe_customers`** — SELECT only:
  ```
  CREATE POLICY "clinic admins read clinic customer" ON public.clinic_stripe_customers FOR SELECT TO authenticated
    USING (
      EXISTS (
        SELECT 1 FROM public.clinic_memberships m
        WHERE m.clinic_id = clinic_stripe_customers.clinic_id
          AND m.user_id = auth.uid()
          AND m.status = 'active'
          AND m.role IN ('owner','admin')
      )
    );
  ```

- **`subscription_events`** — NO policies (RLS enabled with zero policies = deny-all for authenticated; only service_role bypasses RLS). Add an explicit comment in the migration: `-- subscription_events: service_role only; no policies = deny-all for authenticated.`

## SECURITY DEFINER counter function

```
CREATE OR REPLACE FUNCTION public.count_active_patients(p_clinic_id uuid)
RETURNS integer
LANGUAGE sql
SECURITY DEFINER
SET search_path = public, extensions
STABLE
AS $$
  SELECT COUNT(DISTINCT m.user_id)::integer
  FROM public.clinic_memberships m
  WHERE m.clinic_id = p_clinic_id
    AND m.status = 'active'
    AND m.role = 'patient'
    AND EXISTS (
      SELECT 1 FROM public.injections i WHERE i.user_id = m.user_id AND i.created_at > now() - interval '30 days'
      UNION ALL SELECT 1 FROM public.weights w WHERE w.user_id = m.user_id AND w.created_at > now() - interval '30 days'
      UNION ALL SELECT 1 FROM public.meals me WHERE me.user_id = m.user_id AND me.created_at > now() - interval '30 days'
      UNION ALL SELECT 1 FROM public.workouts wo WHERE wo.user_id = m.user_id AND wo.created_at > now() - interval '30 days'
      UNION ALL SELECT 1 FROM public.symptoms s WHERE s.user_id = m.user_id AND s.created_at > now() - interval '30 days'
      LIMIT 1
    );
$$;
REVOKE ALL ON FUNCTION public.count_active_patients(uuid) FROM PUBLIC;
GRANT EXECUTE ON FUNCTION public.count_active_patients(uuid) TO service_role;
GRANT EXECUTE ON FUNCTION public.count_active_patients(uuid) TO authenticated;
```

**Caller-side gating for `authenticated`:** Because Phase 14's counter is consumed only by 14-07 (server-side cron/webhook running as service_role) AND surfaced as a billing summary to clinic admins in Wave 3 (14-05 / 14-06), grant authenticated EXECUTE but the function MUST refuse the call when the caller lacks `billing` permission on the clinic. Add inside the function body (preferred — single statement gates both auth contexts):

Switch the function `LANGUAGE` to `plpgsql` (not `sql`) so we can `RAISE EXCEPTION` on unauthorized authenticated callers:

```
CREATE OR REPLACE FUNCTION public.count_active_patients(p_clinic_id uuid)
RETURNS integer
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, extensions
STABLE
AS $$
DECLARE
  v_uid uuid := auth.uid();
  v_count integer;
BEGIN
  -- Service-role bypass: when called from an Edge Function with the service-role
  -- JWT, auth.uid() is null. Allow.
  -- Authenticated bypass: require billing permission OR fall back to
  -- clinic_memberships role check if has_permission('billing') is not registered.
  IF v_uid IS NOT NULL THEN
    IF NOT EXISTS (
      SELECT 1 FROM public.clinic_memberships m
      WHERE m.clinic_id = p_clinic_id
        AND m.user_id = v_uid
        AND m.status = 'active'
        AND m.role IN ('owner','admin')
    ) THEN
      RAISE EXCEPTION 'forbidden' USING errcode = '42501';
    END IF;
  END IF;

  SELECT COUNT(DISTINCT m.user_id)::integer INTO v_count
  FROM public.clinic_memberships m
  WHERE m.clinic_id = p_clinic_id
    AND m.status = 'active'
    AND m.role = 'patient'
    AND EXISTS (
      SELECT 1 FROM public.injections i WHERE i.user_id = m.user_id AND i.created_at > now() - interval '30 days'
      UNION ALL SELECT 1 FROM public.weights w WHERE w.user_id = m.user_id AND w.created_at > now() - interval '30 days'
      UNION ALL SELECT 1 FROM public.meals me WHERE me.user_id = m.user_id AND me.created_at > now() - interval '30 days'
      UNION ALL SELECT 1 FROM public.workouts wo WHERE wo.user_id = m.user_id AND wo.created_at > now() - interval '30 days'
      UNION ALL SELECT 1 FROM public.symptoms s WHERE s.user_id = m.user_id AND s.created_at > now() - interval '30 days'
      LIMIT 1
    );

  RETURN v_count;
END;
$$;
REVOKE ALL ON FUNCTION public.count_active_patients(uuid) FROM PUBLIC;
GRANT EXECUTE ON FUNCTION public.count_active_patients(uuid) TO service_role;
GRANT EXECUTE ON FUNCTION public.count_active_patients(uuid) TO authenticated;
```
