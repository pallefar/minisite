<objective>
Close the three lower-priority but real gap-closure findings — the test-hygiene cluster. These do not block the monetization runtime the way CR-01/CR-02/CR-04 do, but they leave Phase 14's verification surface dishonest: a hollow e2e that cannot prove SC#3, a latent runtime-break SDK version split, and a SQL test that may error before its assertion.

**CR-03 — Stripe SDK version split.** `leanshot/package.json` pins `stripe@^17.7.0` (used by the Node-side bootstrap script + all 3 e2e fixtures), while the Edge Functions import `stripe@19` via `supabase/functions/import_map.json`, and every file hard-codes `apiVersion: '2026-04-22.dahlia'` (a v17 SDK does not type that version or guarantee the request shapes — `stripe-bootstrap.ts` already casts via `as` to suppress the error). Reconcile: pin the npm `stripe` devDependency to `^19.x`.

**WR-09 — hollow clinic-metered-billing e2e.** `clinic-metered-billing.spec.ts` calls `stripe.billing.meterEventSummaries.list('mtr_test_placeholder', ...)` with a literal placeholder ID — that call always throws, the test falls into the `catch`, and the cascading fallbacks end with `meterEventFound = webhookResp.status === 200`. The final assertion only throws `if (!meterEventFound && webhookResp.status !== 200)`. Net effect: the test passes on a webhook 200 alone — SC#3 / MONEY-05 ("11 active patients → overage=1") is never actually proven. Fix: read the real meter ID from `process.env.STRIPE_METER_ACTIVE_PATIENTS`, assert `aggregated_value === 1`, remove the status-code escape hatch, and `test.skip` (not pass) when the meter env var is absent.

**CR-05 — invalid enum + column drift in SQL/e2e test data.** `count-active-patients.test.sql:77` and `:81` insert `site = 'abdomen'`, which is not a valid `InjectionSite` value (`src/types/index.ts:27-35`: `abdomen-ul | abdomen-ur | abdomen-ll | abdomen-lr | thigh-l | thigh-r | arm-l | arm-r` — no bare `'abdomen'`). The clinic e2e fixture (`clinic-metered-billing.spec.ts:141-149`) repeats `site: 'abdomen'` AND uses `date` + `dose_unit` column names, while the live `injections` schema uses `logged_at` + `unit` + a required `log_id` PK component. Fix to valid enum values and reconcile the e2e fixture insert to the live schema.

Purpose: Re-satisfy the MONEY-05 (clinic metered billing — make SC#3 actually provable) and MONEY-01 (webhook correctness — consistent SDK) test-confidence portions. Affects SC#3 confidence.

Output: 1 dependency repin (`package.json` + lockfile), 1 e2e spec rewrite, 1 SQL test fix.
