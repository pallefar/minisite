<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anon role → anonymous_sessions | Untrusted browser cookie holders must NOT be able to read other sessions or enumerate. Deny-all RLS + service-role-only access. |
| authenticated → onboarding_flows | Any signed-in user can READ active flow config (needed by hook); writes deny-all → SECDEF only. |
| authenticated → activation_events | User can read OWN row only; writes deny-all → service-role Edge Fn only. |
| authenticated (non-superadmin) → save_consumer_onboarding_flow | Function-level check rejects non-superadmin callers with 42501 even if RLS would otherwise allow. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-01-01 | Spoofing | anonymous_sessions | mitigate | `cookie_id` is server-generated UUID (gen_random_uuid in Plan 34-02); deny-all RLS means even guessing a cookie_id grants no DB access from anon role |
| T-34-01-02 | Information Disclosure | anonymous_sessions | mitigate | Force RLS + no permissive policies; service-role only via merge Edge Fn (Plan 34-05) |
| T-34-01-03 | Elevation of Privilege | save_consumer_onboarding_flow | mitigate | Function body checks `admin_role = 'superadmin'` from profiles; advisory lock prevents concurrent version increments; audit_logs row captures every save |
| T-34-01-04 | Tampering | onboarding_flows | mitigate | INSERT/UPDATE/DELETE deny-all RLS; only SECDEF mutates; partial unique index makes "two active flows" structurally impossible |
| T-34-01-05 | Information Disclosure | activation_events | mitigate | User-self-read policy (`user_id = auth.uid()`); writes via service-role only |
| T-34-01-06 | Repudiation | save_consumer_onboarding_flow | mitigate | Audit log row with `actor = auth.uid()`, `action = 'consumer_onboarding_flow.save'`, before/after JSONB diff (mirrors Phase 31 pattern) |
| T-34-01-07 | Denial of Service | onboarding_flows partial unique index | accept | Index conflict on `is_active=true` is a feature not a bug — atomically swapped inside the SECDEF advisory-lock window |
</threat_model>
