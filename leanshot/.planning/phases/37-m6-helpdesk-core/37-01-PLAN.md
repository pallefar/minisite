Create migration `20270707000003_helpdesk_secdef_rpcs.sql` with all SECURITY DEFINER RPCs needed by Edge Fns and the frontend. Per [[reference_supabase_migration_gotchas]], every SECDEF function MUST set `search_path` explicitly to `public, extensions`. Per [[feedback_planner_iter1_anti_patterns]] every SECDEF function must `revoke execute … from public` then `grant execute … to authenticated` (or `service_role` where appropriate).

RPCs:

1. **`generate_helpdesk_reply_token(p_ticket_id uuid, p_user_id uuid) returns text`** — vault-secret-backed HMAC.
   - Reads `helpdesk_hmac_secret` from `vault.decrypted_secrets`.
   - Computes `encode(hmac(p_ticket_id::text || ':' || p_user_id::text, secret, 'sha256'), 'base64')` then strips `=`, replaces `+`→`-`, `/`→`_` (base64url).
   - Returns the token.
   - `grant execute … to authenticated, service_role`.
   - Uses `pgcrypto.hmac` — must `create extension if not exists pgcrypto with schema extensions;` in file (no-op if present).

2. **`verify_helpdesk_reply_token(p_token text, p_ticket_id uuid, p_user_id uuid) returns boolean`** — constant-time compare in SQL.
   - Recompute expected token same as (1).
   - Constant-time compare via `length(p_token) = length(expected) and bit_or(...) = 0` pattern; concretely use the standard `length-prefix XOR` SQL trick OR a single SQL bytea XOR using `decode(...,'base64')` length-checked. Recommended: `do $$ … $$` block returning boolean via `octet_length` equality + a per-byte XOR aggregate. Avoid early-return; always iterate full length.
   - `grant execute … to service_role` only. (Frontend doesn't verify — Edge Fn does.)

3. **`close_ticket(p_ticket_id uuid, p_resolution_note text) returns void`** — agent-only, audited.
   - Asserts caller is in `org_members` for `tickets.org_id`.
   - Updates `tickets` set `status='closed', closed_at = now(), updated_at = now()` where id = p_ticket_id.
   - Inserts a `ticket_messages` row with `author_kind='system'`, `body=p_resolution_note`, `via='admin'`.
   - `grant execute … to authenticated`.

4. **`reopen_ticket(p_ticket_id uuid, p_reason text) returns void`** — agent OR owner.
   - Asserts caller is `tickets.user_id` OR in `org_members`.
   - Updates `tickets` set `status='open', closed_at=null, updated_at=now()`.
   - Inserts system message with reason.
   - `grant execute … to authenticated`.

5. **`apply_ai_suggestion(p_suggestion_id uuid) returns void`** — agent-only.
   - Reads `ticket_ai_suggestions` row.
   - For each tag in `suggested_tags` with `confidence >= 0.75`, INSERT INTO `ticket_tags(ticket_id, tag_name, confidence, applied_by='ai')` ON CONFLICT DO NOTHING.
   - If `suggested_route_user_id` AND `suggested_route_confidence >= 0.75`, UPDATE `tickets.assigned_to`.
   - Sets `ticket_ai_suggestions.applied_at = now()`.
   - `grant execute … to authenticated`.

6. **`search_kb_articles(p_query text, p_locale text default 'en', p_org_id uuid default null, p_limit int default 10) returns table(...)`** — used by KB typeahead.
   - Stub here; the FTS body lives in Plan 02 (where the GENERATED tsvector columns are added). For this migration, create the function with a trivial body that returns no rows; Plan 02 replaces via `create or replace function`. This forces Plan 02 to be a same-API replacement.
   - Returns: `id uuid, slug text, title text, locale text, rank real`.
   - `grant execute … to authenticated`.

```sql
create or replace function public.create_ticket_with_first_message(
  p_subject text,
  p_body text,
  p_priority text default 'p3'
) returns uuid
language plpgsql
security definer
set search_path = public, extensions
as $fn$
declare
  v_user_id uuid := auth.uid();
  v_org_id uuid;
  v_is_clinician boolean := false;
  v_phi boolean;
  v_ticket_id uuid;
begin
  if v_user_id is null then
    raise exception 'unauthenticated' using errcode = '42501';
  end if;
  if p_subject is null or length(trim(p_subject)) = 0 or length(p_subject) > 200 then
    raise exception 'invalid_subject' using errcode = '22023';
  end if;
  if p_body is null or length(trim(p_body)) = 0 then
    raise exception 'invalid_body' using errcode = '22023';
  end if;
  if p_priority not in ('p1','p2','p3','p4') then
    raise exception 'invalid_priority' using errcode = '22023';
  end if;

  -- Resolve primary org + clinician role (PHI gate per D-01)
  select primary_org_id into v_org_id from public.profiles where id = v_user_id;
  select exists (
    select 1 from public.org_members om
    where om.user_id = v_user_id and om.role in ('owner','clinician','staff')
  ) into v_is_clinician;
  v_phi := v_is_clinician;

  insert into public.tickets (user_id, org_id, subject, priority, phi, status, source)
    values (v_user_id, v_org_id, p_subject, p_priority, v_phi, 'open', 'widget')
    returning id into v_ticket_id;

  insert into public.ticket_messages (ticket_id, author_user_id, body, author_kind)
    values (v_ticket_id, v_user_id, p_body, 'user');

  return v_ticket_id;
end;
$fn$;

revoke execute on function public.create_ticket_with_first_message(text, text, text) from public, anon;
grant execute on function public.create_ticket_with_first_message(text, text, text) to authenticated;
```
