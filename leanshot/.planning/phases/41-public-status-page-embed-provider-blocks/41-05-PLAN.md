<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| consent-banner state → embed render | Consent state crosses into the decision to load the iframe. Must read state at mount AND subscribe (defense against race). |
| Admin-pasted KB body → DOM | KB authors paste markdown that can include `<embed-block>` HTML tags. dompurify is the strip-stage. |
| iframe content → parent page | Once consented, provider scripts execute inside the sandbox. Sandbox flags are the trust boundary. |
| allowlist DB row → CustomIframeBlock render decision | Live allowlist gates whether a Custom-iframe URL renders. Race: row removed between fetch and render → fail closed (validator returns null → error placeholder). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-41-05-01 | Tampering | iframe DOM kept with src='' on consent revoke → provider continues to set cookies | mitigate | ConsentGatedEmbed conditionally renders the iframe element — on revoke, the element is REMOVED from the React tree (Task 1 Test 3 explicitly asserts querySelector('iframe') returns null). Documented in RESEARCH §Anti-Patterns + UI-SPEC §Surface B revoke section. |
| T-41-05-02 | Tampering | Race: HOC mounts after consent already granted → listener attached after the event fired → embed never loads | mitigate | useEffect reads CookieConsent.acceptedCategory(...) SYNCHRONOUSLY at mount before subscribing (Task 1 Test 4 covers). |
| T-41-05-03 | Elevation of Privilege | Custom-iframe block bypasses allowlist via client-only check | mitigate | CustomIframeBlock validation is the editor-side UX check; server-side validation in Plan 41-03 render.ts is authoritative for published pages. Plan 41-02 RPC validation is authoritative for hostname adds. Three-layer defense. |
| T-41-05-04 | Tampering | Admin-pasted KB body contains `<script>` via `<embed-block>` attribute | mitigate | dompurify ADD_ATTR allowlist restricted to type/data-url/data-id/data-allow ONLY — no `onerror`, no `style`, no event handlers; default dompurify html-profile already blocks `<script>` (verified Phase 50 / KB editor existing behavior). |
