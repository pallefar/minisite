# Phase 41 — UI Design Contract

> Visual and interaction contract for the Phase 41 surfaces: public status page (Better Stack hosted), public-facing embed-block render (consent-gated), PageEditor embed configuration, Calendly inline preview (popup-OAuth), and `/admin/embeds/allowlist` superadmin UI. Generated by gsd-ui-researcher.

**Surfaces in scope (from orchestrator brief):**
- **A** — Better Stack hosted public status page at `status.leanshot.app` (branding config only — Better Stack hosts the UI).
- **B** — Public-facing embed block render (Calendly / YouTube / Tally / Custom-iframe) on landing pages + KB articles. Pre-consent placeholder card + post-consent iframe with Skeleton loader.
- **C** — PageEditor block-config panel for the new `custom_iframe` block type (existing Phase 15 PROPERTY_CONFIGS already cover calendly/youtube/tally; this phase adds the 4th provider and harmonises validation surfaces).
- **D** — PageEditor Calendly inline preview (popup-OAuth, NOT nested iframe — V13-EMBED pitfall).
- **E** — Superadmin Custom-iframe allowlist UI at `/admin/embeds/allowlist`.

**Exceptions:**
- **Touch targets:** All interactive controls (add-hostname button, Remove button, "Connect Calendly" button, "Manage cookie preferences" link, inline iframe-load retry, allowlist row "remove" icon button) have a minimum **44×44px hit area** even when visual size is smaller (use `min-h-[44px] min-w-[44px]` + `inline-flex items-center justify-center` on icon-only buttons; this matches `IconButtonProps` precedent + WCAG 2.5.5 target size).
- **Iframe content area:** Iframe inner dimensions are provider-driven (Calendly 700px height recommended, YouTube 16:9 aspect-ratio, Tally provider-set) — `aspect-ratio: 16/9` for YouTube, `min-height: 700px` for Calendly, `min-height: 500px` for Tally, `min-height: 400px` for Custom-iframe. These are not spacing-scale violations — they are provider container constraints, not LeanShot-controlled spacing.

## Surface-by-surface Visual Contract

### Surface B — Public-facing embed block render (consent-gated)

**Three states per embed block, in this order:**

**State 1 — Pre-consent (consent required category NOT yet granted):**
- DSv2 `Card variant="default" padding="lg"` (24px outer padding, `--color-surface` background, `--radius-card` 24px corner radius, `--shadow` 6px-16px box-shadow).
- Inner layout (top-to-bottom, 16px gap):
  1. **Provider logo** at 32×32px (Calendly/YouTube/Tally lockup SVG OR a `lucide-react Video` / `Calendar` / `FileText` / `ExternalLink` icon for Custom-iframe at `size={32}` `color="--color-text-secondary"`).
  2. **Heading L2** (`--text-xl` 22px semibold) — copy per D-08, sentence case, no exclamation:
     - Calendly: "Enable functional and analytics cookies to view this Calendly meeting"
     - YouTube: "Enable analytics and marketing cookies to view this YouTube video"
     - Tally: "Enable functional cookies to view this Tally form"
     - Custom-iframe: "Enable marketing cookies to view this embed"
  3. **Body caption** (`--text-xs` 12px, `--color-text-secondary`) — single line: "Required: [Functional | Analytics | Marketing] cookies. We never load this content until you opt in."
  4. **Inline link** (`--text-sm` 13px, `--color-primary` 600 weight) — "Manage cookie preferences →" — opens the Phase 22 consent banner via `window.dispatchEvent(new CustomEvent('leanshot:open-consent-banner'))` (or whichever event the P22 banner subscribes to — planner verifies).
- **No** "Connect" or per-provider CTAs (those live in the editor only).

**State 2 — Loading (consent granted, iframe not yet `onLoad`'d):**
- Same Card outer shell.
- DSv2 `Skeleton` primitive fills the inner area at the provider's required dimensions:
  - YouTube: full-width × `aspect-ratio: 16/9`.
  - Calendly: full-width × `min-height: 700px`.
  - Tally: full-width × `min-height: 500px`.
  - Custom-iframe: full-width × `min-height: 400px`.
- Skeleton renders a single rectangle with `--color-skeleton` background + shimmer animation (already configured; class `skeleton-shimmer` is suppressed under `prefers-reduced-motion: reduce` per existing `src/index.css:638`).

**State 3 — Loaded:**
- Iframe with `loading="lazy"` attribute (D-claude-discretion-7) + provider-specific sandbox flags hardcoded by block type:
  - Calendly: `sandbox="allow-scripts allow-same-origin allow-popups allow-forms"` (Calendly docs require popups for confirm step).
  - YouTube: `sandbox="allow-scripts allow-same-origin allow-presentation"`.
  - Tally: `sandbox="allow-scripts allow-same-origin allow-forms"`.
  - Custom-iframe: `sandbox="allow-scripts allow-same-origin"` (FIXED per D-16; no admin override).
- Iframe `onLoad` transitions opacity `0 → 1` over **200ms** using `--duration-quick` + `--ease-out-quart`, **gated by `useReducedMotion()`** (skip transition if reduced motion is preferred — per D-10 and existing project pattern).
- Iframe replaces (not overlays) the Skeleton — Skeleton unmounts on `onLoad` to free DOM.

**Cross-state transition (consent grant while State 1 visible):**
- D-09 — block subscribes to Phase 22 consent-change event. On grant of the required category, block transitions State 1 → State 2 → State 3 **without page reload**. The State 1 → State 2 transition is also opacity 0→1 200ms (reduced-motion gated).

**Consent decline / category-toggle-off:**
- Block reverts to State 1; iframe `src` is set to empty + iframe element is unmounted (do NOT keep iframe DOM around with `src=""` — Calendly/YouTube still set cookies on stale `src`). Already-loaded provider scripts cannot be unloaded; this is documented as an accepted limitation (consent-revocation requires page reload for full cleanup — surface as a tertiary-text caption when revoke happens: "Refresh the page to fully remove this embed").

**KB-article surface (EMBED-06):** Identical State 1/2/3 contract — same render component used in `page-builder` block renderer AND KB article markdown renderer.

### Surface D — Calendly inline preview (popup-OAuth)

**Preview thumbnail card inside the PageEditor property panel (only when block type = `calendly`):**

- 320×180px (16:9) Card at `padding="md"`, `variant="default"`.
- Three states:

**State D1 — Unauthenticated (no Calendly OAuth token in session):**
- Card background `--color-surface`.
- Centered 40×40px Calendly logo (color SVG asset, full opacity).
- Below logo: `--text-sm` 13px `--color-text-secondary`: "Connect your Calendly account to preview availability."
- Primary CTA below: DSv2 `Button variant="primary" size="md"` — label "Connect Calendly". Click handler opens `window.open('/api/calendly/oauth-start', 'calendly_oauth', 'width=560,height=720,popup=yes')` (planner picks exact OAuth start URL).

**State D2 — Popup-OAuth in progress:**
- CTA replaced by a DSv2 `Spinner size="md"` + tertiary-text "Waiting for Calendly confirmation in popup window…"
- Cancel link below the spinner — `--color-text-secondary` `--text-xs` — "Cancel" (closes popup via `ref.close()`).

**State D2-error — Popup blocked:**
- Card border switches to `--color-danger`.
- Inline error icon (lucide `ShieldAlert` size 20px `--color-danger`) + body copy: "Popup blocked. Allow popups for this site to connect Calendly."
- Retry CTA: Button `variant="ghost"` — "Try again".
- Secondary link below: `--text-xs` `--color-text-secondary` — "Open Calendly settings in new tab" (fallback escape — sets `target="_blank"`).

**State D3 — Authenticated, preview loaded:**
- Card body shows the configured Calendly URL hostname in `font-mono` `--text-sm` + connected-account email in `--text-xs --color-text-secondary`.
- Live availability preview via Calendly's embed widget rendered INSIDE the editor property panel (this is the editor surface — sandbox + CSP still apply, but no nested OAuth — token is already in session).
- "Disconnect" link below — `--text-xs` `--color-text-secondary` — clears the in-memory OAuth token (per Claude's discretion in D-CONTEXT: token storage shape is in-memory only or sessionStorage; planner picks).

**postMessage origin validation (planner-owned per D-CONTEXT):** Only accept postMessage events where `event.origin === 'https://calendly.com'` (and the LeanShot OAuth callback origin). Reject all others silently. Error UX on validation failure: log to Sentry + show State D2-error.

### Surface E — Superadmin allowlist UI at `/admin/embeds/allowlist`

**Page shell:** Renders inside the existing `AdminShell` (manifest-driven; planner adds a new `ADMIN_MODULES` entry with `{key:'embeds', label:'Embeds', route:'embeds/allowlist', icon: ShieldCheckIcon, minRole:'superadmin', flagKey:'admin.embeds.enabled'}`).

**Header section** (padding `xl` = 32px around):
- H1 `--text-2xl` 26px semibold: "Custom iframe allowlist"
- Subtitle `--text-base` 16px `--color-text-secondary`: "Hostnames on this list can be embedded via the Custom-iframe block on landing pages and KB articles. Exact-match only — no wildcards or subdomains."

**Add-hostname form** (Card `variant="elevated"` `padding="lg"`, top margin `lg` = 24px):
- Inline form layout — horizontal stack, gap `md` = 16px:
  - `Input` (label "Hostname", placeholder `meet.example.com`, hint `--text-xs --color-text-secondary` "Exact hostname only — do not include `https://`, paths, or wildcards.")
  - `Button variant="primary"` — label "Add hostname".
- Validation rules (planner enforces server-side AND client-side):
  - Empty → "Hostname is required"
  - Contains `://` → "Enter hostname only — no protocol"
  - Contains `/` or `?` → "Enter hostname only — no path or query"
  - Contains `*` or starts with `.` → "Wildcards and leading dots are not supported"
  - Already on allowlist → "[hostname] is already on the allowlist"
- On success: optimistic insert into table + DSv2 `Toast` `tone="success"` (uses existing `useToast` hook): "Added [hostname] to allowlist".
- On audit-log write success: silent (audit row is server-side per P25 schema; D-17 90d retention).

**Allowlist table** (Card `variant="flat"` outer, `--color-admin-table-row` row bg, dividers in `--color-border`):

| Column | Width | Cell content |
|--------|-------|--------------|
| Hostname | flex-1 | `font-mono` `--text-sm`, copy-to-clipboard affordance on hover (icon button, 44×44 hit area) |
| Added by | 160px | Avatar (DSv2 `InitialsAvatar` size sm) + admin email in `--text-xs --color-text-secondary` |
| Added | 120px | Relative timestamp ("3 days ago"), tabular-nums; tooltip on hover with absolute ISO timestamp |
| Last used | 120px | Relative timestamp OR "Never" in `--color-text-tertiary` italic if `last_used_at IS NULL`; tabular-nums |
| References | 100px | Badge — `--color-success-soft` when count = 0 + label "Unused"; `--color-warning-soft` when count ≥ 1 + label "[N] page[s]". Clicking the badge opens a Sheet (DSv2 `Sheet` primitive) listing the referencing pages with deep-links into PageEditor |
| Actions | 80px | Icon-only "Remove" button (lucide `Trash2` size 20px `--color-danger`), 44×44 hit area, opens DSv2 `Confirm` modal |

**Sort:** Default sort = Added desc (newest first). Column headers click-sortable — sortable visual cue is a lucide `ChevronUp`/`ChevronDown` icon next to the active column header, `--text-xs --color-text-tertiary`.

**Remove confirmation modal** (DSv2 `Confirm` primitive):
- Title: "Remove [hostname] from allowlist?"
- Body variants (planner picks based on reference count):
  - 0 references: "This hostname is not in use on any page. Removing it stops future embeds — existing pages are unaffected because no page references it."
  - ≥1 reference: "[N] page[s] currently embed this hostname. Removing it will break those embeds — visitors will see a 'Hostname not on allowlist' error on those pages. Confirm only if you have already updated those pages." (use `--color-danger-soft` banner inside modal)
- Confirm CTA: `variant="danger"` — "Remove hostname"
- Cancel CTA: `variant="ghost"` — "Keep on allowlist"

**Empty state** (table has 0 rows — fresh deployment):
- DSv2 `EmptyState` primitive, centered, `padding="2xl"`:
  - Icon: lucide `ShieldOff` size 48px `--color-text-tertiary`
  - Heading: "No hostnames on the allowlist yet"
  - Body: "Add the first hostname above. Any page using the Custom-iframe block requires its hostname here first — exact match only."
  - No secondary CTA (the add-form above is the primary path).

**Loading state** (initial fetch):
- 5 Skeleton rows (each row is 56px tall — matches typical table row height), `--color-skeleton`, shimmer animation respects reduced-motion.

**Error state** (fetch failure):
- DSv2 `Card variant="flat"` with `--color-danger-soft` background, icon lucide `WifiOff` `--color-danger`, body copy: "We couldn't load the allowlist. Check your connection and try again.", `Button variant="primary"` — "Retry".
