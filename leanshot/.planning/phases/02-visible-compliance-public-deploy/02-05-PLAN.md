**Insertion strategy**:

The fallback modal renders ALONGSIDE the dashboard, NOT instead of it (per D-11 wording: "render the same blocking modal **over** the dashboard"). The Modal primitive's `position: fixed inset-0 z-[100]` ensures it visually blocks the dashboard. The user can perceive the dashboard chrome beneath, but cannot interact (the Modal's backdrop swallows pointer events, and per 02-02 `dismissible={false}` means backdrop clicks do nothing).

Add the modal mount inside the dashboard return JSX, alongside the other lazy overlays:
```tsx
{needsDisclaimer && (
  <DisclaimerModal
    open
    onAcknowledge={() => useStore.getState().acknowledgeDisclaimer('v1')}
  />
)}
```

**Fire-once analytics** (D-11 inferred + EventName from 02-03):

```typescript
useEffect(() => {
  if (needsDisclaimer) {
    track('disclaimer_required', { surface: 'dashboard' });
  }
}, [needsDisclaimer]);
```

Note: this fires whenever `needsDisclaimer` transitions from false→true OR mounts true. The user-visible flicker is acceptable; the alternative (refs + manual once-flag) is more code for marginal value. Document the choice in the SUMMARY.

**Should the onboarding branch also mount the modal?** No — D-08's Step 0 already covers onboarding. The fallback is for the `view === 'dashboard'` branch ONLY. Onboarding-flow users who haven't reached Step 0 yet will be on Step 0 and see the inline disclaimer there.
