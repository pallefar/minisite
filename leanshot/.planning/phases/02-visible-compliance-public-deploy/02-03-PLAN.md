**Grep exit-code inversion** (RESEARCH gotcha #5):

`grep` exits **0 on match**, **1 on no-match**. The job's success condition is **no match** = job passes. Use idiom B from RESEARCH:

```yaml
- name: Check for forbidden mental-health terms (CMIA AB 2089 — D-16)
  run: |
    if grep -rniE '\b(depression|anxiety|therapy|mental health treatment)\b' src \
         --include='*.ts' --include='*.tsx' \
         --exclude='*.test.ts' --exclude='*.test.tsx'; then
      echo "::error::Forbidden term found in user-facing string (SC#5 denylist)."
      echo "Allowed: 'mood' (Mood tab name). Disallowed: depression, anxiety, therapy, mental health treatment."
      exit 1
    fi
```

Reasoning for the inversion (encode in a comment in the workflow):
- `grep -rniE pattern src ...` returns exit 0 when ANY file matches, exit 1 when NO file matches.
- We want CI to FAIL when matches exist → `if grep …; then exit 1; fi` translates match→exit1.
- The plain `! grep …` form works too but the `if/then` form lets us emit a GitHub Actions `::error::` annotation that surfaces in the PR Files-changed view.
