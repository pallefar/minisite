<!-- Sentry data-sentry-mask + sentry-mask className spec (RESEARCH STACK §Sentry). -->

Per [Sentry React docs](https://docs.sentry.io/platforms/javascript/guides/react/session-replay/privacy/):
- `data-sentry-mask` HTML attribute → element + descendants masked.
- `sentry-mask` CSS className → same effect.
- `data-sentry-unmask` allows an opt-out for non-PHI inside a masked subtree (rare; not handled in this lint to keep regex simple).

**JSX prop binding shapes the regex must catch:**
- `<input value={patient.name} />` — `value` prop, expression `patient.name`.
- `<span>{dose.value} mg</span>` — expression text node `dose.value`.
- `<input value={profiles.email} />` — `profiles.email` (note plural — projects use both).
- `<DoseInput dose={dose} />` — prop binding `dose` (the prop NAME is `dose`, the BINDING is `dose`; lint checks the EXPRESSION text not the prop name to avoid false positives on `<DoseInput dose=...` where the receiving component itself is the masked surface).

**Lint design decision:** lint matches on EXPRESSION TEXT (right side of `={...}`), not on prop name. This matches RESEARCH design where the JSON lists "dose.value, patient.name" etc as full property access paths. So a fixture `<span>{patient.email}</span>` triggers because `patient.email` is the rendered expression; `<UserCard patient={patient} />` does NOT trigger because `patient` is the bare identifier (the inside of UserCard is what gets audited separately).

**Ancestor shielding:** if a JSX element 0-3 lines above has `data-sentry-mask` or `className=".*sentry-mask.*"`, descendants are considered shielded. To keep this lint simple, the implementation uses a 3-line lookback (NOT full AST parent traversal). Documented as a known limitation; AST upgrade per RESEARCH Pitfall 11 cadence.

**`scripts/audit-sentry-mask.ts`:**

Mirror `lint-stripe-phi.ts` shape (Pattern S8). Header cites Phase 25 D-15, HIPAA-16, RESEARCH Pitfall 11 (regex caveats + AST upgrade trigger).

Implementation outline:
1. Parse CLI args (--json, --strict, --root).
2. Load `sentry-mask-required-props.json` → phiExpressions list. Escape each for regex (esp. `.`).
3. Recursively walk `src/` for `.tsx` only (PHI rendering is JSX; `.ts` files don't render). Exclude `__tests__`, `*.test.*`, `*.spec.*`.
4. For each `.tsx` file:
   - Skip if file content doesn't reference any PHI expression substring (fast path).
   - Build a regex matching `{<expr>}` or `={<expr>}` for each PHI expression: `/\{\s*<escaped-expr>\s*\}/g`. Multi-expression per file matched in sequence with line tracking.
   - For each match: determine line number. Check the same line + 3 lines above for:
     - `data-sentry-mask` attribute on a JSX element.
     - `className` attribute whose value contains the substring `sentry-mask`.
     - `// sentry-mask-lint:allow reason='...'` comment (allowlist).
   - Ancestor shielding: scan 0-3 lines above (in the same JSX subtree-ish — heuristic) for a JSX element opening with `data-sentry-mask` (no closing tag check; this is the documented heuristic limit). If found, consider the match shielded.
   - On unshielded + non-allowlisted match → finding.
5. Emit `::error file=PATH,line=N::PHI expression <EXPR> rendered without data-sentry-mask. Wrap in element with data-sentry-mask, add className=\"sentry-mask\", or annotate with // sentry-mask-lint:allow reason='<why>'.`
6. Exit 0 / 1.

CRITICAL — false positive note in header: this lint INTENTIONALLY accepts false negatives (under-blocks) over false positives (over-blocks) to keep developer ergonomics manageable. The complementary defenses are: (a) Sentry runtime PII scrubber, (b) Sentry organization-level masking defaults, (c) PR review. The lint is a "shift-left" reminder, NOT the final boundary.

**`scripts/__tests__/audit-sentry-mask.test.ts`** (vitest):

Subprocess-invocation style mirroring Plan 25-05 tests. Fixture files written to tmpdir. Cases:
1. **Clean:** `<input value={patient.name} data-sentry-mask />` → exit 0.
2. **Violation:** `<input value={patient.name} />` → exit 1 + stderr `patient.name`.
3. **className shield:** `<input value={patient.name} className="form-input sentry-mask" />` → exit 0.
4. **Allowlist with reason:** preceding line `// sentry-mask-lint:allow reason='display name shown to self only'` → exit 0.
5. **Allowlist without reason:** `// sentry-mask-lint:allow` (no reason=) → exit 1.
6. **Ancestor shielding:** `<div data-sentry-mask>\n  <span>{patient.email}</span>\n</div>` → exit 0 (lookback finds masked ancestor).
7. **Non-PHI prop unaffected:** `<input value={settings.theme} />` → exit 0.
8. **Multi-violation per file:** 3 violations → exit 1 + 3 separate `::error` lines.
9. **Test file excluded:** fixture under `__tests__/` with violation → exit 0.
10. **JSON mode emits valid JSON:** parse stdout.
