<objective>
Wire up the operational cycle of the compliance program:
1. **Nightly BAA expiry check** — alerts founder + writes audit_logs as BAAs approach expiry (60/30/14/7/1-day buckets); flips status on expiry.
2. **Weekly subprocessor diff** — detects vendor subprocessor list changes; alerts founder + appends snapshot.
3. **Admin Compliance page** — lets superadmin manually flip status='signed' as each vendor BAA closes during the 4-8 week parallel signing window.

This is the OPERATIONS layer that turns the Plan 25-01 storage + Plan 25-03 email path into a working compliance program. Without it, vendor BAAs are just rows in a table that nobody updates.

Per [[feedback_status_machine_transition_owner]]: this plan owns the writers for `status='signed'` (superadmin UI) and `status='expired'` (cron) — both transitions documented in the Plan 25-01 migration header.

Purpose: Closes HIPAA-12 cron + UI halves + HIPAA-13 expiry-alert half.

Output: 2 migrations + 2 Edge Fns + 1 modules.ts edit + 5 React files + tests + SUMMARY.
</objective>

-- vendor_baa_chain_update — superadmin writes status='signed' transition.
create or replace function public.vendor_baa_chain_update(
  p_vendor_name text,
  p_signed_at timestamptz,
  p_expiry_at timestamptz
) returns void
language plpgsql
security definer
set search_path = public, extensions, pg_catalog
as $$
declare
  v_actor uuid := auth.uid();
  v_role  text;
begin
  if v_actor is null then raise exception 'not_authenticated' using errcode = '28000'; end if;
  select admin_role::text into v_role from public.profiles where id = v_actor;
  if v_role is null or v_role != 'superadmin' then
    raise exception 'forbidden' using errcode = '42501';
  end if;
  if p_signed_at is null then raise exception 'signed_at required' using errcode = '22023'; end if;
  if p_expiry_at is null then raise exception 'expiry_at required' using errcode = '22023'; end if;

  update public.vendor_baa_chain
     set status = 'signed', baa_signed_at = p_signed_at, baa_expiry_at = p_expiry_at, updated_at = now()
   where vendor_name = p_vendor_name;
  if not found then raise exception 'vendor_not_found' using errcode = 'P0002'; end if;

  -- Phase 24 audit_logs insert — verified column shape:
  -- (id, created_at, actor_user_id, target_user_id, action_name, table_name,
  --  row_pk, before_data, after_data, org_id, source) with source check ('rpc','trigger').
  insert into public.audit_logs (
    actor_user_id, target_user_id, action_name,

end;

**`baa-expiry-check/index.ts`:** Mirror `affiliate-payout/index.ts` cron-only pattern. Module header per Pattern S3/S4/S5.

Flow:
1. Bearer compare (constant-time) against `SUPABASE_SERVICE_ROLE_KEY` — 401 on mismatch.
2. Lazy admin client (`getAdmin()`).
3. SELECT vendor_baa_chain WHERE status='signed' AND baa_expiry_at IS NOT NULL ORDER BY baa_expiry_at ASC.
4. For each row: compute `days_until = floor((baa_expiry_at - now()) / 1 day)`.
5. Bucket check: if days_until in {60, 30, 14, 7, 1} → invoke a sibling SECDEF RPC (add to migration 20260520000002 or a companion migration) `public.log_vendor_baa_event(p_vendor_name text, p_action_name text, p_payload jsonb)` which inserts into audit_logs with `action_name=p_action_name, table_name='vendor_baa_chain', after_data=p_payload, source='rpc'`. For bucket alerts, pass `action_name='vendor_baa_expiry_warning'`, `payload={vendor_name, days_until, bucket}`. Direct `admin.from('audit_logs').insert(...)` is NOT viable — Phase 24 revoked INSERT on audit_logs from service_role. Use idempotency key `vendor_baa_expiry_warning_{vendor}_{bucket}_{YYYY-MM-DD}` checked via a SELECT on audit_logs (`where action_name = 'vendor_baa_expiry_warning' and after_data->>'vendor_name' = $1 and after_data->>'bucket' = $2 and date(created_at) = current_date`) before invoking the RPC.
6. If `days_until <= 0` → call `vendor_baa_chain_set_expired(vendor_name)` RPC (which flips status + writes its own audit row).
7. Try to email founder via Plan 25-03 `email-router.sendEmail({ template:'baa_expiry_alert', phi:false, to:FOUNDER_EMAIL, vars:{vendor, days_until} })`. PHI=false because vendor names + dates are NOT PHI. If health check returns no_api_key (Resend missing) → log warn + continue (don't crash on missing config).
8. Return 200 `{ checked: rows.length, alerts: alertsEmitted, expired: expiredCount }`.

Idempotency note: use the unique combination of (vendor_name, bucket, date) — never write 2 rows for the same vendor in the same bucket on the same day. The cleanest path is a UNIQUE constraint on a small `vendor_baa_alerts` table OR a check `where not exists (...)` before insert. For v1.3 simplicity use the `where not exists` SELECT-then-INSERT pattern (cron is single-instance per schedule slot; race-window is theoretical).
