<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anon browser session → authenticated profile | Local anon data is merged into a server profile; the merge must bind to the authenticated session only |
| client → PostHog | Feature-flag value read client-side; controls only UI step ordering (no security decision) |
| AuthCallbackView → merge-anon-session Edge Fn | Post-OAuth merge crosses to the server with the new session token |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-59-08 | Tampering/Elevation (merge hijack) | mergeAnonSession | mitigate | Helper accepts ONLY the just-authenticated session access token (no externally-supplied user id); the merge-anon-session Edge Fn (already shipped, advisory-locked) scopes the merge to the JWT subject — a malicious anon session cannot overwrite another user's data |
| T-59-09 | Denial of Service (redirect block) | AuthCallbackView merge | mitigate | Merge is best-effort: wrapped so any failure/timeout is caught and the dashboard/onboarding redirect always proceeds (verified by a reject-still-redirects test) |
| T-59-10 | Tampering | PostHog variant value | accept | getFeatureFlag controls only onboarding step ordering, not access/authz; a tampered flag value at worst shows the wrong (still-valid) onboarding sequence; undefined falls through to the safe control |
| T-59-SC | Tampering | npm installs | mitigate | This plan installs NO packages (posthog-js, supabase-js already installed); supply-chain gate owned by Plan 02 |
</threat_model>
