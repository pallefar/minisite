# Phase 31 — UI Design Contract

> Visual and interaction contract for Phase 31: White-Label (Path-Based) + Org Roles + Clinic Onboarding Builder.
> Generated by gsd-ui-researcher. Five distinct UI surfaces; design tokens derived from the project's canonical design system at `src/index.css`.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Tailwind v4 `@theme` tokens + hand-authored primitives |
| Preset | not applicable |
| Component library | Custom (`src/components/ui/` — Button, Card, Modal, Sheet, Input, Toast, Badge, Pill, ProgressRing, Skeleton) |
| Icon library | lucide-react ^0.460.0 |
| Font (LeanShot default) | Geist (sans), Fraunces (display), Geist Mono (mono) |
| Font (clinic-brand options) | Inter, Fraunces, JetBrains Mono, Lora, IBM Plex Sans — curated dropdown only |

**Shadow DOM note:** No shadow DOM. Brand tokens are CSS custom properties on `<html>`; Tailwind utility classes reference them via `var(--brand-*)` fallback chain.

---

## Spacing Scale

Same 4 px base as the rest of the project (no phase-specific exceptions).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4 px | Icon gaps, chip internal padding |
| sm | 8 px | Compact element spacing, gap between form label and input |
| md | 16 px | Default element spacing, card padding |
| lg | 24 px | Section padding, tab-content top padding |
| xl | 32 px | Layout gaps between major form sections |
| 2xl | 48 px | Page-level vertical breathing room |
| 3xl | 64 px | Not used in P31 surfaces |

Exceptions:
- Drag-handle touch target: 40 × 44 px (40 px wide to fit beside row content, 44 px tall to meet WCAG 2.5.8 minimum; same as `BlockTreeItem` in Phase 15).
- Color picker swatches in BrandingTab: 32 × 32 px — below the general minimum but acceptable because they are NOT the primary interaction target (the oklch text input beside them is the primary target, with full keyboard access).

## Typography

P31 inherits the project type scale verbatim. No new sizes are introduced. The 4-size constraint is met by using exactly these four for P31 UI:

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 13 px | 400 | 1.5 | Tab content body text, matrix table cells, form helper text, step list labels |
| Label | 14 px | 600 | 1.4 | Form field labels, section headings inside tab panels, nav tab labels, permission matrix column headers |
| Subhead | 16 px | 600 | 1.4 | Tab panel H1 (e.g. "Branding", "Onboarding"), card section titles, RoleEditorModal heading |
| Display | 20 px | 600 | 1.2 | Not used in P31 — reserved for higher-level page titles in other surfaces |

**Monospace exception:** oklch input fields render in `var(--font-mono)` at 13 px / weight 400 to make color strings scannable.

## Color

Derived from `src/index.css` `@theme` tokens. No new color values are introduced in P31.

| Role | Token | Value (light) | Usage |
|------|-------|--------------|-------|
| Dominant (60%) | `--color-bg` | `#f2ede0` (cream-100) | Page background, tab panel background |
| Secondary (30%) | `--color-surface` | `#fefcf7` (cream-card) | Cards, settings nav sidebar, form fields, modal backgrounds |
| Accent (10%) | `--color-primary` | `#1b4842` (teal-700) | See reserved list below |
| Destructive | `--color-danger` | `#cf5454` (clay) | Destructive actions only: "Remove member", "Delete flow version" |

**Accent (`--color-primary`) reserved for:**
- Active tab indicator line (2 px bottom border on nav tab)
- Active nav item background fill (`--color-primary-soft` at 10 % opacity tint)
- Focus rings on all interactive elements (`focus-visible` outline)
- Primary CTA buttons (Save branding, Save onboarding flow, Confirm role change)
- Live WCAG meter — passing indicator checkmark icon
- Drag-over highlight ring on `SortableTreePanel` drop target

**NOT accent:** role pills (use semantic badge tones), WCAG fail state (uses `--color-danger`), read-only section backgrounds.

**Brand overlay tokens** (applied to `<html>` at `/clinic/{slug}/*` routes, fallback to defaults when null):

| CSS property | Fallback | Controls |
|---|---|---|
| `--brand-primary` | `var(--color-primary)` | Primary buttons, links, active states |
| `--brand-accent` | `var(--color-sage)` | Accent badges, highlights |
| `--brand-bg` | `var(--color-bg)` | Page background |
| `--brand-text` | `var(--color-text)` | Body text |
| `--brand-logo` | LeanShot wordmark SVG | Sidebar logo slot |
| `--brand-heading-font` | `var(--font-display)` | Heading elements |
| `--brand-body-font` | `var(--font-sans)` | Body elements |
| `--brand-radius` | `var(--radius)` | Card + button radius |

**Brand application scope:** Sidebar chrome, topbar, primary buttons, card borders, links consume `--brand-*` tokens. Tab navigation active indicators, focus rings, and all accessibility indicators stay at LeanShot defaults (`--color-primary`) to preserve cross-org consistency and WCAG compliance regardless of clinic's color choices.

## Surface 1: BrandingTab

**Location:** New tab inside `ClinicSettingsPage` tab strip at `/clinic/{slug}/settings/branding`. Tab added to the `NAV` array with `id: 'branding'`, icon `Palette` from lucide-react, `visibleWhen: (perms) => perms['branding.edit'] === true`.

**Layout:** Two-column at `md:` breakpoint and above. Form fields on the left (min-width 320 px). Live preview panel on the right (min-width 280 px, max-width 420 px). On mobile, preview panel collapses below the form. Entire panel is a `<Card variant="flat">` with 24 px padding.

### Form section

**Logo upload zone**
- 160 × 80 px dashed-border dropzone (`border-dashed border-2 border-[var(--color-border)]`, `rounded-xl`).
- Label: "Clinic logo". Helper: "PNG, JPG, or SVG · max 500 KB · max 1024 × 1024 px".
- States: idle (dashed border + upload icon + "Drag or click to upload"), drag-over (`border-[var(--color-primary)]` + teal bg tint), uploading (Skeleton shimmer over the zone + `aria-busy="true"`), uploaded (img preview + "Remove" ghost button top-right).
- On click: triggers hidden `<input type="file" accept=".png,.jpg,.jpeg,.svg">`.
- Calls `upload_org_branding_asset(org_id, 'logo')` on file selection.

**Favicon upload zone**
- 64 × 64 px square dashed-border dropzone, same visual language.
- Label: "Favicon". Helper: "ICO or PNG · max 500 KB · max 64 × 64 px recommended".
- Same state machine as logo zone.
- Calls `upload_org_branding_asset(org_id, 'favicon')`.

**Color token section** — heading "Brand colors" (14 px / semibold)
Four color rows, each containing:
- Left: 32 × 32 px rounded swatch (background = current oklch value, border: `1px solid var(--color-border)`).
- Middle: `<Input type="text">` (monospace, 13 px) showing the `oklch(…)` string. Placeholder: `oklch(0.65 0.18 240)`. `aria-label="{field} color"`.
- Right: WCAG indicator chip showing the relevant contrast ratio (e.g., "4.8 : 1") in a small `<Badge>` with `tone="success"` when passing, `tone="danger"` when failing. Only the text/bg and primary/bg pairs are shown (the other two fields are informational only).
- Validation: swatch color updates live as user types a valid oklch string (client-side parse). Invalid strings keep the last valid color in the swatch. A red `aria-live="polite"` inline error appears below the input on blur if the string is not valid oklch.

| Field label | CSS prop stored | WCAG check |
|---|---|---|
| Background | `--brand-bg` → `bg_color` | — |
| Text | `--brand-text` → `text_color` | text/bg ratio ≥ 4.5 |
| Primary | `--brand-primary` → `primary_color` | primary/bg ratio ≥ 3.0 |
| Accent | `--brand-accent` → `accent_color` | — |

**WCAG meter** — displayed as a two-row inline summary beneath the color section:
- Row 1: "Text on background: {ratio} : 1" with pass (Check icon, `text-[var(--color-success)]`) or fail (AlertCircle icon, `text-[var(--color-danger)]`) indicator.
- Row 2: "Primary on background: {ratio} : 1" with same treatment.
- Meter updates live as color fields change (client-side computation of WCAG relative luminance from oklch).

**Font section** — heading "Typography" (14 px / semibold)
Two `<Select>` dropdowns:
- "Heading font" — options: Inter, Fraunces, JetBrains Mono, Lora, IBM Plex Sans. Each option renders the font name in its own typeface via inline style.
- "Body font" — same option set.

**Radius section** — heading "Corner radius" (14 px / semibold)
Segmented control (implemented as a `<PillGroup>` with 4 options):
- sm / md / lg / xl — maps to `--radius-sm` / `--radius` / `--radius-lg` / `--radius-xl` from the token sheet.
- Selected pill: `variant="active"` (primary-soft bg + primary text). Unselected: ghost.

**Support email** — `<Input type="email">` with label "Support email". Placeholder: `support@yourclinic.com`. Validates on blur (must be a valid email format). Helper: "Shown to patients in the clinic onboarding flow."

**"View as default" toggle** — ghost `<Button size="sm">` with `Eye` icon. Label: "Preview defaults". On click: temporarily applies LeanShot default tokens to the preview pane (does not mutate form values). Button label flips to "Preview clinic theme" and icon to `EyeOff` while defaults are shown. Toggling back restores the pending form values.

**Save button** — `<Button variant="primary">` "Save branding". Disabled when: any pending color is invalid oklch OR WCAG check is failing for either required pair. `aria-busy="true"` + Spinner while saving. On success: toast "Branding saved — patients will see this on their next visit." On server-side WCAG rejection (`CONTRAST_TEXT_BG_FAIL` or `CONTRAST_PRIMARY_BG_FAIL`): inline error beneath the meter row with the exact pair that failed, never a generic toast.

### Live preview pane

- Contained in a `<Card variant="elevated">` with 16 px padding, sticky at `md:` while the form scrolls.
- Section heading: "Patient view preview" (13 px / secondary color). `role="img"` `aria-label="Live preview of clinic branding"`.
- Renders a miniature clinic surface (not interactive, `aria-hidden="true"` on interactive-looking elements inside):
  - A 32 px tall fake sidebar strip: shows `--brand-logo` image or LeanShot wordmark fallback, background = `--brand-bg` with a subtle `--brand-primary` accent left-border.
  - A fake card: background = `--color-surface`, `border-radius = --brand-radius`, a mock heading in `--brand-heading-font` at 14 px weight 600, body text in `--brand-body-font` at 12 px weight 400, and a mock primary CTA button using `--brand-primary`.
  - A text-on-bg sample: "Patient data stays private" rendered in `--brand-text` over `--brand-bg`.
- All four `--brand-*` color props + two font props + radius prop update live as the form changes (React controlled state, no save required).

## Surface 2: OnboardingTab

**Location:** New tab inside `ClinicSettingsPage` tab strip at `/clinic/{slug}/settings/onboarding`. Icon: `ListOrdered` from lucide-react. `visibleWhen: (perms) => perms['onboarding.edit'] === true` (owner gate; clinician sees a read-only "current flow" view — see below).

**Owner view layout:** Two-column at `md:` breakpoint. Left column: step builder (48 % width). Right column: patient preview (48 % width). On mobile: single column, builder first, preview after a "Preview for patients" toggle button.

### Left: Sortable step list

Heading: "Steps" (14 px / semibold). Sub-label: "Drag to reorder. Mandatory steps cannot be removed." (13 px / secondary).

Implemented via `<SortableTreePanel<OnboardingStepNode>>` (new generic primitive extracted from `BlockTreePanel`).

**Step card row** (each `OnboardingStepNode` renders as a row in the list):
- 44 px tall row (`<li>` with `flex items-center gap-2`).
- Drag handle: 40 × 44 px touch target, `aria-label="Drag to reorder {step name}"`, `GripVertical` icon (16 px), `cursor-grab`. Handle is hidden (opacity 0, pointer-events none) for `consent` (locked position, no reorder).
- Step type icon: 20 × 20 px lucide icon — mapping below.
- Step name: 13 px / weight 500, flex-1 text-left.
- "Mandatory" badge: `<Badge tone="neutral">` "Required" — shown for `medication` and `consent` step types. Positioned right of the step name.
- Skip toggle: `<Pill aria-pressed={!step.skip}>` "Skippable" — rendered only for step types where `skip` is allowed (welcome, intro_card, goals, body_stats, doctor_invite, tour). Toggling calls `setSteps` locally (not saved until user hits Save).
- Edit button: `<IconButton aria-label="Edit {step name}">` with `Pencil` icon (16 px). Only shown for `welcome` and `intro_card` (the two editable types). Clicking opens the step editor modal.
- Remove button: `<IconButton aria-label="Remove {step name}">` with `Trash2` icon (16 px), `text-[var(--color-danger)]`. Hidden for mandatory steps (`medication`, `consent`). Also hidden if the step type is the only instance of a unique-locked type.

**Step type icon mapping:**
| StepType | lucide icon |
|---|---|
| welcome | `Sparkles` |
| intro_card | `Image` |
| medication | `Pill` |
| goals | `Target` |
| body_stats | `Scale` |
| consent | `FileCheck` |
| doctor_invite | `Stethoscope` |
| tour | `Map` |

**Empty state** (when all removable steps are removed — extremely rare, but handle gracefully):
- EmptyState illustration + "Add a step to get started" heading + "Click Add step to choose from the step library." body.

**"Add step" button** — `<Button variant="secondary" size="sm" leadingIcon={<Plus/>}>` "Add step". Positioned below the step list. Clicking opens an inline palette (not a modal — appears as a sub-panel with `animate-fade-in`) listing the available step types that are not already present AND not mandatory-locked. Each type shown as a card with its icon + name + one-line description. Clicking a type appends it to the list.

**Step editor modal** — `role="dialog"` `aria-modal="true"` `aria-labelledby="step-editor-title"`. Opens for `welcome` and `intro_card` only.
- Heading: "Edit {step name}" (16 px / semibold), `id="step-editor-title"`.
- For `welcome`: `<Input>` "Step title" (max 60 chars, character counter shown at 40+) + `<Textarea>` "Body text" (max 200 chars, character counter shown at 150+).
- For `intro_card`: same inputs + `intro_card`-only image uploader (64 × 64 px zone, same pattern as logo upload zone but smaller; stores to `org-onboarding-assets` bucket).
- For all other step types: "No customization available — LeanShot controls this step's contents." (13 px / secondary) with a `Info` icon. Modal should not open for these types (edit button is hidden); this fallback guards against direct calls.
- Buttons: "Cancel" (ghost) + "Apply" (primary). "Apply" writes to local state only; does not call a server RPC until the outer Save is clicked.

**Save + version history footer area:**
- "Save flow" `<Button variant="primary">` — calls `save_org_onboarding_flow(org_id, steps)`. `aria-busy` while saving. On success: toast "Saved version {N} — new patients will see this flow." (version number from server response). Disabled while the step list has validation errors (e.g., mandatory steps missing, unknown step types).
- Version history `<Select>` — label "Version history". Populated from last 5 `org_onboarding_flows` rows (version number + formatted date). Selecting a version shows a ghost-text "Preview only" note beside the select + a "Restore this version" `<Button variant="secondary" size="sm">` button. Restoring calls `activate_onboarding_flow_version(org_id, flow_id)`. Confirmation: inline toast "This will replace the current active flow." + confirm button (not a blocking modal — per D-16 fast admin actions).

### Right: Patient preview

- Sticky at `md:`, `position: sticky; top: 24px`.
- `<Card variant="elevated">` with 16 px padding.
- Heading: "Patient view" (13 px / secondary). `role="img"` `aria-label="Preview of patient onboarding flow"`.
- Renders a miniature step-by-step preview using `<ProgressIndicator>` from `src/components/onboarding/ProgressIndicator.tsx` (reused as-is) + read-only step frames.
- Navigation: previous / next `<IconButton>` arrows (`ChevronLeft` / `ChevronRight`) to page through preview steps. Current step indicator: "Step {N} of {total}" (13 px / secondary).
- Step frame content: shows the step title/body text from `custom` fields if set, or the LeanShot default label for non-editable steps. No input fields in preview (read-only mockup).

### Clinician read-only view (when `surfaceCheck('onboarding.edit')` is false)

- Single panel (no step builder), heading: "Current patient onboarding flow" (16 px / semibold).
- Read-only list of the active flow's steps using the same step card row layout but with drag handles and all edit/remove/skip controls hidden. `aria-readonly="true"` on the list container.
- Footer note: "Only workspace owners can edit the onboarding flow." (13 px / secondary, italic).

## Surface 4: First-paint brand application

**Not a visual surface — a visual contract for how brand tokens are applied across `/clinic/{slug}/*`.**

### Token application rules

Applied via `applyBrandTokens()` in `main.tsx` before React mounts (mirrors existing `applyThemeToDOM()` pattern):
- Sets all 8 `--brand-*` CSS custom properties directly on `document.documentElement` (the `<html>` element).
- Source priority: `localStorage['leanshot_brand_{slug}']` first (warm paint, synchronous); then async RPC `resolve_clinic_branding(slug)` refreshes and updates both the DOM and localStorage.

### Which elements consume brand tokens

| Surface element | Token consumed | Note |
|---|---|---|
| Sidebar background | `--brand-bg` | Darkened 8% via `color-mix` |
| Sidebar logo slot | `--brand-logo` | Falls back to LeanShot wordmark SVG when null |
| Sidebar logo `alt` attribute | From RPC `clinic_name + " logo"` | Required for a11y; must be in the RPC response per D-07 note |
| Primary buttons | `--brand-primary` | `background-color` |
| Primary button text | Computed: white when `--brand-primary` luminance < 0.5, else dark | Server pre-validates WCAG; client mirrors the decision |
| Topbar/nav active indicator | `--brand-primary` | 2 px bottom border on active tab |
| Links | `--brand-primary` | `color` |
| Card border-radius | `--brand-radius` | All cards within `/clinic/*` routes |
| Body font | `--brand-body-font` | `font-family` on `body` within the route |
| Heading font | `--brand-heading-font` | Applied via `.font-display` on heading elements |

### What NEVER changes with brand tokens

| Element | Stays as | Reason |
|---|---|---|
| Focus rings | `var(--color-primary)` (LeanShot teal) | Predictable a11y indicator across all orgs |
| Tab navigation active indicator on `<ClinicSettingsPage>` nav | `var(--color-primary)` | Internal settings surface stays LeanShot-branded |
| Error / warning colors | `var(--color-danger)` / `var(--color-warning)` | Semantic clarity must not vary by brand |
| Toast backgrounds | `var(--color-surface)` | System feedback stays neutral |
| `aria-live` regions | All system defaults | AT users need consistent ARIA announcements |

### Graceful fallback chain

When `org_branding` row has `NULL` for any token:
- `--brand-primary`: falls back to `var(--color-primary)` = LeanShot teal.
- `--brand-bg`: falls back to `var(--color-bg)` = cream.
- `--brand-logo`: sidebar renders the LeanShot wordmark (`<img>` with `alt="LeanShot"`).
- `--brand-heading-font` / `--brand-body-font`: fall back to `var(--font-display)` / `var(--font-sans)`.
- `--brand-radius`: falls back to `var(--radius)` = 0.875 rem.

### Favicon injection

`main.tsx` also injects the favicon: if `org_branding.favicon_url` is present, a `<link rel="icon">` is set (or updated) on `document.head`. Falls back to the LeanShot favicon.

## Surface 5: Theme reset / "View as default" affordance

**Location:** Within BrandingTab only. See Surface 1 form section for the toggle button spec.

**Interaction contract:**
- "Preview defaults" button applies LeanShot default token values to the live preview pane (Surface 1 right column) without touching form field values or calling any server RPC.
- The preview pane renders a visual `<Badge tone="neutral">` "Showing LeanShot defaults" label in its top-right corner while in default-preview mode.
- Switching back (button label: "Preview clinic theme") re-applies the in-progress form values to the preview.
- This toggle is purely presentational; it has no effect on `--brand-*` CSS properties on the actual `<html>` element (those are only mutated on initial page load from localStorage/RPC, not by the BrandingTab form until Save is clicked).
