**handler.ts** — mirror grandfathered-policy-notice DI shape:

Export `interface RequestRefundDeps { fetchImpl, supabaseServiceClient, stripe, resendApiKey, supabaseUrl, signingKey, physicalAddress?, slackWebhookUrl?, moneyBackDays?: number }`. Default `moneyBackDays: 14`.

Export `handle(req: Request, deps: RequestRefundDeps): Promise<Response>`:

1. **GET /healthz** → 200 `{ ok: true, fn: 'request-refund' }`.

2. **POST /** (refund request):
   - Read JWT from `Authorization: Bearer <jwt>` (mirror `jwtFromReq` from stripe-checkout). If missing → 401.
   - Resolve user via `supabaseServiceClient.auth.getUser(jwt)`. If error/null → 401.
   - Parse body: `{ reason: string (optional, max 2000 chars) }`. Sanitize (no HTML tags; strip control chars).
   - SELECT `subscriptions WHERE user_id = user.id AND status IN ('trialing','active','past_due') ORDER BY created_at DESC LIMIT 1`. If none → 404 `{ error: 'no_subscription' }`.
   - **Idempotency**: SELECT `refunds WHERE subscription_id = sub.id AND status IN ('pending','succeeded') LIMIT 1`. If exists → 409 `{ error: 'refund_already_processed', stripe_refund_id: existing.stripe_refund_id }`.
   - **Eligibility check** (CONTEXT.md D-08): compute `inTrial = sub.trial_end_at && new Date(sub.trial_end_at) > new Date()`; compute `inMoneyBack = (now - sub.created_at) < moneyBackDays * 86400_000`. If neither → 403 `{ error: 'window_expired', eligibility_reason: 'past_14d_money_back', support_email: 'billing-support@leanshot.app' }`.
   - Compute `eligibility_window = inTrial ? 'trial' : 'money_back_14d'`.
   - **Resolve payment_intent**: `stripe.invoices.list({ subscription: sub.stripe_subscription_id, status: 'paid', limit: 1 })` → `paymentIntent = invoice.payment_intent`. If none → 500 `{ error: 'no_paid_invoice' }` (defensive — trial users may have no paid invoice; if `inTrial && no_paid_invoice` → return 200 `{ ok: true, status: 'trial_no_charge_to_refund' }` and proceed directly to cancel-subscription branch).
   - **Execute refund**: `stripe.refunds.create({ payment_intent, reason: 'requested_by_customer' })`. Wrap in try/catch; on Stripe error → 500 `{ error: 'refund_failed' }` (do NOT echo Stripe error details — Pitfall 8 from stripe-checkout).
   - **INSERT refunds row** (use surrogate uuid PK): `{ subscription_id, stripe_refund_id, stripe_payment_intent_id, amount_cents: refund.amount, currency: refund.currency, status: refund.status, reason, eligibility_window, created_at: now(), updated_at: now() }`. Use `.insert()` (not upsert — surrogate id makes every call a new row).
   - **Cancel subscription**: `stripe.subscriptions.cancel(sub.stripe_subscription_id)`. The `customer.subscription.updated` webhook (Plan 65-04) will mark the row cancelled; we don't touch `subscriptions` table directly here. If Stripe cancel fails, log + alert Slack but DON'T fail the response — refund already issued; cancel can be retried by operator.
   - **Fire Resend confirmation**: per-recipient send to `user.email` with template `refund-confirmation.html/.txt`. Subject: "Your refund has been processed". Body interpolates `{{amount_dollars}}` (refund.amount / 100), `{{eligibility_window}}` ("within your trial" or "within 14-day money-back window"), `{{physical_address}}`, `{{unsubscribe_url}}` (mint via newsletter-token).
   - Return 200 `{ ok: true, refund_id: refund.id, amount_cents: refund.amount, status: refund.status }`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user JWT → request-refund | JWT-authed POST (NOT service-role) |
| request-refund → Stripe | refunds.create + subscriptions.cancel + invoices.list |
| request-refund → DB | service_role admin writes refunds row + reads subscriptions |
| request-refund → Resend | per-recipient confirmation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-65-06-01 | Spoofing | JWT bypass | mitigate | Bearer JWT resolved via supabase.auth.getUser; 401 on null user |
| T-65-06-02 | Tampering | refund of other user's subscription | mitigate | SELECT subscriptions WHERE user_id = auth.user.id; no user-controlled subscription_id |
| T-65-06-03 | Repudiation | refund grief | mitigate | reason captured + eligibility_window recorded + stripe_refund_id UNIQUE + created_at audit row |
| T-65-06-04 | Information Disclosure | Stripe error echo | mitigate | Stripe errors → generic `{ error: 'refund_failed' }`; never JSON.stringify(stripeErr) |
| T-65-06-05 | Denial of Service | refund abuse | mitigate | Idempotency check returns 409 on existing refund; eligibility window caps repeat-charges per subscription |
| T-65-06-06 | Elevation of Privilege | refund + cancel atomicity | accept | If subscriptions.cancel fails after refunds.create succeeded, operator gets Slack alert; user already got their money back |
</threat_model>
