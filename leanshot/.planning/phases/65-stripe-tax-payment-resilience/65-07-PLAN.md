<interfaces>
PostHog feature-flag evaluation API: `POST https://us.posthog.com/decide?v=3` with `{ api_key, distinct_id }` returns `{ featureFlags: { trial_ending_copy_variant: 'a' | 'b' | false } }`. Caller should default to 'a' if PostHog returns false/undefined.

Stripe Promotion Codes SDK v19: `stripe.promotionCodes.create({ coupon: <coupon_id>, max_redemptions: 1, customer: <stripe_customer_id>, code: <unique-suffix> })` returns `Stripe.PromotionCode { id, code, ... }`. Coupon IDs (10%off / 25%off / 50%off) MUST exist in Stripe Dashboard before deploy — that's an operator action documented in close-out (Plan 65-10).

Win-back discount table (per CONTEXT.md specifics + Phase 65 inline):
- T+30d: 10% off (coupon env var STRIPE_COUPON_WINBACK_10)
- T+60d: 25% off (coupon env var STRIPE_COUPON_WINBACK_25)
- T+90d: 50% off (coupon env var STRIPE_COUPON_WINBACK_50)

From 65-01: `lifecycle_emails_sent (user_id, stage)` composite PK with stage IN ('trial_ending_t3d','trial_ending_t1d','winback_t30d','winback_t60d','winback_t90d') + copy_variant column + promo_code column.

Window queries:
- Trial T-3d: `status='trialing' AND trial_end_at BETWEEN now() + interval '3 days' AND now() + interval '4 days'`
- Trial T-1d: `status='trialing' AND trial_end_at BETWEEN now() + interval '1 day' AND now() + interval '2 days'`
- Winback T+30d: `status='canceled' AND cancelled_at BETWEEN now() - interval '37 days' AND now() - interval '30 days'`
- Winback T+60d: `status='canceled' AND cancelled_at BETWEEN now() - interval '67 days' AND now() - interval '60 days'`
- Winback T+90d: `status='canceled' AND cancelled_at BETWEEN now() - interval '97 days' AND now() - interval '90 days'`

The 7-day wide window guarantees catch-up if cron skips a run; the composite-PK lifecycle_emails_sent prevents double-send anyway.
