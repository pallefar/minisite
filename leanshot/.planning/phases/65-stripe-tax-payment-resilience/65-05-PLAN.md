**handler.ts** — mirror `grandfathered-policy-notice/handler.ts` shape.

Export `interface DunningOrchestratorDeps { fetchImpl, supabaseServiceClient, resendApiKey, serviceRoleKey, supabaseUrl, signingKey, physicalAddress?, slackWebhookUrl?, sendIntervals?: { first_failed_hours, second_failed_hours, final_warning_hours } }`. Default `sendIntervals = { first_failed_hours: 24, second_failed_hours: 72, final_warning_hours: 168 }` (T+1d / T+3d / T+7d expressed as "hours since previous-stage send, or hours since dunning_state transition for first_failed").

Export `handle(req: Request, deps: DunningOrchestratorDeps): Promise<Response>` with:

1. **GET /healthz** → 200 `{ ok: true, fn: 'stripe-dunning-orchestrator' }`. Exempt from bearer auth.

2. **POST /** → require `Authorization: Bearer <serviceRoleKey>` (constant-time compare). 401 on mismatch.

3. **Placeholder guard** (per [[feedback_placeholder_string_runtime_guard_pattern]]): if `physicalAddress` missing OR matches `/\[.*\]|TODO|REPLACE_ME|PLACEHOLDER/i` → call `sendSlackGuardrailAlert(slackWebhookUrl, 'P1: stripe-dunning-orchestrator PHYSICAL_ADDRESS unset')` and return 503 `{ error: 'physical_address_missing_or_placeholder' }`. Same guard pattern as grandfathered-policy-notice WR-02.

4. **Query for actionable rows**: SELECT from `subscriptions` JOIN `auth.users` (per [[reference_profiles_email_vs_auth_users_email]] — profiles has no email column) where:
   - `dunning_state IN ('first_failed','second_failed','final_warning')`
   - AND `(last_dunning_email_at IS NULL OR last_dunning_email_at < now() - interval_for(dunning_state))`
   - AND `auth.users.email_marketing_consent IS TRUE` (or null — null = consent given at signup; explicit FALSE means opted out)
   - AND NOT EXISTS (SELECT 1 FROM email_lifecycle_exclusion WHERE user_id = subscriptions.user_id) per Phase 64-04 exclusion table
   - LIMIT 200 per invocation (cron runs every 15min so 200/invocation × 96 = 19,200/day cap — adjust if needed)

5. **Per-row send loop**:
   - Determine `stage = subscriptions.dunning_state` (string)
   - Determine `templatePath = './dunning-{stage_short}.html'` where `stage_short = 'first'|'second'|'final'`
   - INSERT into `dunning_emails_sent (subscription_id, stage, sent_at, resend_message_id=null)` with `.upsert(..., { onConflict: 'subscription_id,stage', ignoreDuplicates: true })` — if it returns the conflict-skipped indicator (rowCount 0), this email was ALREADY sent for this (sub, stage) pair → skip (counts as `skipped`). The composite PK in 65-01 makes this race-safe.
   - If insert succeeded (new row), call Resend API: `POST https://api.resend.com/emails` with bearer `resendApiKey`, JSON body `{ from: 'LeanShot Billing <billing@leanshot.app>', to: [user.email], subject: <stage subject>, html: <rendered>, text: <rendered>, headers: { 'List-Unsubscribe': '<https://leanshot.app/unsubscribe?t=...>', 'List-Unsubscribe-Post': 'List-Unsubscribe=One-Click' } }`. Use `mintUnsubscribeToken` for the URL.
   - On success: UPDATE `dunning_emails_sent SET resend_message_id = response.id` + UPDATE `subscriptions SET last_dunning_email_at = now()` keyed by subscription_id.
   - On Resend 4xx/5xx: log error, push `{ subscription_id, error }` to errors[], DELETE the just-inserted `dunning_emails_sent` row (so retry on next cron invocation can re-attempt) — atomicity is best-effort; acceptable per CAN-SPAM (we'd rather miss-send than double-send, but the composite PK gives us strict prevention of double-send anyway; the rollback just allows retry).

6. **Return** 200 `{ sent: N, skipped: M, errors: [...] }`. Always 200 unless guard/auth failed.

Stage subjects + copy variants:
- `first_failed`: "We couldn't process your last payment" — CTA "Update payment method" → `https://app.leanshot.app/settings/billing`
- `second_failed`: "Action needed: second payment attempt failed" — escalated urgency, same CTA URL
- `final_warning`: "Your subscription will be cancelled in 24 hours" — final escalation, same CTA URL

All template bodies: Inter/system-font, brand-color CTA button, plain-text fallback, CAN-SPAM footer with `physicalAddress` interpolated, RFC 8058 List-Unsubscribe header/body link.
