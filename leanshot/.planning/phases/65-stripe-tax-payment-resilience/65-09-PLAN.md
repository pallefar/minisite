<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → request-refund | JWT-authed POST (Plan 65-06 handler) |
| browser → Supabase REST | RLS-gated SELECT on subscriptions / tax_nexus_state_revenue / tax_nexus_thresholds |
| browser → nexus-monitor | Refresh button calls service-role-bearer Fn? No — that's a privileged Fn. Refresh button should call a separate staff-scoped wrapper OR the browser invokes via supabase.functions.invoke which signs with user JWT (NOT service role). Need staff RLS guard in nexus-monitor for the user-triggered refresh path, OR add a dedicated `nexus-refresh-staff` light Fn that staff can call without service-role. ACCEPTABLE shortcut: define an SECDEF RPC `public.staff_refresh_nexus_revenue()` that gates on `public.is_staff()` and runs `refresh materialized view ...` — Plan 65-08 already proposes a similar SECDEF; reuse or add a staff wrapper here. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-65-09-01 | Spoofing | refund as another user | mitigate | request-refund Fn (Plan 65-06) resolves user via JWT; no user-controlled subscription_id |
| T-65-09-02 | Tampering | proximity tier client-spoofing | accept | Client computes tier from server-supplied revenue + threshold; admin user is privileged anyway; only display affected |
| T-65-09-03 | Information Disclosure | non-staff /admin/tax access | mitigate | minRole='staff' enforced by AdminShell; RLS on tax_nexus_thresholds + matview restricts SELECT to authenticated staff |
| T-65-09-04 | Elevation of Privilege | matview refresh from browser | mitigate | Define `public.staff_refresh_nexus_revenue()` SECDEF gated on `public.is_staff()`; browser calls via PostgREST RPC; service-role NOT exposed to browser |
</threat_model>
