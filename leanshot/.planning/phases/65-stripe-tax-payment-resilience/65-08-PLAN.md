- `tax_nexus_thresholds`: (state text PK, state_name text, threshold_amount_cents bigint, threshold_period_days int, transaction_count_threshold int nullable, notes text).

This plan ADDS a new table `nexus_alert_log` for de-duplicating Slack alerts within the same day:
- `nexus_alert_log (state text, alert_tier text CHECK in ('monitoring','at_risk','nexus_established'), alerted_at timestamptz)` — composite PK (state, alert_tier, date_trunc('day', alerted_at)).

Wait — that composite PK can't include a function. Use INSERT-then-check approach: `INSERT INTO nexus_alert_log (state, alert_tier, alerted_at) VALUES (...) ON CONFLICT (state, alert_tier) WHERE alerted_at > now() - interval '1 day' DO NOTHING` — but partial unique indexes are required. Simpler approach: add a unique index `(state, alert_tier, day_bucket)` where `day_bucket date generated always as ((alerted_at at time zone 'UTC')::date) stored`. Then composite PK `(state, alert_tier, day_bucket)` works.

Or simplest: just query `SELECT 1 FROM nexus_alert_log WHERE state=? AND alert_tier=? AND alerted_at > now() - interval '23 hours' LIMIT 1` BEFORE firing the Slack alert. Insert after fire. Two-statement gating; not strictly atomic but cron runs at 24h cadence so race window is negligible.

**This plan creates the nexus_alert_log table as part of the handler's pre-flight check** — but ADDING a migration here would put it out-of-band from Plan 65-01. Better: add this table to Plan 65-01's task 2 as a 9th migration `20290104000009_nexus_alert_log.sql`.

`handle(req, deps)`:

2. POST / requires service-role bearer (constant-time).
3. **Slack webhook guard**: if `slackWebhookUrl` empty/missing → 503 `{ error: 'slack_webhook_unset' }`. No point running without alert channel; surfaces as Slack-channel-misconfigured at cron-fire time.

Or, simpler: use `supabaseServiceClient.rpc('refresh_nexus_revenue')`. **Add this RPC to the 65-01 schema as part of the matview migration** — back-amend 20290104000008 to include `create or replace function public.refresh_nexus_revenue() returns void language sql security definer as $$ refresh materialized view concurrently public.tax_nexus_state_revenue; $$;` plus `revoke all on function public.refresh_nexus_revenue() from public; grant execute on function public.refresh_nexus_revenue() to service_role;`. 5. **Query proximity**:
   ```sql
   SELECT t.state, t.state_name, t.threshold_amount_cents, COALESCE(r.revenue_cents, 0) AS revenue_cents,
          (COALESCE(r.revenue_cents, 0)::numeric / t.threshold_amount_cents * 100) AS proximity_percent
   FROM public.tax_nexus_thresholds t
   LEFT JOIN public.tax_nexus_state_revenue r ON r.state = t.state
   ```
   Use PostgREST chain or `.rpc('get_nexus_proximity')` (define this SECDEF RPC alongside refresh_nexus_revenue for cleaner test stubs).
6. **Classify each state**:
   - `proximity < monitoring` (60) → tier = `safe`, no alert
   - `monitoring ≤ proximity < at_risk` (60-79) → tier = `monitoring` (Slack info)
   - `at_risk ≤ proximity < nexus_established` (80-99) → tier = `at_risk` (Slack warning)
   - `proximity ≥ nexus_established` (100+) → tier = `nexus_established` (Slack critical, "Registration required")
7. **De-dup gate per state+tier**: for each non-safe state, `SELECT 1 FROM nexus_alert_log WHERE state=? AND alert_tier=? AND alerted_at > now() - interval '23 hours' LIMIT 1`. If exists → skip (counts as `alerts_skipped`).
8. **Fire Slack alert** via `sendSlackGuardrailAlert(slackWebhookUrl, payload)`:
   - For tier=`monitoring`: blue info — "Nexus monitoring: {state_name} ({state}) at {proximity}% of {threshold_amount_dollars} threshold."
   - For tier=`at_risk`: yellow warning — "Nexus AT RISK: {state_name} ({state}) at {proximity}% of threshold ({revenue_dollars} / {threshold_amount_dollars}). Review at /admin/tax."
   - For tier=`nexus_established`: red critical — "🚨 NEXUS ESTABLISHED: {state_name} ({state}) at {proximity}% — REGISTRATION REQUIRED. Stripe Tax registration in {state_name} must be completed within 30 days. Review at /admin/tax."
9. **Record alert log row**: INSERT into `nexus_alert_log` (state, alert_tier, revenue_cents, threshold_amount_cents, proximity_percent). Insert regardless of Slack success (so the 23h de-dup gate works even if Slack is down — operator will see Slack failures separately).
10. Return 200 `{ refreshed: true, states_checked: N, alerts_fired: K, alerts_skipped: M, errors: [...] }`.
