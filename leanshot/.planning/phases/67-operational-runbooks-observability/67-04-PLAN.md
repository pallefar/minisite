### `scripts/posthog/funnel-alerts.json`
3 funnel definitions:
- **activation**: signup_completed → first_dose_logged → 7-day-retention
- **payment**: paywall_shown → checkout_started → subscription_created
- **signup**: landing_viewed → onboarding_started → signup_completed

Each with PostHog `subscription` (alert) config: WoW drop > 20% threshold → Slack webhook destination = `SLACK_GUARDRAIL_WEBHOOK_URL`.

JSON format follows PostHog's Insight + Subscription API schema.

### `scripts/posthog/seed-funnel-alerts.sh`
Bash script that:
1. Reads `funnel-alerts.json`
2. For each funnel, `curl -X POST` to PostHog API `/api/projects/{POSTHOG_PROJECT_ID}/insights/` to create the funnel
3. For each created insight, POST to `/api/projects/{POSTHOG_PROJECT_ID}/subscriptions/` to attach the alert
4. Uses `POSTHOG_PERSONAL_API_KEY` from env
5. Idempotent: skip if a funnel with same name exists (GET first)

Operator runs once: `POSTHOG_PERSONAL_API_KEY=... POSTHOG_PROJECT_ID=140479 bash scripts/posthog/seed-funnel-alerts.sh`.

Add operator instructions inline as a `# Usage:` header block.

Handler/index split per Phase 64-03 pattern. Service-role bearer auth.

Logic:
1. Poll 3 upstream status APIs:
   - Sentry: `https://status.sentry.io/api/v2/status.json`
   - Supabase: `https://status.supabase.com/api/v2/status.json`
   - Vercel: `https://www.vercel-status.com/api/v2/status.json`
2. For each, parse `status.indicator` field (`none | minor | major | critical`)
3. If any indicator != `none`, POST to Better Stack incidents API:
   - `POST https://uptime.betterstack.com/api/v2/incidents` with auth bearer `BETTER_STACK_API_KEY` + body `{ summary, description: 'Upstream incident: ${vendor}', requester_email, ... }`
4. Dedupe via Better Stack's own merge OR check before POST (last-known-incident table — optional, defer to per-vendor `bs_upstream_incidents` if needed)

Cron: every 5min via pg_cron (deferred to Phase 67 close-out migration OR Phase 70).

Test (Deno): mock each upstream + Better Stack POST; assert correct behavior across 4 indicator levels × 3 vendors.

If `BETTER_STACK_API_KEY` env var missing → handler returns 503 + Slack alert (placeholder-guard pattern from Phase 60-13).
