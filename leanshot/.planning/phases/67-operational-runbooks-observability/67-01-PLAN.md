Structure:

# Incident Response Runbook

## Severity Levels
P1 — Site fully down / user data exposed / payment processing broken
P2 — Single critical feature broken (sign-in, dose-log, AI coach)
P3 — Degraded UX (slow loads, AI rate-limited)
P4 — Non-customer-facing (admin tool broken)

## Detection Signals (mapped to escalation)
| Signal | Source | Severity | Auto-page? |
|--------|--------|----------|------------|
| Sentry error rate spike | Sentry | P1 if >100/min | Yes (Better Stack) |
| Supabase 5xx | Supabase status | P1 | Yes |
| Stripe webhook failures | Stripe Dashboard | P1 | Manual escalation |
| ... etc |

## Log Locations
- Sentry: https://sentry.io/organizations/<org>/issues/?project=leanshot
- Supabase: Studio → Functions → Logs
- Vercel: vercel.com/<team>/leanshot/deployments → Logs
- Better Stack: bettstack.com/team/<team>/monitoring
- PostHog: app.posthog.com → Activity → Events

## Rollback Procedure
### Edge Fn rollback
1. `npx supabase functions deploy <fn> --import-map <prev-tag>` — DEFERRED until tag-based deploy
2. Interim: `git revert <commit>` + redeploy
### Vercel rollback
1. Vercel Dashboard → Deployments → Promote previous to Production
### Database rollback
1. PITR restore: see backup-restore.md
2. NEVER `supabase db reset --linked` on prod — wipes all data

## Status Page Updates
Better Stack → Incidents → Create New → ... (template)

## HIPAA Breach Notification Trigger
If incident involves PHI (protected health information):
- Start 60-day clock per HIPAA Breach Notification Rule §164.404
- Notify affected individuals within 60 days
- Notify HHS Office for Civil Rights within 60 days (or annually if <500 affected)
- See [[reference_compliance_hipaa_breach_notification]] if exists

## Post-Incident
- Blameless postmortem within 5 business days
- Add detection signal to this runbook if novel
- Update PostHog funnel alerts if related
