# Phase 15 — UI Design Contract
## Page Builder + Landing Pages

> Visual and interaction contract for two distinct surfaces: (1) the admin editor chrome and (2) the rendered landing-page output. Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (custom Tailwind v4 `@theme` — no shadcn, no components.json) |
| Preset | not applicable |
| Component library | Bespoke DS v2 primitives in `src/components/ui/*.tsx` |
| Icon library | lucide-react `^0.460.0` |
| Font — body | Geist 400/600, loaded via `<link>` tag (not `@import`) |
| Font — mono | Geist Mono 400, for numeric/code contexts |
| Font — display | Fraunces, for editorial headings and Hero blocks |
| Token source | `src/index.css` `@theme {}` block — the single source of truth |

**No shadcn gate needed.** This project uses a fully custom DS delivered via Tailwind v4 CSS custom properties. The existing token set is exhaustive and covers every visual contract below.

**No third-party registries.** Registry safety gate: not applicable.

## Surfaces in Scope

This phase ships two structurally separate UI surfaces. The contract below addresses both.

| Surface | Route | Bundle | Audience |
|---------|-------|--------|----------|
| Admin editor | `/admin/pages/*` | Lazy `admin-bundle` (never downloaded by visitors) | `is_staff` users only |
| Rendered landing page | `/{slug}` (root) | Zero React bundle — static HTML from `page-render` Edge Function | Public visitors |

## Spacing Scale

Source: `src/index.css` `--spacing: 0.25rem` (4px base). Tailwind v4 generates multiples automatically. The declared values in use for this phase:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon gaps, drag handle padding, inline chip spacing |
| sm | 8px | Block tree item inner padding, property field label gap |
| md | 16px | Panel section padding, property group spacing |
| lg | 24px | Rail padding (left/right), editor toolbar height |
| xl | 32px | Preview pane min gutter, card section padding |
| 2xl | 48px | General spacing ceiling; also compact-density block padding (see Block Vertical Rhythm below) |
| 3xl | 64px | Default-density block padding (see Block Vertical Rhythm below) |

**Exceptions:**

- Drag handle touch target: minimum 44px height (a11y — WCAG 2.5.5 touch target size).
- Viewport toggle buttons (mobile/tablet/desktop preview, D-06): minimum 44x44px touch area even though the visible icon is 20px.
- Block tree item drag grip: 40px wide × full row height so the grab zone is generous without a hover affordance delay.

## Block Vertical Rhythm (rendered landing pages only)

The D-06 `spacingDensity` block style prop controls **vertical section padding on rendered landing-page blocks only**. These are not general UI spacing tokens and are never used in the editor chrome or for any UI-element spacing.

| `spacingDensity` value | Block top/bottom padding | Notes |
|------------------------|--------------------------|-------|
| `compact` | 48px | Standard-set value (2xl) |
| `default` | 64px | Standard-set value (3xl) |
| `spacious` | 96px | Extended value — rendered-page block sections only |

The 96px spacious value is intentionally outside the standard {4, 8, 16, 24, 32, 48, 64} UI token set because it applies exclusively to block-level vertical rhythm on published pages, not to any interface element or component. It is rendered via inline CSS (`padding-top: 96px; padding-bottom: 96px`) on block wrappers in the `page-render` Edge Function output, and is never referenced by editor chrome components.

## Typography

Source: `src/index.css` type scale. All sizes are from the existing `--text-*` tokens. **Do not introduce new sizes or weights.**

### Admin Editor Chrome

The editor chrome uses smaller type than the published output — this is an information-dense tool surface.

| Role | Size | Weight | Line Height | Token | Usage |
|------|------|--------|-------------|-------|-------|
| Body / property label | 13px | 400 (regular) | 1.5 | `--text-sm` | Property field labels, help text, block tree labels |
| UI label / button | 13px | 600 (semibold) | 1.5 | `--text-sm` | Button text, section headers in panels, version history timestamps |
| Property heading | 16px | 600 (semibold) | 1.55 | `--text-base` | Property group headings ("Style", "Content", "SEO") |
| Page/panel title | 18px | 600 (semibold) | 1.5 | `--text-lg` | Editor topbar page title, modal titles |

**Sizes in editor: 3 (13px, 16px, 18px). Weights: 2 — regular (400) and semibold (600). No medium (500) usage.**

### Published Landing-Page Output

The renderer produces semantic HTML. These are the typographic contracts for each block type, drawn from the design-system v2 token set. **Maximum 4 distinct sizes.**

| Role | Size | Weight | Line Height | Token | Usage |
|------|------|--------|-------------|-------|-------|
| Label / badge | 13px | 600 | 1.5 | `--text-sm` | Block eyebrow labels ("Features", "Pricing", "FAQ"); feature grid card body; footer copyright |
| Body copy | 16px | 400 | 1.55 | `--text-base` | Paragraph text in FAQ answers, Image+text body, testimonial quotes, hero subheadline, CTA descriptor, lead form labels |
| Subheading / card title | 22px | 600 | 1.35 | `--text-xl` | Feature grid card titles, testimonial author name, CTA headline, Image+text heading |
| Section heading | 32px | 600 | 1.15 | `--text-3xl` | FAQ section header, Feature grid section header, Testimonial section header; also the **mobile Hero heading** (see responsive variant below) |

**Responsive variant — Hero heading:** The Hero block primary headline uses the `section-heading` (32px) token as its base. On screens ≥768px it scales to 56px (`--text-5xl`) via a responsive modifier. This is a viewport-width breakpoint override on the **same semantic role** — not a fifth font size. Declared as: `text-3xl md:text-5xl` (Fraunces, weight 400 italic). No other block type uses the 56px size.

**Weights in rendered output: 2 — regular (400) and semibold (600).**

**Font assignment:**
- Fraunces: Hero block headings only (editorial moment). No other block type uses Fraunces.
- Geist: all other text on all surfaces.
- Geist Mono: not used on public-facing landing pages. Reserved for admin UI numeric displays (revision IDs, timestamps) and Pricing block dollar amounts.

## Color

Source: `src/index.css` semantic tokens. Published-page colors MUST use these CSS custom properties — never raw hex in component code.

### 60/30/10 Split

| Role | Token | Value (light) | Usage |
|------|-------|---------------|-------|
| Dominant (60%) — page background | `--color-bg` | `#f2ede0` (cream-100) | Landing-page page background; editor workspace background |
| Secondary (30%) — surfaces | `--color-surface` | `#fefcf7` (cream-card) | Cards inside landing blocks; editor panel backgrounds (left/right rails); block tree item backgrounds |
| Accent (10%) — primary | `--color-primary` | `#1b4842` (teal-700) | See reserved list below |
| Destructive | `--color-danger` | `#cf5454` (clay) | Delete page, remove block, discard revision — confirmation dialogs only |

**Accent (`--color-primary`) is reserved for:**

1. Primary CTA buttons on published landing pages ("Subscribe", "Get started", "Book a call")
2. Checkout-button block (Pricing block CTA) — wires to Stripe Checkout
3. "Publish page" button in the admin editor toolbar
4. "Restore" button in the Version History panel (irreversible action — teal, not destructive, because restore is recoverable via re-save)
5. Active/selected state ring on block tree items when selected (2px ring + `--color-primary-soft` halo)
6. Focus-visible ring on all interactive elements — this inherits the project-wide `Button.tsx` pattern (`ring-2 ring-[var(--color-primary)]`) and is not a new Phase 15 decision
7. Link text color on published pages

**Accent is NOT used for:** drag handles, property group headers, version history rows, help text, secondary navigation, tab labels, toggle labels, or any decorative purpose.

### Block Background Tone Palette (D-05, `backgroundTone` style prop)

Each block's `backgroundTone` maps to a specific token, not an arbitrary color. This is the complete allowed set:

| `backgroundTone` value | Token | Usage context |
|------------------------|-------|---------------|
| `default` | `--color-bg` (#f2ede0) | Most blocks — cream page background |
| `subtle` | `--color-surface-elevated` (#f6f2e8) | Alternating section blocks for visual rhythm |
| `brand` | `--color-hero-bg` (#1b4842) with `--color-text-on-hero` text | CTA blocks, pricing highlight sections |
| `dark` | `--color-teal-950` (#0b1413) with `--color-text-on-hero` text | Footer block only |

No other background values are permitted. The property editor exposes exactly these 4 options as a segmented selector — no color picker.

### Rendered Page vs Editor Visual Split

The editor chrome uses `--color-surface-elevated` (#f6f2e8) as the background for rails (left block tree, right property panel) to distinguish them from the preview pane center, which shows the real cream-100 page background inside the iframe.

## Interaction Contracts

### Admin Editor

**Drag and drop (D-04, dnd-kit):**

- Library: `@dnd-kit/core@6.3.1` + `@dnd-kit/sortable@10.0.0`.
- Sensors: `PointerSensor` (threshold: 5px distance) + `KeyboardSensor` (arrow keys).
- Keyboard-accessible reorder: Arrow Up / Arrow Down moves the focused item one position. Space or Enter activates drag mode. Escape cancels. This satisfies the a11y reorder requirement without a separate "move" control.
- Drag overlay: the dragged item renders as a `DragOverlay` clone with `opacity-50` on the original slot and `shadow-lg` + full opacity on the clone.
- Nesting: blocks can be nested (e.g. Testimonial inside a CTA wrapper). The drop indicator shows a 2px `--color-primary` line between items or a teal halo when hovering a valid parent.
- Collision detection: `closestCenter` strategy. `collisionPriority` on nested droppables for disambiguation.
- Motion: drag transitions use `prefers-reduced-motion` via the `useReducedMotion()` hook. When reduced-motion is active, DragOverlay renders without the position-transition animation.

**Property panel selection:**

- Clicking a block in the BlockTreePanel sets it as the selected block and populates the PropertyPanel.
- Clicking directly in the PreviewPane iframe is NOT interactive (the preview is read-only). The iframe has `pointer-events: none` overlay with a tooltip on hover: "Edit properties in the right panel."
- If no block is selected: PropertyPanel shows a placeholder: "Select a block to edit its properties."

**Save:**

- Auto-save on property field blur (debounced 1000ms). Visual feedback: a "Saving..." status in the editor topbar replaces the "Saved" status for the duration of the API call.
- Explicit "Save draft" button also present (secondary variant).
- Every save creates a new `landing_page_revisions` row (D-07 append-only).

**Publish (D-09):**

- "Publish page" button (primary variant, teal) in the editor topbar.
- On click: button enters `loading` state (`aria-busy="true"`, spinner icon).
- Action: updates `landing_pages.published_revision_id` → triggers Vercel on-demand revalidation via `x-prerender-revalidate` header.
- On success: button returns to normal, topbar status updates to "Published", StatusBadge changes to sage `published`.
- Duration target: ≤3 seconds for the full publish + revalidation cycle.

**Version history (D-07):**

- "History" button (ghost variant) in editor topbar opens the `VersionHistoryPanel` (Sheet, right side).
- Each revision row: timestamp (Geist Mono 13px), author email (13px), "Restore" button (secondary variant).
- "Restore" triggers a `Confirm` dialog (existing DS primitive): title "Restore this version?", body "The page will revert to this revision. Any unpublished changes will be preserved in history.", confirm button (primary), cancel button (secondary).

**Template picker (D-14):**

- Shown only on new page creation. Modal with 5 template cards.
- Each template card: `Card` (clickable variant), 160px thumbnail image, template name (16px semibold), 1-line description (13px regular).
- Templates: Long-form sales, Lead-magnet opt-in, Comparison, FAQ, Testimonial-driven.
- Selecting a template and confirming copies its block tree into the new page — one-time scaffold.
- Cancel: starts with an empty block tree.

**Asset library (D-13):**

- Triggered from any image property field in the PropertyPanel ("Choose image" button, secondary variant).
- Modal: 3-column image grid. Each image card shows the image, filename (truncated), and a checkmark when selected.
- Upload: drag-and-drop or file input button. Accepts image/jpeg, image/png, image/webp, image/gif. Max 10 MB.
- Alt-text: required. When selecting an image, an alt-text input appears below the grid. If the image already has a saved alt-text (from a prior use), it pre-fills. Submit is disabled until alt-text is non-empty.
- `aria-label="Asset library"` on the modal, `role="dialog"` + `aria-modal="true"`.

**Viewport preview toggle (D-06):**

- 3 icon buttons above the PreviewPane: Phone (375px), Tablet (768px), Monitor (100%).
- Each button: `Button` (ghost variant, icon-only). Active: `Button` (tonal variant). `aria-pressed` on the active button.
- On change: PreviewPane `<iframe>` `width` transitions to the new value (instant, no animation — avoids confusion with actual device behavior).
- Default: Monitor (full width).

### Published Landing Pages

**CTA / Checkout button:**

- Single-click → shows spinner overlay on the button (`aria-busy="true"`) → redirects to Stripe Checkout within 1-2 seconds.
- If the Edge Function call fails: inline error below the button (see Copywriting Contract error copy).

**FAQ accordion:**

- Trigger: `<button>` with `aria-expanded` and `aria-controls`. Content panel: `role="region"` with matching `id`.
- Open/close transition: max-height CSS transition, 200ms `ease-out-quart`. Skipped if `prefers-reduced-motion`.

**Lead form:**

- Validation: HTML5 `required` + `type="email"` for the email field. Browser-native validation fires on submit.
- Submit: button enters loading state. On success: form replaced with success message (in-place, no navigation). On error: inline error below submit button.
- Honeypot field: `display: none` visually, but present in the DOM. Submissions with honeypot filled are silently dropped by `lead-capture`.

**Scroll behavior:**

- Anchor links in footer nav scroll smoothly to sections. Respects `prefers-reduced-motion`: when reduced motion is active, `scroll-behavior: auto`.

## Accessibility Contract

Published pages must achieve Lighthouse a11y ≥ 95 (SC #3). Editor chrome: WCAG 2.1 AA.

| Requirement | Implementation |
|-------------|---------------|
| Alt text on every image | Required field in asset library picker. `lead-capture` and `page-render` enforce non-empty alt on `<img>` elements. |
| Keyboard-accessible drag-drop | dnd-kit `KeyboardSensor`. Arrow Up/Down to reorder. Space/Enter to grab. Escape to cancel. `aria-grabbed` on active drag item. |
| Icon-only button labels | `aria-label` required on all `ViewportToggle` buttons, social icons in footer block, drag handle grip. Typed in component props (project convention from `Button.tsx`). |
| Modal/sheet semantics | `role="dialog"` + `aria-modal="true"` + `aria-label` on every Modal and Sheet (VersionHistoryPanel, TemplatePicker, AssetLibraryPicker). Project convention from `Modal.tsx`. |
| FAQ accordion | `aria-expanded` on trigger, `aria-controls` → panel `id`, `role="region"` on panel. |
| Iframe titles | Required `title` attribute on all `<iframe>` elements (Calendly, YouTube, Tally, preview pane). |
| Live regions | Save/publish status in editor topbar: `role="status"` + `aria-live="polite"`. Lead form success/error messages: `role="alert"`. |
| Reduced motion | `useReducedMotion()` hook checked before any animated transition in the editor. CSS `@media (prefers-reduced-motion: reduce)` covers the renderer's FAQ accordion and scroll-behavior. |
| Focus management | On modal open: focus trapped inside. On modal close: focus returns to trigger element. On block selection: focus does NOT jump to PropertyPanel — user navigates intentionally. |
| Color contrast | All text/background token pairs already validated in DS v2 (cream-card surface + teal-700 primary + clay danger all meet WCAG AA at 4.5:1 for body, 3:1 for large text). No new color pairs introduced in Phase 15. |
| Touch targets | Drag handle rows: 44px minimum height. Viewport toggle buttons: 44x44px. All form inputs: 44px height (existing `Input` DS convention). |
