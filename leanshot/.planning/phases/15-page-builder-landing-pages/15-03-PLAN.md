  type:      BlockType
  parent_id: string | null           // null = root level

  'clinic', 'admin', 'share', 'api', 'auth', 'assets',
  'sitemap.xml', 'robots.txt'

isReservedSlug(slug: string): boolean — returns true if the lowercased,

escapeHtml(value: unknown): string
  - Coerces value to string, then replaces & < > " ' with HTML entities
    (&amp; &lt; &gt; &quot; &#39;). Applied to EVERY user-authored content
    field before it is interpolated into an HTML string. This is the XSS
    boundary — render.ts NEVER interpolates a raw content field.

renderBlock(block: BlockNode): string
  - switch on block.type. This plan implements ONLY these three case names:
      case 'hero'   — see Hero content shape below
      case 'cta'    — see CTA content shape below
      case 'footer' — see Footer content shape below
    default: return '' (unknown/not-yet-implemented type renders nothing —
    later plans replace the default-fall-through by adding their case).
  - Each branch wraps output in a semantic element (<section> for hero/cta,
    <footer> for footer) and applies the style helpers below.

renderPage(page): string
  - Input shape (the row index.ts passes — NOT the raw DB row):
      {
        slug: string
        seo: { title?: string; description?: string; ogImage?: string;
               canonical?: string; schemaType?: string }   // jsonb column
        blocks: BlockNode[]   // from landing_page_revisions.blocks of the
                              // published revision, sorted by order
      }
  - Returns a COMPLETE HTML document string: <!doctype html> ... </html>.
  - <head> injection HOOK: emits <title>, <meta name="description">,
    <meta property="og:*">, <link rel="canonical"> from page.seo. Leave a
    clearly-commented `renderHead()` seam so 15-08 can extend it with
    JSON-LD + site_settings cascade. This plan does the minimal head.
  - <body>: blocks.filter(parent_id === null).sort(order).map(renderBlock).join('')
  - Fonts: <link rel="preload"> for Geist + Fraunces in <head> (UI-SPEC
    Performance Contract). No <script> tags — zero JS, CLS = 0.

renderNotFound(): string
  - Returns a complete minimal HTML document for the 404 case. Body copy
    EXACTLY: "Page not found. It may have been moved or removed."
    (15-UI-SPEC.md Copywriting Contract — published-pages 404 row).

Style helper contracts (used by every renderBlock branch, shared by 15-05/06/07):
  backgroundTone → token class/inline style:
    'default' → background var(--color-bg)               (#f2ede0)
    'subtle'  → background var(--color-surface-elevated)  (#f6f2e8)
    'brand'   → background var(--color-hero-bg) + text var(--color-text-on-hero)
    'dark'    → background var(--color-teal-950) + text var(--color-text-on-hero)
    (default when unset: 'default' — EXCEPT Hero defaults to 'brand', Footer to 'dark')
  spacingDensity → inline padding-top/padding-bottom:
    'compact' → 48px   'default' → 64px   'spacious' → 96px
    (the 96px value is intentionally outside the token set — inline style only,
     per 15-UI-SPEC.md Block Vertical Rhythm)
  alignment → text-align: left | center | right (default 'center' for hero/cta)
  hideOnMobile (D-06) → when true, the block wrapper gets a class that resolves
    to `display:none` below the md breakpoint (e.g. inline <style scoped> rule
    or a utility class emitted in the document <head>). Honored by render.ts —
    this is where D-06's hide-on-mobile actually takes effect on published pages.

Per-block content field shapes (block.content is Record<string, unknown> —
narrow with `as string ?? ''` defensively; NEVER trust the shape):
  hero.content:
    heading:      string   // Fraunces, 32px→56px responsive, escapeHtml'd
    subheading:   string   // Geist 16px, escapeHtml'd
    ctaLabel:     string   // primary CTA <a> text, escapeHtml'd
    ctaHref:      string   // primary CTA href — escapeHtml'd + only http(s)/#/relative
    secondaryCtaLabel?: string
    secondaryCtaHref?:  string
  cta.content:
    heading:      string   // Geist 22px semibold, escapeHtml'd
    body:         string   // Geist 16px, escapeHtml'd
    ctaLabel:     string
    ctaHref:      string
    secondaryCtaLabel?: string
    secondaryCtaHref?:  string
  footer.content:
    logoText:     string   // escapeHtml'd
    navLinks:     Array<{ label: string; href: string }>  // each field escapeHtml'd
    copyright:    string   // 13px, escapeHtml'd

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public internet → `page-render` Edge Function | Unauthenticated visitors (and search-engine crawlers) request `/{slug}`. No JWT, no cookie. Every request is untrusted input — the slug is attacker-controlled. |
| `landing_page_revisions.blocks` JSONB → rendered HTML | Block content fields are authored by `is_staff` users in the editor but flow UNVALIDATED through `page-render`. Treated as untrusted at the render boundary (defense in depth — a compromised staff account or a future non-staff author must not yield stored XSS). |
| Vercel CDN → visitor | `page-render` responses are cached publicly. Anything per-user or unpublished in a response would be cache-poisoned to all visitors. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-03-01 | Information Disclosure | `page-render/index.ts` query | mitigate | The query hard-filters `status='published'` (and requires a non-null `published_revision_id`) IN THE FUNCTION — never trusts RLS alone. An unpublished/draft page or a slug with no published revision returns `renderNotFound()` 404, never draft block content. Covered by index.test.ts behavior (3). |
| T-15-03-02 | Tampering (stored XSS) | `render.ts` content interpolation | mitigate | `escapeHtml()` entity-encodes `& < > " '` and is applied to EVERY user-authored content field before interpolation. `render.ts` never interpolates a raw content field and emits NO `<script>` tags. Hrefs are restricted to http(s)/`#`/relative. Covered by render.test.ts XSS-payload assertions + the `grep -c '<script'` gate. |
| T-15-03-03 | Information Disclosure | slug enumeration | accept | An attacker can probe arbitrary slugs; a 404 vs 200 reveals whether a *published* page exists at that slug. Published pages are public by definition (they have public URLs), so this leaks nothing sensitive — unpublished pages are indistinguishable from non-existent ones (both 404). No mitigation needed. |
| T-15-03-04 | Information Disclosure | error responses | mitigate | The handler's try/catch returns a generic 500 body and `console.error`s the detail — DB error strings are NEVER echoed to the client (mirrors `share`'s T-08-I2). |
| T-15-03-05 | Tampering (cache poisoning) | Cache-Control on responses | mitigate | Responses carry `Cache-Control: public, s-maxage=60, stale-while-revalidate=86400` + `Vary: Accept-Encoding` — pages are anonymous/public with no per-user data, so public caching is correct and carries nothing user-specific. cors.ts emits `Access-Control-Allow-Origin: *` with NO credentials (no cookies in scope). |
| T-15-03-06 | Spoofing | `verify_jwt` default | mitigate | `config.toml` `[functions.page-render] verify_jwt = false` is REQUIRED and explicitly set — without it the gateway 401s every anonymous visitor (Pitfall 7). The function is intentionally public; there is no auth to spoof. |
| T-15-03-07 | Elevation of Privilege | service-role client | accept | `index.ts` uses the service-role key (bypasses RLS) so it can read `landing_pages` server-side, but it ONLY ever runs the single published-filtered SELECT — no INSERT/UPDATE/DELETE, no other tables. The `status='published'` filter is the access-control gate. Same posture as `share/index.ts`. |
