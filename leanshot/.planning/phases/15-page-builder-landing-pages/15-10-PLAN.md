## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public visitor browser -> rendered /pricing HTML | Untrusted visitor reads a fully public, zero-auth static page |
| rendered-page Checkout `<a href>` -> SPA `?upgrade=` handler | A crafted URL with an arbitrary `upgrade` value can hit the SPA handler |
| SPA `?upgrade=` handler -> stripe-checkout Edge Function | The SPA sends a `plan` value into a JWT-authed, billing-mutating endpoint |
| staff editor (block content) -> rendered-page Checkout target | A staff-authored Pricing block carries a `checkoutPlan` that becomes a real money path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-10-01 | Tampering | `render.ts` pricing branch — Checkout `<a href>` target | mitigate | The href plan segment is derived ONLY from `checkoutPlan`, validated against the exact two-value enum (`plus_monthly` / `plus_yearly`) in the render branch; any other value renders an inert `<span>` with no href. A raw Stripe price ID can never reach the href — verified by `grep -c "STRIPE_PRICE\|price_0\|price_1"` returning 0 on render.ts. |
| T-15-10-02 | Elevation of Privilege | SPA `?upgrade=` handler -> stripe-checkout/session | mitigate | The handler only ever sends the `plan` enum; `stripe-checkout/session` itself re-validates `plan` against its server-side `validPlans` allowlist and resolves the actual price from Supabase Function secrets — the client cannot select a price. The handler also requires a verified, non-anonymous signed-in user before invoking (no anonymous checkout). |
| T-15-10-03 | Tampering | SPA `?upgrade=` handler — arbitrary param value | mitigate | The handler ignores any `upgrade` value not in the two-value enum (no fall-through to a default plan, no string passthrough). The param is stripped after a single fire so a refresh cannot replay it. |
| T-15-10-04 | Information Disclosure | rendered /pricing page is fully public | accept | `/pricing` is intentionally public marketing content — no auth, no PII, no tenant data. The page-render Edge Function only serves the published revision; no draft/unpublished data is reachable. Standard public-page exposure; nothing to mitigate. |
| T-15-10-05 | Spoofing / financial | e2e hitting live Stripe | mitigate | The e2e runs only under the explicit HAS_LIVE env gate, uses Stripe test-mode keys, and asserts the redirect ONLY — it stops at the Checkout page and never completes a charge (mirrors checkout-trial-flow.spec.ts). The manual checkpoint instruction repeats: test mode, stop at redirect. |
| T-15-10-06 | Tampering (XSS) | `ctaLabel` / `name` interpolated into the `<a>` element | mitigate | Both fields are passed through 15-03's existing HTML-escape helper before interpolation (same discipline 15-05's pricing branch already uses for price/features); the zero-`<script>` CI gate (`grep -c '<script'` == 0 on render.ts) is re-asserted in Task 2's verify. |
