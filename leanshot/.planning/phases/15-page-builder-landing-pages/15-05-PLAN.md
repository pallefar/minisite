<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff-authored block content → page-render HTML output | Block `content` fields (FAQ q/a, testimonial quote, feature-grid text, image-text body, pricing copy) are authored in the editor, stored as JSONB, then interpolated into HTML strings by the Deno `page-render` function and served to every public visitor. Untrusted-at-render-time string data crosses into markup here. |
| editor iframe → embedded page-render document | The `PreviewPane` iframe loads `page-render` output inside the staff editor origin. A malicious or malformed draft must not be able to script the parent editor frame or navigate it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-05-01 | Tampering | `page-render/render.ts` — 5 new renderBlock() branches | mitigate | Every interpolation of staff-authored text (FAQ q/a, pricing name/price/cadence/features/ctaLabel, testimonial quote/authorName/authorPhotoAlt, feature-grid title/body, image-text heading/body/imageAlt) routes through 15-03's existing `escapeHtml` helper. Task 1 includes an explicit XSS test asserting `<script>` content renders as escaped text. No `innerHTML`-equivalent raw injection; renderer only outputs known template strings. |
| T-15-05-02 | Tampering | `image-text` / `testimonial` block `<img>` rendering | mitigate | `imageUrl` / `authorPhotoUrl` are emitted only as `src` attribute values, HTML-escaped; never interpolated into a JS or CSS context. `imageAlt` is required and escaped; renderer omits the `<img>` entirely when alt is blank (a11y + avoids attribute-injection on an empty-alt path). |
| T-15-05-03 | Elevation of Privilege | `PreviewPane` iframe | mitigate | iframe is `sandbox`ed to a minimal allowlist (no `allow-popups`, no `allow-top-navigation`, no `allow-modals`), `pointer-events: none` (read-only), and `src` is hard-constructed as the same-origin `/{pageSlug}?preview=true` for the page currently being edited — the component never accepts an externally-supplied URL, so it can only ever load the staff user's own draft preview. |
| T-15-05-04 | Information Disclosure | Pricing block Checkout button | accept | The Checkout button in this plan is visual-only (no Stripe call, no price ID, no secrets). Stripe wiring and any secret handling is owned by 15-10. No sensitive data crosses this plan's surface. |
| T-15-05-05 | Spoofing | FAQ accordion / rendered interactive elements | accept | Rendered-page accordion is static HTML + CSS only (no JS in `page-render` output); there is no client-side auth or state on published pages in Phase 15 (D-17 — no analytics/tracking). No spoofable trust decision exists on this surface. |
</threat_model>
