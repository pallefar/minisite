## D-14 Independence Invariant (Templates)

The defining property of the template feature is that **a scaffolded page is fully independent of the source template** — editing the page never touches the source, and the source can be re-edited or replaced without affecting prior scaffolds. This is enforced by `scaffoldFromTemplate()`:

1. **Deep copy** via `structuredClone()` — content/style nested objects are byte-disjoint from `TEMPLATES[id].blocks`.
2. **Id regeneration** — every block gets a fresh `crypto.randomUUID().slice(0, 8)`; no scaffold id collides with the source.
3. **parent_id remap** — the topology is preserved against the NEW ids; nested parent references are rewritten through the id remap table.

Three tests in `templates.test.ts` prove each property:

- "returns a deep copy — mutating a nested content object does NOT mutate TEMPLATES"
- "regenerates every block id — no scaffold id collides with the source template"
- "preserves parent/child topology — parent_id points at the NEW id of the scaffolded parent"

Plus a fourth test asserts that two consecutive scaffolds from the same template have disjoint id sets — so opening two new-page tabs never produces colliding revision-internal block ids.

## D-07 Append-Only Invariant (Restore)

Restore in this plan is **literally publishing an older revision** — the user picks an older row, the panel POSTs `{ pageId, revisionId }` to `page-publish` (15-04), and `page-publish` atomically re-points `landing_pages.published_revision_id`. The `landing_page_revisions` row is **never UPDATEd or DELETEd** — the project's append-only invariant (Plan 15-01 enforces this at the DB trigger level) is honored.

The component does not import `supabase.from('landing_page_revisions')` at all. The restore code path is:

```
row click → setConfirmRevisionId(rev.id) → Modal opens
                                       ↓
                          user confirms in Modal
                                       ↓
              restoreFn({ pageId, revisionId }) → POST /page-publish
                                       ↓
                       landing_pages.published_revision_id := revisionId
```

The invariant-guard test calls every row's Restore button + confirms, then asserts every `restoreFn` call's `revisionId` is in the panel's own `revisions` prop. The page-publish Edge Function additionally verifies `revision.page_id === pageId` server-side (15-04 owns that check) — defence in depth against a forged client revisionId.

## Tier-Conditional buildImageUrl (RESEARCH Pitfall 3)

Supabase Storage's image-transform endpoint (`.../render/image/public/...`) is gated to the Pro plan; the free tier returns 400. The LeanShot project `ytnsipxxmzgaebkqmokp` is currently on the free tier, so the runtime default MUST be raw bucket URLs.

```typescript
buildImageUrl(path: string, opts?: {
  width?: number;
  height?: number;
  resize?: 'cover' | 'contain' | 'fill';
  transformsEnabled?: boolean;  // injectable seam; defaults to import.meta.env.VITE_SUPABASE_STORAGE_TRANSFORMS_ENABLED === 'true'
}): string
```

- `enabled && wantsSize` → `${url}/storage/v1/render/image/public/page-assets/${path}?width=...`
- otherwise → `${url}/storage/v1/object/public/page-assets/${path}` (raw bucket URL, NO query params)

Tests exercise both branches explicitly (passing `transformsEnabled: true` and `transformsEnabled: false`) without mutating `import.meta.env` at runtime.
