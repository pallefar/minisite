### `lead-capture` Edge Function HTTP contract

```
POST /functions/v1/lead-capture/submit
  verify_jwt = false  (public — no Authorization required)
  Content-Type: application/json

Request body:
  {
    "email": string,          // required
    "name"?: string,          // optional; only meaningful when block collectName=true
    "page_slug"?: string,     // optional; used to resolve page_id for the leads row
    "website"?: string        // HONEYPOT — must be absent or empty for a real user
  }

Responses:
  200 { "ok": true }                       // success OR honeypot-filled (identical body — bots learn nothing)
  400 { "error": "bad_json" }              // unparseable body
  400 { "error": "missing_email" }         // email absent/empty
  400 { "error": "invalid_email" }         // fails email regex
  429 { "error": "rate_limited" }          // >5 submissions from this IP in 15 min
  500 { "error": "internal_error" }        // unhandled

Honeypot semantics: if `website` is a non-empty string, the function returns
200 { ok: true } WITHOUT inserting a leads row, and WITHOUT sending a Resend
notification. (A `honeypot_flagged = true` row MAY be inserted for analytics —
see <action> for the chosen behavior.)
```

### Rendered `<form>` markup contract (what `renderBlock()` emits for `lead-form`)

The rendered form posts to the `lead-capture` function. The field `name` attributes MUST match the request-body keys exactly: `email`, `name`, `website` (honeypot). The honeypot input is visually hidden (`style="position:absolute;left:-9999px"` + `aria-hidden="true"` + `tabindex="-1"` + `autocomplete="off"`), NOT `display:none` removed from the DOM. The `<form>` carries a `data-lead-capture-url` attribute (or an inline endpoint) so the published page's small inline submit script knows where to POST.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public visitor → `lead-capture` Edge Function | Fully unauthenticated form POST (`verify_jwt=false`). Untrusted JSON body crosses here. Primary abuse surface of this plan. |
| `lead-capture` Edge Function → `public.leads` (Postgres) | Service-role client (bypasses RLS). Insert path for visitor-supplied data. |
| `lead-capture` Edge Function → Resend API | Server-to-server. Visitor-supplied `email`/`name` is reflected into a staff notification email. |
| rendered `<form>` markup → published page DOM | `content` strings from the block JSONB are interpolated into static HTML served to every visitor. |
