<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| staff editor → `site_settings` / `landing_pages` SEO fields → DB | Staff-authored SEO text (title, description, OG, canonical) is persisted, then later emitted into served HTML. Untrusted-at-render-time: a compromised staff account or a stored value crafted to break out of HTML context. |
| `page-render` Edge Function → public visitor HTML | SEO field values + auto-generated JSON-LD are interpolated into the `<head>` of HTML served to every visitor and crawler. Injection here = stored XSS on the marketing host. |
| public crawler → `sitemap` Edge Function → DB | Fully public, no JWT. Must not leak unpublished (draft) page slugs. |
| browser → `site_settings` write path | The `SiteSettingsPanel` write must be authorized server-side, not just hidden in the client UI. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-08-01 | Injection (Tampering) | `json-ld.ts` → `<script type="application/ld+json">` in served HTML | mitigate | `generateJsonLd` returns `JSON.stringify(...)` then `.replace(/</g, '\\u003c')`, so the output string can never contain a literal `</script>` to terminate the script tag. Unit test asserts a `</script>`-containing title produces output with no literal `</script>`. `json-ld.ts` never accepts raw user JSON-LD (D-16 — auto-generated + dropdown only). |
