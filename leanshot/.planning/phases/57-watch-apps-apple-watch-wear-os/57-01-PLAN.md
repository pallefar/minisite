<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| watch → phone | Watch quick-log payload crosses to the phone via WatchConnectivity; the watch is a lower-trust origin (no auth session of its own). |
| watch → backend (FORBIDDEN) | Watch must NEVER reach Supabase directly — it has no credentials; all writes relay through the authenticated phone. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-57-AUTH | Spoofing/Tampering | WatchConnectivityManager.swift payload | mitigate | Watch payload omits `user_id`; phone-side `dedupeAndMerge` (Plan 57-03) stamps `user_id` from the authenticated session. Acceptance asserts no `supabase`/`URLSession` import in watch sources. |
| T-57-LOSS | Repudiation/DoS | quick-log delivery path | mitigate | Use `transferUserInfo` (FIFO, offline-tolerant) not `sendMessage`. Acceptance greps for absence of `sendMessage` in the dose-log path. |
| T-57-SC | Tampering | npm/pod installs | accept | This plan installs NO packages; SwiftUI/WidgetKit/WatchConnectivity are Apple system frameworks resolved from the Xcode SDK (RESEARCH Package Legitimacy Audit — none). |
</threat_model>
