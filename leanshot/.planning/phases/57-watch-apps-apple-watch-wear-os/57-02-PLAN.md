<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| watch → phone | Wear quick-log DataItem crosses to the phone; the watch is a lower-trust origin with no auth session of its own. |
| watch → backend (FORBIDDEN) | The wear module must NEVER reach Supabase/HTTP directly; all writes relay through the authenticated phone. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-57-AUTH | Spoofing/Tampering | WatchDataLayerService.kt payload | mitigate | Wear payload omits `user_id`; phone-side `dedupeAndMerge` (Plan 57-03) stamps it from the authenticated session. Acceptance asserts no okhttp/retrofit/supabase/HTTP import in the wear module. |
| T-57-LOSS | Repudiation/DoS | quick-log delivery path | mitigate | Use `DataClient.putDataItem` (persisted, offline-tolerant), not `MessageClient` (no retry, drops on disconnect). Acceptance greps for absence of `MessageClient`. |
| T-57-SC | Tampering | Maven dependency installs | mitigate | Wear deps are official Google/Jetpack libraries on Maven Central (RESEARCH Package Legitimacy Audit — Approved, not npm). Task 1 verifies versions against Maven Central before pinning ([ASSUMED] → confirmed). |
</threat_model>
