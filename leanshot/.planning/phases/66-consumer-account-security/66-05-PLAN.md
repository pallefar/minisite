Mirror Phase 64-03 `grandfathered-policy-notice` shape (handler/index split + DI deps).

`handler.ts` exports `handleRequest(req, deps)`:
- `POST /` with body `{ email?: string, action: 'check' | 'log_failure' | 'log_success' }`
- For `check`:
  - Count failed attempts WHERE `email = lower(req.email)` AND `attempt_at > now() - interval '15 min'` → if ≥5 → return `{ allowed: false, reason: 'email', locked_until: now + 30min }`
  - Count failed attempts WHERE `ip_address = req.ip` AND `attempt_at > now() - interval '15 min'` → if ≥5 → return `{ allowed: false, reason: 'ip', locked_until: now + 30min }`
  - Else → `{ allowed: true }`
- For `log_failure`: insert row with `outcome='failed'` + `failure_reason`. THEN check brute-force thresholds:
  - Count failures by this IP in last 1h → if ≥10 → emit PostHog `auth_brute_force_detected` (ip-based) + Slack alert
  - Count failures against this email in last 1h → if ≥20 → emit PostHog (email-based) + Slack alert
- For `log_success`: insert row with `outcome='success'`. Also DELETE prior failure rows for this email in last 15min (clears the lockout window per D-03).

Use no auth (public Fn — pre-sign-in). Rate limit Fn itself via simple in-memory token bucket OR Vercel Edge rate-limit header check on inbound IP.

PostHog: use existing helper at `_shared/posthog-server.ts` (or whatever the project uses). Slack: `_shared/slack-alert.ts`. CAN-SPAM placeholder guard NOT needed (no email body sent).

`index.ts` thin Deno.serve wrapper with `import.meta.main` guard.

Test (Deno):
- check with no prior attempts → `{ allowed: true }`
- check with 5 failures from same email in 15min → `{ allowed: false, reason: 'email' }`
- check with 5 failures from same IP in 15min → `{ allowed: false, reason: 'ip' }`
- log_failure inserts row + fires PostHog when threshold crossed
- log_success deletes prior failure rows for the email

```ts
export async function signInWithLockout(
  supabase: SupabaseClient,
  email: string,
  password: string
): Promise<{ ok: true; user: User } | { ok: false; reason: 'locked' | 'invalid_credentials' | 'unknown'; lockedUntil?: Date }>;
```

Flow:
1. POST to `/functions/v1/auth-rate-limit-check` with `{ email, action: 'check' }` (also sends user's IP via header or fetch's default)
2. If `allowed: false` → return `{ ok: false, reason: 'locked', lockedUntil }`
3. Else call `supabase.auth.signInWithPassword({ email, password })`
4. On success → POST `{ email, action: 'log_success' }` → return `{ ok: true, user }`
5. On failure → POST `{ email, action: 'log_failure' }` → return `{ ok: false, reason: 'invalid_credentials' }`

Update the existing sign-in form (likely `src/components/auth/SignInForm.tsx`) to use `signInWithLockout` instead of `supabase.auth.signInWithPassword` directly.

`<SignInLockoutBanner>` props: `lockedUntil: Date`, `reason: 'ip' | 'email'`. Renders red banner: *"Too many failed attempts. Try again in MM:SS or use a [magic link](/login/magic)."* Countdown timer updates every second.

Test:
- `signInWithLockout` returns locked when rate-limit Fn says so (skip live sign-in call)
- Banner counts down + shows magic-link CTA
- Successful sign-in clears lockout
