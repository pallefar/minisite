For each surface, find the existing CTA handler and wrap it:

```tsx
async function handleDeleteAccount() {
  const gate = await requireAal2ForConsumerAction(supabase, 'delete-account', {
    onChallenge: () => new Promise(resolve => setAal2Modal({ open: true, resolve, purpose: 'delete-account' }))
  });
  if (gate.ok === false && gate.reason !== 'mfa_not_enabled') {
    toast.error('Please confirm your identity to delete your account');
    return;
  }
  // proceed with delete (existing logic)
}
```

If MFA not enrolled (`reason: 'mfa_not_enabled'`), the action proceeds WITHOUT step-up (per D-02 — gate doesn't apply if MFA not set up). This is intentional: we don't want to lock users out of account deletion by requiring MFA they haven't enrolled.

For export-all-data: target `src/lib/dsar/export-trigger.ts` (Phase 64-04 DSAR pipeline) — wrap the trigger function.
For change-email: target the existing form (likely in `src/components/settings/`). If no such form exists yet, create a minimal stub one that calls `supabase.auth.updateUser({ email })`.

Each wrap must NOT break MFA-disabled users (they get the action immediately).
