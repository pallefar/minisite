<objective>
Ship the `community-admin-report-digest` Edge Function — daily 9am UTC cron triggers it; it reads open `community_reports` rows, groups by target_type, and sends one email per admin (`is_staff=true` AND `admin_digest_opt_in=true`) using the `community_admin_report_digest` template added in 45-02. This bridges the Phase 45 report queue to admin visibility BEFORE Phase 48 ships the moderation UI (per CONTEXT integration-point — reports must not be invisible until Phase 48).

Per RESEARCH Pattern 3 + Pitfall 7: the Fn READS only (no write), avoiding the auth.uid() vs service-role mismatch. The cron migration uses the vault service-role pattern (memory `reference_supabase_pg_cron_vault_service_role_pattern`) + named dollar-quote tags (memory `reference_postgres_dollar_quote_nesting_in_cron_body`).

Purpose: Wave 1 — depends on schema (45-01: community_reports table + admin_digest_opt_in column) and notification widening (45-02: 'community-admin-report' category + email template). Consumed only by the daily cron — no consumer UI calls this Fn directly.
Output: Edge Fn implementation + Deno tests + per-fn deno.json + daily cron migration.
</objective>
