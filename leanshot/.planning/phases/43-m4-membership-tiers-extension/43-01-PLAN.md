<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stripe → stripe-webhook Edge Fn | Untrusted webhook payload; signature verified upstream via `stripe.webhooks.constructEvent` |
| stripe-webhook Edge Fn → Postgres (service-role) | Service-role bypasses RLS; idempotency guarantee from UNIQUE constraint on `stripe_payment_intent_id` |
| authenticated user → tier_effective view | RLS via `security_invoker=true`; user can only read their own `lifetime_purchases` row via self-read policy |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-43-01-01 | Tampering | webhook replay creates duplicate lifetime entitlement | mitigate | UNIQUE constraint on `lifetime_purchases.stripe_payment_intent_id` + upsert `onConflict: 'stripe_payment_intent_id', ignoreDuplicates: true` (D-02) |
| T-43-01-02 | Spoofing | malicious actor invokes webhook URL with forged `meta.tier_kind='lifetime'` for arbitrary user_id | mitigate | Stripe signature verification at outer dispatcher (existing `stripe.webhooks.constructEvent` in `stripe-webhook/index.ts`); `meta.user_id` originates from server-side `payment_intent_data.metadata` set in stripe-checkout (Plan 43-04), NOT user-controlled input |
| T-43-01-03 | Information Disclosure | one user reads another user's lifetime_purchases row via API | mitigate | RLS policy `pol_lifetime_purchases_self_read` with `USING (user_id = auth.uid())`; denial-by-default for all other operations |
| T-43-01-04 | Elevation of Privilege | authenticated user attempts INSERT into lifetime_purchases via PostgREST | mitigate | NO insert/update/delete RLS policies → denial-by-default (Pattern S2); service-role webhook is sole writer |
| T-43-01-05 | Information Disclosure | Slack alert leaks PII (user_id is uuid only; no email/name) | accept | Payload contains user_id + amount only; uuid is opaque; channel is internal Slack #growth-experiments |
| T-43-01-06 | Denial of Service | Slack webhook downtime blocks payment processing | mitigate | `EdgeRuntime.waitUntil` makes Slack call non-blocking; `.catch(console.error)` swallows failures; webhook returns 200 to Stripe regardless |
| T-43-01-07 | Tampering | concurrent webhook race creates two rows for same payment_intent | mitigate | UNIQUE index serializes at Postgres level (PG default); `ignoreDuplicates: true` returns success on second race-winner |
</threat_model>
