| Boundary | Description |
|----------|-------------|
| client → admin-impersonate | Caller JWT validated by gateway + is_staff re-checked in body |
| Edge Fn → Supabase Auth Admin API | Service-role key from env; mutations target user's app_metadata |
| client → admin-stripe-action | Caller JWT validated; Stripe secret never leaves Fn |
| Edge Fn → Stripe API | Bearer with STRIPE_SECRET_KEY; idempotency_key prevents replay |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-18 | S | Non-staff caller invokes admin Edge Fn | mitigate | is_staff re-check inside Fn body (gateway JWT verification only confirms identity, not authorization) |
| T-22-19 | E | Admin impersonates themselves or another admin | mitigate | Self-guard (target_user_id === caller.id) + admin-guard (target.is_staff check) in admin-impersonate body |
| T-22-20 | T | Impersonation 30-min TTL bypass via clock skew | mitigate | impersonation_exp written in app_metadata; useImpersonation hook (plan 22-09) reads via JWT exp claim; cron-cleanup deferred to v1.3 follow-up |
| T-22-21 | T | Refund amount > original charge | mitigate | Stripe API rejects natively; client UI in plan 22-07 also has `max={charge.amount}` input validation |
| T-22-22 | R | Stripe API succeeds but admin_log_refund fails → no audit row | accept | We swallow the secondary RPC failure but log to Sentry breadcrumb; Stripe webhook reconciliation (existing P14) catches the row via invoice.refunded event |
| T-22-23 | T | Stripe SDK error messages leak charge metadata to logs | mitigate | Wrap StripeError as `{error: 'stripe_' + code}`; never echo raw.message |
| T-22-24 | E | A1 PROBE FAIL: app_metadata write doesn't propagate → impersonation banner mounts before RLS sees claim → reads succeed but client thinks impersonation active | mitigate | Fallback branch mints custom HS256 JWT directly (claim is in token at issue time); plan 22-09 useImpersonation reads from JWT app_metadata (works in both branches) |
| T-22-25 | T | Refund idempotency_key collision (same charge refunded twice with different amounts) | accept | idempotency_key = 'refund-' + charge_id + '-' + amount_cents differentiates amounts; Stripe returns the existing refund record for identical args (intended) |
