  <name>Task 1: Enable RLS on 7 public tables (single migration)</name>
  <files>supabase/migrations/20290106000001_enable_rls_7_public_tables.sql</files>
  <action>
Create migration `20290106000001_enable_rls_7_public_tables.sql`. For each of the 7 tables, append a 3-statement block:

```sql
-- Block 1: email_send_counters
alter table public.email_send_counters enable row level security;
create policy "email_send_counters_deny_all_authenticated"
  on public.email_send_counters
  for all
  to authenticated
  using (false)
  with check (false);
comment on table public.email_send_counters is 'Service-role-only write; RLS enabled per Phase 66.5 SEC-01.';
```

Repeat verbatim for each of: `ad_spend_facts_y2026m05`, `ad_spend_facts_y2026m06`, `ad_spend_facts_y2026m07`, `ad_spend_facts_y2026m08`, `paywall_events`, `plan_history`.

CRITICAL:
- Use **bare** `create policy` (no `IF NOT EXISTS` — remote PG unsupported per `[[feedback_phase_close_out_supabase_gotchas]]`).
- Service-role (the Edge Fn writer role) is RLS-exempt automatically — no explicit bypass policy needed.
- The `using (false)` + `with check (false)` blocks all `authenticated`-role access via PostgREST. Anon access requires `to anon` to be added if a future plan needs it; default blocks anon too via `authenticated` role hierarchy.

If on running locally `supabase db push --local` ANY of the 7 tables don't exist (drift), the migration MUST `IF NOT EXISTS`-guard the `ALTER TABLE` — but `ALTER TABLE` doesn't support `IF NOT EXISTS` itself. Workaround: wrap each in a `DO $$ BEGIN ... EXCEPTION WHEN undefined_table THEN NULL; END $$;` block so the migration is idempotent against drift. Recommended for safety:

```sql
do $$
begin
  alter table public.email_send_counters enable row level security;
exception when undefined_table then
  raise notice 'public.email_send_counters does not exist on remote; skipping RLS enable (drift)';
end $$;

do $$
begin
  drop policy if exists "email_send_counters_deny_all_authenticated" on public.email_send_counters;
  create policy "email_send_counters_deny_all_authenticated"
    on public.email_send_counters
    for all
    to authenticated
    using (false)
    with check (false);
exception when undefined_table then
  raise notice 'public.email_send_counters does not exist on remote; skipping policy';
end $$;
```

NOTE the `drop policy if exists` BEFORE `create policy` — this lets the migration be replayable. The DO-block + drop-then-create combination is the safe-resume shape.

Repeat the DO-block pattern for each of the 7 tables. Long file but mechanical.

Before writing, INSPECT existing view definitions on remote OR in migration history:

```bash
grep -rE "create.*view.*v_cancellation_offers_roi|create.*view.*share_snapshot_view|create.*view.*user_activity_daily" supabase/migrations/ 2>&1 | head -10
```

For each view, find the migration that created it and read the full SELECT body. Then refactor:

### View 1: `v_cancellation_offers_roi`
- Action: `CREATE OR REPLACE VIEW public.v_cancellation_offers_roi WITH (security_invoker = true) AS <existing SELECT>`. The `WITH (security_invoker = true)` clause inverts the default and forces invoker-rights (PG15+).
- If the existing SELECT references tables that admin already has access to, no further changes. If it references restricted tables, RLS will block non-admin users — that's the desired behavior.

### View 2: `share_snapshot_view`
- Inspect the SELECT — does it `JOIN auth.users`?
- If YES: refactor the JOIN to use `public.profiles` (which has display_name + first_name but NOT email per `[[reference_profiles_email_vs_auth_users_email]]`). If the view returns email, the join MUST stay but be wrapped in a SECDEF function that returns rows for authorized callers (alternative: maintain the join but explicitly mask email with `'<redacted>'` AS email for the share recipient).
- DROP the SECDEF qualifier: `CREATE OR REPLACE VIEW … WITH (security_invoker = true) AS …`.

### View 3: `user_activity_daily`
- Inspect the SELECT — does it `JOIN auth.users`?
- If YES: refactor to use `public.profiles` join keys. Drop email/auth.users columns from the SELECT if not strictly needed.
- If the view truly needs auth.users.email: keep the join but ensure RLS on the underlying table chain restricts non-admin reads, OR replace the view with a SECDEF function.

If the project doesn't have these views in source-migrations (i.e. they were created via Studio without a migration), document that finding in 66-5-CARRY-OVER.md — operator must apply the refactor via SQL editor against remote.

For each view that DOES have a source migration, emit a `CREATE OR REPLACE VIEW … WITH (security_invoker = true) AS …` statement.
