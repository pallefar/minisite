# Phase 55 — UI Design Contract

> Visual and interaction contract for the HealthKit OPT-IN consent surface,
> enabled/syncing state, revoked state, and Settings revoke + historical-purge
> controls. Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

**Scope:** Consumer-facing iOS surface only. Four distinct UI states:
1. Consent screen (opt-in, HIPAA disclosure, default OFF)
2. Enabled/syncing state (HealthKit connected, last-sync timestamp)
3. Revoked state (firewall disabled, data flagged for optional purge)
4. Settings controls (revoke toggle + purge confirmation)

**Out of scope:** Firewall/import internals, non-UI architecture, on-device
HealthKit permission grant (Phase 70 HUMAN-UAT).

## Spacing Scale

Declared values (multiples of 4; Tailwind v4 `--spacing: 0.25rem` base):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (p-1) | Icon-text gaps, inline badge padding |
| sm | 8px (p-2) | Compact list item internal padding |
| md | 16px (p-4) | Default modal body / card padding |
| lg | 24px (p-6) | Section breaks within consent modal |
| xl | 32px (p-8) | Top/bottom modal breathing room on mobile |
| 2xl | 48px | Major section breaks (consent → action footer) |

Exceptions:
- Touch targets on Revoke and Purge buttons: minimum 44px height (use `Button size="lg"` or explicit `min-h-[44px]`). Required for iOS tap-target compliance.
- HealthKit data-type list items: `p-3` (12px) internal padding — matches `EditConsentScopeModal` row pattern.

## Color

All values are `var(--color-*)` tokens from `src/index.css`. No ad-hoc hex values.

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `--color-bg` | `#f2ede0` (cream-100) | Modal backdrop, page background |
| Secondary (30%) | `--color-surface` / `--color-surface-elevated` | `#fefcf7` / `#f6f2e8` | Modal body, data-type list item backgrounds, Settings card |
| Accent (10%) | `--color-primary` | `#1b4842` (teal-700) | Primary CTA button ("Connect Apple Health") only |
| Success | `--color-success` | `#45b077` (sage) | "Connected" badge, sync confirmation toast |
| Destructive | `--color-danger` | `#cf5454` (clay) | Revoke button, Purge button, Revoked badge, danger section border |

**Accent (`--color-primary`) is reserved for:**
- The "Connect Apple Health" primary opt-in CTA button only.
- The `accent-[var(--color-primary)]` on the single consent acknowledgement checkbox.

All other interactive elements (Sync now, Cancel, Revoke, Settings toggle) use
`tonal`, `ghost`, or `destructive` variants — not the accent token.

**Dark-mode:** All tokens resolve correctly under `[data-theme="dark"]` via the
existing DS token overrides in `src/index.css`. No dark-mode-specific overrides
needed in this phase.

## Component Composition Detail

### Consent Modal (`HealthKitConsentModal`)

```
Modal (size="md", mobileFullscreen, dismissible=false, hideClose=true)
  ├── [Icon: Heart — lucide, size-8, color=--color-primary]
  ├── [Heading 18px/600: "Connect Apple Health"]
  ├── [Body 13px/400: lead paragraph]
  ├── Card (variant="default")
  │   ├── [Label 13px/600: "What we read from Apple Health"]
  │   └── [ul — 7 data-type rows, each:]
  │       ├── [Icon: data-type icon, size-4, color=--color-text-secondary]
  │       └── [Body 13px/400: data type name + destination]
  ├── Card (variant="default", border=--color-primary-soft)
  │   ├── [Icon: Shield, size-4, color=--color-primary]
  │   └── [Body 13px/400: firewall guarantee]
  ├── [Body 13px/400: retention disclosure]
  ├── [Body 13px/400: revoke path disclosure]
  ├── [Caption 11px/400: "See our Privacy Policy for full details."]
  ├── [label — acknowledgement checkbox row]
  │   ├── <input type="checkbox" default=unchecked />
  │   └── [Label 13px/600: acknowledgement text]
  └── [footer — button row, gap-2, justify-end]
      ├── Button (variant="ghost"): "Not now"
      └── Button (variant="primary", disabled=!checked): "Connect Apple Health"
```

- `dismissible=false`: user must make an explicit choice (Not now OR Connect). ESC
  and backdrop click are disabled — this is a consent gate.
- `hideClose=true`: same reason — no ambient dismiss path.
- Firewall guarantee card uses `--color-primary-soft` (`#deebe6`) as background
  with a `Shield` icon — visually distinct from data-type list.
- Acknowledgement checkbox uses `accent-[var(--color-primary)]` (established
  pattern from `EditConsentScopeModal`).

### Settings HealthKit Card (`HealthKitSettingsSection`)

This is a Card within `SettingsPage.tsx` under a new `'healthkit'` section,
consistent with the existing section-per-feature pattern.

```
Card (variant="default")
  ├── [row: icon=Heart + Label 13px/600 "Apple Health" + Badge (Connected|Revoked|—)]
  ├── [STATE: connected]
  │   ├── [Caption 11px/400: "Last synced 2 hours ago"]
  │   ├── Pill (toggle, aria-pressed): "Auto-sync enabled"
  │   └── Button (variant="tonal", size="sm"): "Sync now" | "Syncing..."
  ├── [STATE: revoked]
  │   ├── [Body 13px/400: "HealthKit sync is disabled..."]
  │   └── Button (variant="tonal", size="sm"): "Reconnect"
  ├── [STATE: not connected]
  │   └── Button (variant="primary", size="md"): "Connect Apple Health"
  └── [if connected OR revoked — divider + destructive zone]
      ├── Button (variant="destructive", size="sm"): "Revoke HealthKit access"
      └── [if revoked — purge subsection]
          ├── [Body 13px/400: purge body copy]
          └── Button (variant="destructive", size="sm"): "Delete imported Apple Health data"
```

- Badge tones: `Connected` → success (sage), `Access revoked` → danger (clay),
  no badge → (state: not connected).
- Auto-sync Pill toggle: aria-pressed mirrors the `healthkit_enabled` flag in the
  user profile. Toggle OFF calls the Revoke flow (with confirmation gate).
- "Sync now" button: disabled while syncing; shows `<Loader2>` icon + "Syncing..."
  during in-progress state.
- Destructive zone is visually separated by a `border-t border-[var(--color-border)]`
  divider — same pattern as cancellation section in `SettingsPage`.

## Accessibility Contract

All requirements are HIPAA-consent-critical — this surface must be fully
keyboard-navigable and screen-reader-clear.

| Requirement | Implementation |
|-------------|----------------|
| Keyboard navigation | Tab order: firewall card → data list → disclosure text → checkbox → "Not now" → "Connect" |
| Focus trap | `Modal` already implements focus trap via framer-motion + tabindex management |
| Checkbox | `<input type="checkbox">` — native element, not custom. `aria-label` on each data-type icon (decorative: `aria-hidden="true"`) |
| Consent button disabled state | `disabled` attribute + `aria-disabled="true"` when checkbox unchecked |
| Sync badge | `<Badge role="status">` — live region for sync state changes |
| Confirmation dialogs | `role="dialog"` + `aria-modal="true"` on `Confirm` modal (already handled by `Modal` primitive) |
| Destructive buttons | `aria-label` includes the specific data subject: "Revoke Apple Health access" / "Delete imported Apple Health data" |
| Error toasts | `role="status"` + `aria-live="polite"` (already implemented in `Toast.tsx`) |
| Contrast | All body text on `--color-surface`: `#16221f` on `#fefcf7` — passes WCAG AA (contrast ratio ~16:1). All caption text (`--color-text-secondary` `#4d5e58`) on cream surface passes AA at 11px |
| Reduced motion | Consent modal entry animation gates on `useReducedMotion()` (existing modal pattern) |

## Platform Guard

The consent screen and HealthKit settings card MUST render only on iOS. On
non-iOS platforms:

- The "Connect Apple Health" CTA is replaced with the unavailable-state empty
  card ("Apple Health sync is only available on iPhone.").
- No consent modal is triggered.
- The Settings HealthKit section is still visible (informational) but all
  interactive controls are hidden — only the unavailability message is shown.

Platform detection uses `detectPlatform()` from `src/lib/native/platform.ts`
(not `@capacitor/core` directly — two-tunnel firewall rule).

## State Machine Summary

```
[Not connected / never opted in]
  └── User taps "Connect Apple Health" → Consent Modal opens
        ├── User checks acknowledgement + taps "Connect Apple Health"
        │     ├── iOS grants permission → [ENABLED] + success toast
        │     └── iOS denies permission → stays [Not connected] + error toast
        └── User taps "Not now" → Modal closes, stays [Not connected]

[ENABLED]
  ├── Auto-sync runs in background → updates "Last synced" timestamp
  ├── User taps "Sync now" → [SYNCING] → [ENABLED] on complete
  ├── User toggles Pill OFF → Revoke confirmation → [REVOKED] on confirm
  └── User taps "Revoke HealthKit access" → Revoke confirmation → [REVOKED]

[REVOKED]
  ├── User taps "Reconnect" → Consent Modal opens again (full disclosure re-shown)
  └── User taps "Delete imported Apple Health data" → Purge confirmation → Purge RPC → [REVOKED] (data gone)
```
