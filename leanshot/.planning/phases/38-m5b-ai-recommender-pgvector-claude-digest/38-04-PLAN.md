Algorithm:
1. Auth check: header must be service_role (compare against `SUPABASE_SERVICE_ROLE_KEY`); else 403.
2. `SELECT c.id, c.body_md, c.title, ce.body_sha256 AS stored_sha, ce.stale FROM content c LEFT JOIN content_embeddings ce ON ce.content_id = c.id WHERE c.published_at IS NOT NULL AND c.deleted_at IS NULL AND (ce.content_id IS NULL OR ce.stale = true) LIMIT 1000` — cap per run to avoid runaway.
3. For each row: compute `sha256(c.title || '\n\n' || c.body_md)`. If `ce.stale = true AND stored_sha === computed_sha` → just UPDATE `content_embeddings SET stale = false, last_embedded_at = now() WHERE content_id = $1` and skip embed call. Emit metric `embed.dedup_skip`.
4. Else queue for batch embed: collect up to 100 inputs into one fetch call body (`{ model: OPENAI_EMBED_MODEL, input: [text1, text2, ...] }`). Iterate 5 batches in parallel (Promise.all with semaphore), then 1s sleep, then next 5 batches. Per RESEARCH Pitfall #3.
5. For each successful embedding: UPSERT into `content_embeddings (content_id, embedding, body_sha256, last_embedded_at, stale, embedding_model_id) VALUES (...) 6. 429 handling: parse `Retry-After` header, sleep that many seconds, retry up to 3 times; on 3rd failure, log row_id to Sentry + emit `embed.rate_limit_429` + continue (do not throw).
