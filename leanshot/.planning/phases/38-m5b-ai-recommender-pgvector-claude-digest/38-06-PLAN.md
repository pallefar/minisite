Create `supabase/functions/plan-personalize/index.ts`:

Algorithm (D-17 rule-based, NO LLM):
1. Auth: user JWT OR service_role; else 401.
2. Parse body. Validate `context ∈ {paywall, save_offer}`. 400 on invalid.
3. Single SQL query (denormalized into one query for the <50ms budget): `SELECT p.user_id, p.created_at AS signup_at, p.plan_tier, p.is_active, COALESCE(act.activated_at, NULL) AS activated_at, COALESCE(act.activation_score, 0) AS activation_score, COALESCE(pd.dismissal_count, 0) AS paywall_dismissals, COALESCE(ph.last_plan_change, NULL) AS last_plan_change FROM profiles p LEFT JOIN activation_events act ON act.user_id = p.id LEFT JOIN (SELECT user_id, count(*) AS dismissal_count FROM paywall_events WHERE event_type='dismissed' GROUP BY user_id) pd ON pd.user_id = p.id LEFT JOIN (SELECT user_id, max(changed_at) AS last_plan_change FROM plan_history GROUP BY user_id) ph ON ph.user_id = p.id WHERE p.id = $1`. NOTE: assumes these tables/views exist (Phase 14 Stripe + Phase 34 activation + Phase 39 paywall). If a table missing → return 404 OR fall back to default rule (`extended_trial` per D-17 hand-coded fallback). Document inline.
4. 404 if no row.
5. Apply hand-coded rules in priority order (first match wins, deterministic):
   - **R1:** `context='save_offer' AND is_active=true AND plan_tier='paid_monthly'` → `pause_offer` (confidence 0.9, rationale "Active monthly paid; pause preserves retention before discount").
   - **R2:** `paywall_dismissals >= 3` → `discount_eligible` (confidence 0.8, rationale "≥3 paywall dismissals — price-sensitive signal").
   - **R3:** `plan_tier='paid_monthly' AND paywall_dismissals = 0 AND (now() - signup_at) > interval '60 days'` → `annual_nudge` (confidence 0.7, rationale "60+ day monthly with no dismissals — annual conversion candidate").
   - **R4:** `(activation_score IS NULL OR activation_score < 0.3) AND plan_tier IN ('trial','free')` → `extended_trial` (confidence 0.6, rationale "Low activation; extended trial rescue").
   - **R5 (fallback):** `extended_trial` (confidence 0.3, rationale "Default — no specific signal").
6. Return JSON.
7. NEVER call AI Gateway. NEVER load embeddings. NEVER load symptom or weight data (irrelevant to plan personalization).
8. Single SQL roundtrip + handful of branches → consistently <50ms in warm Edge Fn (~20-30ms typical).
9. Sentry breadcrumb `plan.personalize.rule_matched` with rule ID. PostHog `plan_personalize.hint_returned` with offer_hint + confidence (no PII). `posthog.shutdown()`.
