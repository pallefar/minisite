  <name>Task 1: check-tailwind-tokens.ts (DS-01)</name>
  <files>scripts/ci/check-tailwind-tokens.ts, scripts/ci/check-tailwind-tokens.test.ts</files>
  <action>
Script logic:
1. Parse `leanshot/src/index.css` `@theme { ... }` block — extract all defined token names (e.g. `--color-text`, `--color-surface`, `--color-primary`, `--spacing-1`).
2. Convert to Tailwind utility prefixes: `text-text`, `bg-surface`, `border-primary`, `space-1`, etc.
3. Walk `leanshot/src/**/*.tsx` + `.ts` (skip `.test.*` files).
4. Regex match all Tailwind class usages: `className="..."` + `cn(...)` + `clsx(...)`.
5. For each `text-*` / `bg-*` / `border-*` / `from-*` / `to-*` / `ring-*` / `divide-*` / `placeholder-*` class found, check if the suffix matches a defined token.
6. Special cases — allow:
   - Numeric scale: `text-sm`, `text-lg`, `text-base`, `text-xl`, etc. (Tailwind built-in scale)
   - Standard utilities: `text-center`, `text-left`, `text-right`, `text-balance`, `text-ellipsis`, `text-clip`
   - Sizing: `w-*`, `h-*`, `p-*`, `m-*` with numeric arg
7. Report violations (e.g. `text-text-primary` when only `text-text` exists, or `bg-surface-card` when only `bg-surface` exists).
8. Exit code 1 if any violation found.

Test cases (5+):
- Token `--color-text` defined → `text-text` passes, `text-text-primary` fails
- `bg-surface` passes, `bg-surface-card` fails
- `text-center` always passes (built-in)
- File ending in `.test.tsx` skipped
- Empty @theme block → all custom tokens flagged
  </action>

  <name>Task 2: check-typography-ceiling.ts (DS-02)</name>
  <files>scripts/ci/check-typography-ceiling.ts, scripts/ci/check-typography-ceiling.test.ts</files>
  <action>
Script logic:
1. Walk `leanshot/src/**/*.{tsx,ts,css}` (skip `.test.*`).
2. Regex find all font-size declarations:
   - Tailwind: `text-\[(\d+)px\]`, `text-(xs|sm|base|lg|xl|2xl|3xl|...)` (built-in scale → map to px)
   - CSS: `font-size:\s*(\d+)px` in `.css` files (skip `index.css`)
   - Inline style: `style={{ fontSize: '(\d+)px' }}`
3. Collect unique px values across the codebase.
4. Allowed: {11, 13, 18, 28} px (per Phase 60-13 enforcement + ROADMAP DS-02).
5. Same for font-weight: allowed {400, 600}. Detect `font-(normal|medium|semibold|bold)` + `font-\[(\d+)\]` + CSS `font-weight: (\d+)`.
6. Report violations with file:line locations.
7. Exit code 1 if violations.

Test cases (4+):
- File using only 11/13/18/28 px → pass
- File with `text-[14px]` → fail (14 not in ceiling)
- File with `font-semibold` (600) → pass; `font-medium` (500) → fail
- text-heading custom utility class → allow if it resolves to ≤28px in @theme

NOTE: this is a heuristic — won't catch every CSS-in-JS variant. Document limitations in script header.

```markdown
# LeanShot Accent Color Reserved List (DS-03)

Accent tokens (`text-primary`, `bg-primary`, `text-accent`, `bg-accent`,
`text-success`, `bg-success`, etc.) are reserved for SPECIFIC interactive
or status-bearing surfaces. Non-reserved usage indicates either:
- Decorative noise (visual weight without semantic meaning), or
- Missing a real accent purpose (the color is doing the job of typography or spacing)

## Reserved Surfaces (allowed accent use)
- Primary CTA buttons (`<Button variant="primary">`)
- Active tab indicators
- Selected item state (lists, cards)
- Status badges (success / warning / danger / info)
- Notification dots / unread counts
- Charts: data line color
- Loading spinners / progress bars

## Non-Reserved (forbidden accent use)
- Body text headers (use `text-text` or `text-heading`)
- Card borders that aren't selected state
- Decorative icons next to neutral text
- Sidebar nav labels (active state OK; inactive labels = text-text-muted)
- Modal title bars
- Form input borders (default state)

## Audit Workflow
`scripts/ci/check-accent-reserved.ts` greps for `text-primary` / `text-accent` /
`text-success` / etc. classes + flags occurrences in files NOT matching the
reserved-surface list (heuristic via filename pattern).
```
