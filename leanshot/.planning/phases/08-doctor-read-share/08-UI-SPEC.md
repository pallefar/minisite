# Phase 8 — UI Design Contract

> Visual and interaction contract for the doctor read-share surfaces (patient-side Settings → Active shares + Share-creation modal + doctor-side `/share/{token}` SPA branch). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Inherits the LeanShot v2 design system already declared in `src/index.css` (`@theme` tokens). This phase does NOT introduce a new design language — every value below is pulled from existing tokens. Net-new components (`SharePage`, `CreateShareModal`, `ActiveSharesSection`, `CodeEntryScreen`, `ShareRevokedScreen`) compose existing primitives (`Card`, `Button`, `Modal`, `Input`, `EmptyState`, `Pill`, `Badge`, `Toast`, `MedLevelChart`, `DoctorReport`).

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Tailwind v4 beta with CSS `@theme` tokens) |
| Preset | not applicable |
| Component library | none — internal primitives at `src/components/ui/` (Button, Card, Modal, Input, Toast, EmptyState, Pill, Badge, ConfirmModal, Skeleton) |
| Icon library | `lucide-react` ^0.460.0 (project standard; reuse `Shield`, `Link2`, `Copy`, `Eye`, `EyeOff`, `Trash2`, `Clock`, `User as UserIcon`, `Printer`, `XCircle` from existing imports) |
| Font | Inter (sans, body/UI), Fraunces (display headings, italic 400), JetBrains Mono (numerals/codes — `font-mono` class with `tnum`) |

**Rationale:** Phase 2 + Phase 7 shipped with this stack; introducing shadcn or any new primitives this phase would (a) fight the bundle ceiling (50 kB gz index, currently 21.49 kB) and (b) drift the visual language from the rest of the app right before B2B Phase 9. The doctor's view MUST look and feel like the patient app so the chart + DoctorReport ports render identically.

The LeanShot palette is "clinical warmth": cream-100 surface, teal-700 hero/primary, sage/rose/amber as semantic accents. Per the existing 60/30/10 distribution defined across Phases 1–7, this phase reuses the same ratios. Source tokens: `src/index.css:11-77` (light) + `:158-203` (dark).

| Role | Light value | Dark value | Usage |
|------|-------------|------------|-------|
| Dominant (60%) | `--color-bg` `#efebe0` (cream-100) | `#0b1413` (teal-950) | Page background of Settings + SharePage + CodeEntryScreen |
| Secondary (30%) | `--color-surface` `#fdfbf6` (cream-card) | `#16201e` (teal-900-ish) | Active-shares rows, share-creation modal card, code-entry card surface |

| Warning | `--color-warning` `#e37748` (orange) | `#e37748` | Expiry-imminent banner ("Expires in 4 hours") chip; NOT used as a CTA |

**Accent reserved-for list (the only places `--color-primary` appears as a fill or strong stroke):**
1. Primary CTA buttons: "Create share link", "Generate share", "Submit code", "Print view"
2. Focus-visible outline (`:focus-visible` rule already at `index.css:298`)
3. Active-shares row Pill labeled `"Active"` (status indicator)
4. Recipient-cookie-bound state Pill labeled `"Recipient verified"` on SharePage header
5. Help-link copy underline inside the share-creation modal disclosure ("What can the doctor see?")
6. Numeric badge inside Settings nav for active shares count (existing pattern from Recovery)

**Accent NOT used for:**
- Body text
- Card backgrounds
- Disabled states (use `--color-text-tertiary`)
- Non-primary buttons (those use `secondary` or `ghost` Button variants — already declared in `Button.tsx:34-41`)

**Destructive reserved-for list:**
1. "Revoke" button in Active shares row (uses `Button variant="destructive"`)
2. "Share revoked" page on doctor side: large `XCircle` icon in `--color-danger`
3. Wrong-code error border on `CodeEntryScreen` Input (re-uses existing `aria-invalid` styling from `Input.tsx`)
4. Confirm-revoke modal (typed-confirm with `confirmDestructive=true`, reuses existing `ConfirmModal` from `Confirm.tsx`)

## Interaction Contracts

### Share creation flow
1. Patient clicks `Create share link` in Active shares section → modal opens with focus on `Who is this for?` Input.
2. Patient enters label (≥1 char, ≤80 chars), picks expiry radio (default `7 days`), reviews disclosure → clicks `Generate share`.
3. Modal shows loading state (Button `loading` prop already in `Button.tsx`); on success transitions to post-creation state in-place (same modal, animated via existing `animate-rise`).
4. Two copy buttons render the link + code. Both trigger existing toast pattern (`role="status" aria-live="polite"`).
5. Patient clicks `Done` → modal closes, Active shares list optimistically prepends the new row.
6. Optimistic insert reconciles within 500ms via the share-create RPC response; on failure, row is removed and a `--color-danger-soft` toast surfaces.

### Code entry flow (doctor side)
1. Doctor opens share URL → SharePage mounts in lazy chunk.
2. Edge Function GET `/share/snapshot` returns 401 with `requires_code` → render CodeEntryScreen.
3. Input auto-focuses. Each digit accepts numeric only (`inputMode="numeric" pattern="[0-9]*"`); 6-char max.
4. Auto-submit triggers when 6 digits entered (no Submit button click needed — but Submit button is also present + keyboard-accessible for accessibility).
5. POST `/share/redeem` → on 200: set HttpOnly cookie server-side, transition to SharePage state C with animated fade. On 401: shake the input (`animate-pulse-soft` once, gated by reduced-motion), show error message in `--color-danger`. On 429: show rate-limit copy. On 410 (already consumed): show consumed copy.
6. SharePage subsequently polls `/share/snapshot` (cookie now binds it). No further code prompts.

### Revocation flow
1. Patient opens Active shares → clicks IconButton `Trash2` on a row → typed-confirm ConfirmModal opens.
2. Patient types share label → `Revoke share` button enables.
3. Confirm → RPC call; row Pill flips to `--color-text-tertiary` + label `Revoking…` (Skeleton shimmer disabled per reduced-motion contract).
4. On success (≤1s): row animates out (`animate-fade-in` reverse-direction or fade-out), toast surfaces `Share revoked. Doctor's page is now disabled.`
5. Doctor's open tab: next snapshot poll returns 401 → SharePage transitions to ShareRevokedScreen state D within seconds (matches SC#3 verbatim).

### Print flow (SC#5)
1. Doctor clicks `Print` button on SharePage header.
2. Existing `window.print()` from `DoctorReport.tsx` runs.
3. Global `@media print` rule (index.css:560-573) strips chrome, preserves chart watermark (Phase 3 PK-04), enforces `page-break-inside: avoid` on cards.
4. SharePage adds a print-mode footer line: `Shared via LeanShot · {date printed} · Patient ID redacted` (uses opaque share_id, not patient_id per D-02 Failure Mode (c)).

### Cache-Control header (SC#5)
All Edge Function responses on share routes carry `Cache-Control: private, no-store`. UI does not need to assert this directly, but SharePage MUST NOT use service-worker caching or any client-side persistence of snapshot data (no Zustand persist, no IndexedDB queue — verified by the "doesn't touch store" invariant above).

## Accessibility Contract

Inherits Phase 1 + Phase 2 a11y stance + the conventions block in `CLAUDE.md`. This phase adds:

| Element | Requirement |
|---------|-------------|
| CodeEntryScreen Input | `aria-label="6-digit access code"`, `inputMode="numeric"`, `autoComplete="one-time-code"`. Auto-focus on mount. |
| ShareRevokedScreen heading | `<h1>` so screen-reader users land on the error message immediately, not on a navigation. |
| Active shares row | Row is a `<li>` inside `<ul role="list">`; revoke IconButton has `aria-label="Revoke share for {label}"`. |
| Pill ("Active", "Recipient verified") | `aria-label` echoes visible text + status: `aria-label="Status: Active"`. |
| Print button | `aria-label="Print this share"` (icon-only on mobile, with-label on desktop). |
| SharePage disclaimer banner | `role="note"` with the disclaimer copy as the accessible name. |
| Code copy buttons | Trigger `role="status" aria-live="polite"` toast on success. |
| Reduced-motion | All page-transition animations (`animate-rise`, `animate-fade-in`) honor the existing `prefers-reduced-motion: reduce` rule already in `index.css:485`. Shake-on-wrong-code animation is suppressed entirely under reduced motion. |
| Color contrast | Destructive `clay #cf5454` on cream-card `#fdfbf6` → ratio 4.59:1 (AA passes for body text). Pill "Active" teal-700 on teal-100 → ratio 8.42:1 (AAA). Verified against Phase 2 audit. |
| Focus management | After ConfirmModal closes, focus returns to the IconButton that opened it (Modal.tsx already does this). |
| Keyboard | Tab order on SharePage: skip-to-content link → header → disclaimer → chart → injections → symptoms → photos → weight → doctor report → print button → footer. Print button must be reachable without entering the chart focus trap. |
