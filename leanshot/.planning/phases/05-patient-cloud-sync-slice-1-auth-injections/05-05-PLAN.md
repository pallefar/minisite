Zustand persist `StateStorage` interface (what the adapter must implement):
```ts
interface StateStorage {
  getItem: (name: string) => string | null | Promise<string | null>;
  setItem: (name: string, value: string) => void | Promise<void>;
  removeItem: (name: string) => void | Promise<void>;
}
// Persist passes the configured `name` (currently STORAGE_KEY) as the `name` arg
// on every call. Adapter must IGNORE the passed name and route to the active
// userId's namespace; otherwise we keep writing to STORAGE_KEY.
```

Critical Gotcha — `namespacedKey` is async (uses `crypto.subtle.digest`), but Zustand persist's `getItem`/`setItem` are called synchronously during render-adjacent state updates. The adapter MUST cache the hash synchronously after `setActiveStorageUserId` is called, so getItem/setItem can read the cached namespaced key without awaiting on every call. Persist tolerates `Promise<string|null>` from getItem, but setItem returning a Promise is fine and ignored.

<implementation_design>
Architecturally:

1. **Module-level state in `src/lib/storage.ts`:**
   ```ts
   let activeNamespaceKey: string | null = null;
   // null  → adapter writes/reads the universal STORAGE_KEY
   // string → adapter writes/reads activeNamespaceKey (already-computed namespaced key)
   ```

2. **`setActiveStorageUserId(userId: string | null): Promise<void>`** — exported. Computes the namespaced key via `namespacedKey(userId)` and caches the result in `activeNamespaceKey`. Pass `null` to revert to the universal key (used by SIGNED_OUT).

3. **`createNamespacedStorage(): StateStorage`** — exported factory. Returns a synchronous adapter object whose three methods route to `localStorage[activeNamespaceKey ?? STORAGE_KEY]`. Critically, `setItem` MUST also write to the same key persist expected (no migration here — App.tsx's existing `renameStorageNamespace` still owns the one-shot migration).

4. **`removeUserNamespace(userId: string): Promise<void>`** — exported. Used by App.tsx's SIGNED_OUT handler to wipe the prior user's namespaced key. Wrapped in try/catch (private mode no-op).

5. **App.tsx wiring:**
   - INITIAL_SESSION + SIGNED_IN (verified email): `await setActiveStorageUserId(session.user.id)` BEFORE `renameStorageNamespace(session.user.id)` (so that any post-migration write lands in the namespaced key).
   - SIGNED_OUT: capture `prevUserId` from `useStore.getState().signedIn?.user?.id` BEFORE `setSession(null)`; then `await setActiveStorageUserId(null)`, then `await removeUserNamespace(prevUserId)` to wipe the residue.

6. **No behavioral change for anon users:** Phase 4's anonymous sign-in path mints an anon UID but `session.user.is_anonymous === true`, so the INITIAL_SESSION/SIGNED_IN branches that gate on `!session.user.is_anonymous && session.user.email_confirmed_at` will NOT call setActiveStorageUserId for anon. Anon writes continue to land in the universal key, which is correct — `renameStorageNamespace` migrates anon → permanent on the first verified SIGNED_IN.

**Ordering matters in App.tsx (sequence within INITIAL_SESSION/SIGNED_IN):**

```
setSession(session)                           // already there
setLastWasAnon(...)                           // already there (INITIAL_SESSION only)
if (verified):
  await setActiveStorageUserId(user.id)       // ← NEW — adapter now routes to namespace
  await renameStorageNamespace(user.id)       // already there — one-shot migration
  await runAnonPromotionMigrationIfNeeded()   // already there
  enqueueLocalInjectionsForSync()             // already there
  await pullInitialInjections(user.id)        // already there
  subscribeInjections(user.id)                // already there
  await flushSyncQueue()                      // already there
```

If `setActiveStorageUserId` ran AFTER `renameStorageNamespace`, the first call between them could trigger a persist setItem against the universal key (since `activeNamespaceKey` is still null), defeating the fix. Order is non-negotiable.
</implementation_design>

    // Phase 5 G2 (Plan 05-05) — per-user storage adapter.
    //
    // Closes 05-UAT.md gap G2 (T-05-03 cross-account leak). Before this adapter,
    // Zustand persist was hardcoded with `name: STORAGE_KEY` — so every write
    // after the one-shot `renameStorageNamespace` migration went BACK to the

    //
    // Usage (src/lib/store.ts):
    //   persist((set, get) => ({...}), {
    //     name: STORAGE_KEY,                       // persist's `name` is ignored by the adapter
    //     storage: createNamespacedStorage(),      // adapter routes via module-level activeNamespaceKey
    //     ...
    //   })
    //
    // Wiring (src/App.tsx onAuthStateChange):
    //   case 'SIGNED_IN' / 'INITIAL_SESSION' (verified):

    //     if (prev) await removeUserNamespace(prev);
    // ---------------------------------------------------------------------------

    let activeNamespaceKey: string | null = null;

    /**
     * Set the active user's namespaced key. Pass `null` to revert to the universal
     * `STORAGE_KEY` (used on SIGNED_OUT and during pre-signin anon activity).
     * `namespacedKey` is async (uses `crypto.subtle.digest`); the result is cached
     * synchronously so subsequent get/setItem calls do not need to await.
     */
    export async function setActiveStorageUserId(
      userId: string | null,
    ): Promise<void> {
      if (userId == null) {
        activeNamespaceKey = null;
        return;
      }
      activeNamespaceKey = await namespacedKey(userId);
    }

    /** Test-only inspector: returns the cached namespaced key (or null). */
    export function getActiveStorageNamespace(): string | null {
      return activeNamespaceKey;
    }

    /**
     * Zustand `StateStorage` adapter that routes every read/write/delete to the
     * active user's namespaced localStorage key (or `STORAGE_KEY` when no user is
     * active). The `name` argument from Zustand persist is IGNORED — persist
     * configures `name: STORAGE_KEY` only to satisfy its type contract; routing
     * is owned by `activeNamespaceKey`.
     *
     * Wrapped try/catch on every operation mirrors the existing `migrateFromV3`
     * pattern — private-mode browsers and quota errors are silent no-ops.
     */
    export function createNamespacedStorage(): {
      getItem: (name: string) => string | null;
      setItem: (name: string, value: string) => void;
      removeItem: (name: string) => void;
    } {
      return {
        getItem: (_name: string): string | null => {
          const key = activeNamespaceKey ?? STORAGE_KEY;
          try {
            return localStorage.getItem(key);
          } catch {
            return null;
          }
        },
        setItem: (_name: string, value: string): void => {
          const key = activeNamespaceKey ?? STORAGE_KEY;
          try {
            localStorage.setItem(key, value);
          } catch {
            /* private-mode / quota — silent no-op */
          }
        },
        removeItem: (_name: string): void => {
          const key = activeNamespaceKey ?? STORAGE_KEY;
          try {
            localStorage.removeItem(key);
          } catch {
            /* noop */
          }
        },
      };
    }

    /**
     * Wipe a specific user's namespaced localStorage key. Called by App.tsx's
     * SIGNED_OUT handler with the prior user's id so signed-out users leave no
     * per-user residue (UAT G2 missing item #2).
     */
    export async function removeUserNamespace(userId: string): Promise<void> {
      const key = await namespacedKey(userId);
      try {
        localStorage.removeItem(key);
      } catch {
        /* noop */
      }
    }

    /**
     * Test-only reset hook — clears the module-level cached namespace so unit
     * tests can run independently. Not for production use.
     * @internal
     */
    export function __resetActiveNamespaceForTests(): void {
      activeNamespaceKey = null;
    }

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User A's session → User B's session (same browser) | Two distinct human users using the same browser. After A signs out and B signs in, B's UI must show ZERO of A's data.
