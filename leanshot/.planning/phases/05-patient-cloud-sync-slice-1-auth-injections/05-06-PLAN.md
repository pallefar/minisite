<implementation_design>
The fix is a 2-line change inside MedicationTab plus a co-located test. Architecturally:

1. Replace `useStore((s) => s.user!)` with the nullable variant `useStore((s) => s.user)`.
2. Insert `if (!user) return null;` immediately after all hook calls — i.e., after `useState`, `useToast`, all the `useStore` selectors. React's rules-of-hooks require all hooks fire before the early return.
3. Rename the local variable from `u` to `user` for clarity (the `u` shorthand is a project convention per CLAUDE.md "Local variables: ... sometimes terse single-letters in tight scopes" — but the `!` assertion was the trap; making the variable a regular noun signals it's nullable elsewhere). Optional rename — if the executor prefers to keep `u` for minimal-diff, that's acceptable as long as the guard works.

**Why not the "move SIGNED_OUT view switch ahead of user-clearing setState" alternative?**

The UAT block calls out both options. Option B (re-order the App.tsx state machine so the view switches before `clearUserDataSlices`) is structurally invasive — App.tsx's SIGNED_OUT branch already runs `unsubscribeInjections()` THEN `clearUserDataSlices()` THEN hash-cleanup. Reordering to make MedicationTab unmount FIRST requires either:
- Adding an intermediate "signing-out" view state that hides dashboard tabs (UI flicker risk), or
- Using `flushSync` to force the unmount before the `set({...})` that clears `user` (React 18 footgun territory).

Option A (the null-guard) is the lower-risk, smaller-blast-radius fix. Sentry-noise-only severity (per UAT) doesn't justify the App.tsx reorder. This plan executes Option A.
</implementation_design>
