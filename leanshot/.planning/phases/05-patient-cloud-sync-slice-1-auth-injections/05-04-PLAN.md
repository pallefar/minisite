<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Email-link → browser | Supabase emails the user a one-time link. The link's `redirect_to` query param is server-validated against the allowlist before Supabase exchanges the token for a session. An attacker who crafts a forged link cannot redirect the user to an attacker-controlled host UNLESS that host matches the allowlist glob. |
| Browser → Supabase Auth API | The browser holds the user's session JWT after the redirect lands; before the redirect, the user is unauthenticated. |
| supabase/config.toml → /auth/v1/settings | `supabase config push --linked` is the only path from local TOML to the production GoTrue config. The push is authenticated via the Supabase CLI token (stored in `~/.supabase/access-token`). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-04-01 | Spoofing | Email-link `redirect_to` | mitigate | Allowlist enforced server-side by Supabase Auth — only the 4 explicitly-listed hosts (localhost dev/preview, production SPA, Vercel preview pattern) can receive the post-redirect session. An attacker who submits `redirect_to=https://evil.com/#/auth/verify` to a `generateLink` admin call will get `redirect_to` rewritten to `site_url` (= the production SPA URL). Verified by Task 1 verify-step probe 4 in reverse: any URL outside the 4 entries gets overridden. |
| T-05-04-02 | Information disclosure | `additional_redirect_urls` glob breadth | accept | `https://*-karstens-projects-16afd0e4.vercel.app/**` matches every preview deployment under the karsten team scope, including PR previews from forks. This is intentional — Vercel preview URLs are unguessable (8-char hash) and the team scope is non-public. Risk: an attacker who already has access to fork-preview deployment could phish a leanshot user with a Vercel preview link. Accepted because: (a) preview deployments require active Vercel team membership to deploy, (b) the user must still click the email link from their inbox, (c) the alternative — listing each preview URL by hand — is operationally untenable. Revisit if leanshot makes the GitHub repo public OR enables Vercel preview comments on forks. |
| T-05-04-03 | Tampering | `supabase config push` drift | mitigate | Task 1 acceptance criteria require the CLI diff to show ONLY the two-key change. Any additional drift (e.g., to `minimum_password_length` or anonymous sign-ins) is a STOP condition. The 05-02 Task 5 evidence is the baseline. |
| T-05-04-04 | Elevation of privilege | Supabase CLI access-token leak | accept | The CLI access-token lives in `~/.supabase/access-token` on the developer machine and is not in scope for this plan to rotate. Mitigation is operational (don't commit `~/.supabase/`, don't paste the token into AI chat) — covered by `.planning/decisions/supabase.md` "Rule" section. |

</threat_model>
