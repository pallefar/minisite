# Phase 9 — UI Design Contract

> Visual and interaction contract for the clinic B2B foundations surfaces (operator org-create + workspace home + invite modal + clinic settings with roles admin UI + patient-side consent dialog + Active organizations settings tab + workspace switcher). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Inherits the LeanShot v2 design system already declared in `src/index.css` (`@theme` tokens) and extended by Phase 7 (legal pages) + Phase 8 (share). This phase does NOT introduce a new design language — every spacing/typography/color value below is pulled from existing tokens. Net-new components (`ClinicWorkspace`, `ClinicContextBar`, `WorkspaceSwitcher`, `InvitePatientModal`, `OrgCreateFlow`, `ClinicSettingsPage`, `RolesTab`, `MembersTab`, `WorkspaceTab`, `ConsentDialog`, `ClinicInvitePage`, `ActiveOrganizationsSection`, `EditConsentScopeModal`) compose existing primitives (`Card`, `Button`, `Modal`, `Sheet`, `Input`, `Pill`, `Badge`, `EmptyState`, `Skeleton`, `ConfirmModal`, `Toast`, `IconButton`).

The clinic surface MUST look and feel like the patient app so workspace-context switching feels seamless (Pitfall #8 single-identity invariant) — same fonts, same color tokens, same spacing rhythm, same primitives. Operator UI does not get a different brand; only the clinic-context bar shows the org's logo + name.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Tailwind v4 beta with CSS `@theme` tokens) |
| Preset | not applicable |
| Component library | none — internal primitives at `src/components/ui/` (Button, Card, Modal, Sheet, Input, Toast, EmptyState, Pill, Badge, ConfirmModal, IconButton, Skeleton) |
| Icon library | `lucide-react` ^0.460.0 (project standard; new icons used this phase: `Building2`, `Users`, `UserPlus`, `Mail`, `Shield`, `ShieldCheck`, `KeyRound`, `LogOut`, `ChevronsUpDown`, `Image as ImageIcon`, `Upload`, `Check`, `X`, `AlertTriangle`, `Stethoscope`, `Eye`. Reused from Phase 8: `Link2`, `Trash2`, `Copy`, `Clock`, `XCircle`, `User as UserIcon`) |
| Font | Inter (sans, body/UI), Fraunces (display headings, italic 400), JetBrains Mono (slug + invitation tokens — `font-mono` class with `tnum`) |

**Rationale:** Phase 2 + Phase 7 + Phase 8 all shipped with this stack. Introducing shadcn or any new UI library at Phase 9 would (a) fight the 50 kB gz index ceiling already pressured by Phase 5/6 sync code, (b) drift the visual language right when patients are about to context-switch between their personal account and a clinic workspace, and (c) re-open the Pitfall #8 single-identity affordance discussion. The clinic chrome is operator-facing but lives in the same `auth.users` identity as the patient app — they need to feel like one product.

## Spacing Scale

Tailwind v4 `--spacing: 0.25rem` (4px base). All values below are multiples of 4. Source: `src/index.css:122`. Identical to Phase 8 UI-SPEC.

| Token | Value | Usage (this phase) |
|-------|-------|--------------------|
| 1 | 4px | Icon-to-label gaps inside Pill role-badges, switcher row icons |
| 2 | 8px | Compact stack inside member-list row metadata (joined_at, role); checkbox-to-label gap in consent dialog |
| 3 | 12px | Form-field internal padding (slug input, invite email input); gap between consent-scope checkbox rows |
| 4 | 16px | Default vertical/horizontal gap between settings rows + Modal body padding; gap between role-permission grid cells |
| 6 | 24px | Section padding inside Settings cards; gap between Org-create wizard steps |
| 8 | 32px | Page-level vertical rhythm on workspace home (between context bar / empty roster shell / Invite CTA) |
| 12 | 48px | Empty-state vertical padding on workspace home roster shell |
| 16 | 64px | Maximum content gap; consent dialog top margin on desktop |

**Touch-target exception:** IconButton actions inside the Active organizations rows + Members list rows use `IconButton size="md"` which resolves to 40px square — kept at 40 (not 44) to match the existing pattern from Phase 6/7/8. Hit-target compensated with 4px of surrounding padding inside the row container (total clickable area ≥ 44px square). Workspace switcher trigger button is 36px tall on desktop and 44px tall on mobile (responsive sizing — mobile uses the existing `Button size="lg"` token).

Exceptions: none beyond the IconButton + responsive switcher sizing already established.

## Typography

Source: `src/index.css:79-110`. This phase uses **exactly 4 sizes** + a single optional display row, and **2 weights** (400 regular + 600 semibold). Italic 400 Fraunces is permitted only for the "Workspace created" success state heading (carry-forward of Phase 8's display-heading convention).

| Role | Size | Weight | Line Height | Font | Token |
|------|------|--------|-------------|------|-------|
| Body | 15px (0.9375rem) | 400 | 1.55 | Inter | `text-base` |
| Label / metadata | 13px (0.8125rem) | 400 | 1.5 | Inter | `text-sm` |
| Heading (section/modal/tab) | 18px (1.125rem) | 600 | 1.5 | Inter | `text-lg` |
| Page heading (workspace home, settings page title, consent dialog title) | 26px (1.625rem) | 600 | 1.25 | Inter | `text-2xl` |
| Mono (slug input, invitation token preview, permission keys in role grid) | 13px | 400 | 1.5 | JetBrains Mono `tnum` | `text-sm font-mono` |
| Display (optional — "Workspace created" success state heading only) | 26px italic | 400 | 1.25 | Fraunces | `text-2xl heading-display` (existing class) |

**Numerals contract:** Member counts, joined_at relative-time, expiry-remaining counters in the Members tab MUST use `numerals-tabular` class so digits align column-wise — matches existing Settings number presentation across Phases 6/7/8.

**Permission key contract:** Permission keys (e.g. `org.read`, `patient_photos.read`) in the role-permission grid render in `font-mono text-sm` so operators can scan them like code identifiers. Permission descriptions next to each key render in `text-sm` regular weight.

**Reduced-motion:** Page-heading and modal-open animations honor `prefers-reduced-motion: reduce` via the existing global CSS rule at `index.css:485`. The org-create wizard step transitions, workspace-switcher dropdown reveal, and consent dialog reveal are all gated on the reduced-motion query.

## Color

The LeanShot palette is "clinical warmth": cream-100 surface, teal-700 hero/primary, sage/rose/amber as semantic accents. The 60/30/10 distribution is identical to Phase 8. Source tokens: `src/index.css:11-77` (light) + `:158-203` (dark).

| Role | Light value | Dark value | Usage |
|------|-------------|------------|-------|
| Dominant (60%) | `--color-bg` `#efebe0` (cream-100) | `#0b1413` (teal-950) | Page background of workspace home + ClinicSettingsPage + ConsentDialog backdrop + Active organizations section |
| Secondary (30%) | `--color-surface` `#fdfbf6` (cream-card) | `#16201e` (teal-900-ish) | Settings tab cards, members list rows, invite modal body, role-permission grid card, workspace switcher dropdown panel |
| Accent (10%) | `--color-primary` `#1b4842` (teal-700) | `#6fcbb8` (teal-300) | Primary CTAs only (see reserved-for list below); focus rings; system-role badge fill; workspace-switcher active-context indicator |
| Destructive | `--color-danger` `#cf5454` (clay) | `#da6f6f` | Revoke-membership button, Delete-role button, hard-401 toast icon, typed-confirm modals |
| Warning | `--color-warning` `#e37748` (orange) | `#e37748` | Expired-invite Pill, "Couldn't upload logo" inline warning, 7-day-expiry-warning chip on Members tab — NOT used as a CTA |

**Accent reserved-for list (the only places `--color-primary` appears as a fill or strong stroke):**
1. Primary CTA buttons: `Create workspace`, `Send invitation`, `Accept and join`, `Save changes`, `Invite patient` (workspace home + invite modal), `Create role`
2. Focus-visible outline (existing `:focus-visible` rule at `index.css:298`)
3. Workspace switcher: active-context indicator (left-edge 2px stripe on the currently-selected row)
4. System-role badge fill (`Owner`, `Coach`, `View-only`) when displayed in the Members list and workspace switcher
5. Active-membership Pill on Active organizations rows (label `"Active"`)
6. Org logo monogram fallback background (when no logo uploaded; renders org-name-initial in cream on teal-700)
7. Help-link copy underline inside the consent dialog disclosure ("What does each permission mean?")

**Accent NOT used for:**
- Body text
- Card backgrounds
- Disabled states (use `--color-text-tertiary`)
- Non-primary buttons (use `secondary` or `ghost` Button variants from `Button.tsx:34-41`)
- Clinic logos themselves — logos are operator-uploaded brand assets and may be any color; the surrounding chrome (badge background, ring) uses the teal-700 token. The org logo is treated as imagery, not as the app's brand affordance.

**Destructive reserved-for list:**
1. `Revoke membership` button on Active organizations row (uses `Button variant="destructive"`)
2. `Delete role` button inside RolesTab (custom roles only — system roles do not show the action)
3. `Revoke invite` IconButton (Trash2) on Members tab pending-invites list
4. `Revoke access` IconButton (Trash2) on Members tab active-members list
5. Hard-401 toast on operator drill-in revoke event: `XCircle` icon in `--color-danger`
6. Typed-confirm ConfirmModal `destructive=true` for all four destructive actions above
7. `Decline` button on ConsentDialog (secondary destructive variant — see component inventory)

**Warning reserved-for list:**
1. Expired-invite Pill on Members tab (label `Expired`)
2. Expiry-imminent invite chip (`Expires in 2 days`) on Members tab pending-invites
3. "Couldn't upload logo — file too large" inline message in org-create flow + Workspace settings tab
4. `[COUNSEL REVIEW NEEDED]` placeholder banner in ConsentDialog BAA/HIPAA section (see Copywriting Contract D-04 deferred decision) — visually warning-colored so legal team cannot ship by accident

**Color contrast notes:** Destructive `clay #cf5454` on cream-card `#fdfbf6` → 4.59:1 (AA passes for body text — same as Phase 8). System-role Pill teal-700 fill with cream text → 8.42:1 (AAA). Warning `orange #e37748` on cream-card → 3.71:1 (passes AA for large text 18px+ only; the warning Pill renders at 13px so it gets a darker text token `--color-text-on-warning` to compensate — Pill component handles this via existing tone="warning" variant).

All copy is reviewable in a single grep against `src/components/clinic/` + `src/components/clinic-invite/` + `src/components/dashboard/settings/ActiveOrganizationsSection.tsx`.

## Interaction Contracts

### Org-create flow (operator's first action after sign-up or "Create workspace")

1. Operator clicks `Create a new workspace` (from WorkspaceSwitcher footer) OR completes new-user signup → `OrgCreateFlow` mounts.
2. Step 1: workspace-name Input auto-focuses. Slug Input auto-derives from name on every keystroke (lowercased, kebab-cased, special chars stripped) and is independently editable — once the operator edits the slug, name-edits no longer overwrite it (debounced 200ms).
3. Slug uniqueness checks fire on blur (debounced) against an Edge Function; inline error renders in destructive red below the field if taken/reserved/invalid.
4. Logo upload: drag-drop OR click-to-upload (reuse Phase 6 photo upload affordance). File validated client-side (2 MB, PNG/JPEG). Preview shows 64x64 square crop. If skipped, monogram fallback renders.
5. `Create workspace` button enables only when name + slug are valid (logo optional).
6. Submit → POST to org-create Edge Function → on 200: transition to success state with `Workspace created` heading (Fraunces italic) + workspace URL displayed. On 4xx/5xx: inline error preserving form state.
7. Success-state CTA `Invite first patient` → routes to `/clinic/{slug}` AND opens InvitePatientModal in the same transition (no intermediate empty roster shell flash).
8. Alternative CTA `Go to workspace` → routes to `/clinic/{slug}` showing empty roster shell.

### Invite patient flow (operator)

1. Operator clicks `Invite patient` (workspace home empty state OR Members tab CTA) → InvitePatientModal opens with email Input auto-focused.
2. Operator enters email; validation runs on blur (inline error for malformed addresses).
3. Scope-preselect checkboxes default to all 10 enabled. Operator can uncheck any to indicate "we typically don't need this." These pre-fill the patient's ConsentDialog.
4. `Send invitation` enables when email is valid. Submit → POST to `/clinic-invite/send` Edge Function with email + requested_scope jsonb.
5. **Anti-enumeration (D-02):** Modal ALWAYS transitions to post-send confirmation state showing `Invitation sent` regardless of whether the email exists in `auth.users`. The Edge Function branches server-side at the moment of acceptance, not now.
6. Post-send state: `Invitation sent` heading + body with email + 7-day expiry note + `Done` / `Invite another patient` actions.
7. Done → modal closes; Members tab optimistically prepends a pending-invite row (if the operator is on Members tab) OR no UI change (if on workspace home).
8. Failure (network/server error) → toast `Couldn't send invitation…` + modal stays open with form preserved.

### Workspace switcher interaction (Pitfall #8 invariant)

1. Switcher trigger is in the top-left of the app shell on every authenticated route (between sidebar and topbar on desktop; in topbar on mobile).
2. Click → dropdown opens (desktop) or Sheet slides up from bottom (mobile, reusing existing `Sheet.tsx`).
3. Three groups render in fixed order: `Personal account` → `Memberships` → `Workspaces I run`. Groups 2 and 3 render their empty hints when zero rows exist.
4. Each row shows: avatar (org logo or monogram or LeanShot wordmark for personal) + label + subtitle + role badge (groups 2/3 only).
5. The currently-active context has a 2px teal-700 left-edge stripe + `aria-current="true"`.
6. Click a row → routes to that context's home (`/` for personal, `/clinic/{slug}` for workspaces, future Phase 10 route for memberships). Switcher closes.
7. Footer action `Create a new workspace` → routes to OrgCreateFlow.
8. Keyboard: arrow keys navigate rows within a group; tab moves between groups; enter activates; escape closes. Focus returns to trigger button on close.

### Patient invitation acceptance (D-16 branching state machine)

1. Patient clicks Resend-emailed `Review invitation` button → lands on `/clinic-invite/{rawToken}`. ClinicInvitePage mounts in lazy chunk.
2. Edge Function GET `/clinic-invite/{rawToken}` hashes the token, looks up `invites` row, evaluates state:
   - **expired** → state E
   - **already used** (accepted_at OR rejected_at set) → state F
   - **canceled** (consumed_at set with rejected_at) → state G
   - **valid + auth.getUser() returns user** → state B (ConsentDialog, prefilled with `invites.requested_scope`)
   - **valid + auth.getUser() returns null + email exists in auth.users** → state C (sign-in prompt)
   - **valid + auth.getUser() returns null + email does NOT exist** → state D (signup wizard)
3. State C: patient enters email → `supabase.auth.signInWithOtp({ email })` → confirmation message → on return-from-email-link, ClinicInvitePage re-mounts (still on `/clinic-invite/{rawToken}` route since the OTP redirect carries the URL), now hits state B.
4. State D: patient enters email + password → `supabase.auth.signUp({ email, password })` → confirmation pending message → on confirmation-link click, returns to `/clinic-invite/{rawToken}`, hits state B.
5. State B (ConsentDialog): checkboxes pre-filled from `invites.requested_scope`. Patient unchecks any they don't want to share. Excluded-data note always visible. BAA placeholder banner visible.
6. `Accept and join` → POST `/clinic-invite/accept` with current checkbox state as `consent_scope` jsonb. Edge Function: validates token hash, validates auth.users existence, INSERTs `memberships` row with `consent_scope_at_acceptance` snapshot, sets `invites.accepted_at + consumed_at` (D-18), returns 200. UI transitions to accepted-state heading `You're connected`.
7. `Decline` → confirmation modal → `Decline invitation` → POST `/clinic-invite/reject` → 200 → toast `Invitation declined.` + state F (already used) display.
8. Network failures → state H (generic load error) OR inline toast for accept/decline attempts.

### Active organizations management (patient — D-06, D-15)

1. Patient opens Settings → `Active organizations` tab (NAV position locked above).
2. List loads via Edge Function `GET /memberships?as=patient`. Skeleton rows during load.
3. Each row shows org logo + name + role + joined relative-time + scope summary + edit/revoke IconButtons.
4. Edit scope → EditConsentScopeModal opens with current `memberships.consent_scope` state. Patient toggles checkboxes. `Save changes` → PATCH `/memberships/{id}` with new consent_scope jsonb → 200 → toast + modal closes + row scope summary updates.
5. Revoke → typed-confirm ConfirmModal → `Revoke membership` → PATCH `/memberships/{id}` with `revoked_at = now()` → 200 → toast + row animates out + Realtime broadcast hits operator's roster + drill-in (D-10).
6. **Realtime cross-context broadcast:** If the operator revokes the patient WHILE the patient is viewing Active organizations, the patient sees a toast `{org name} ended your membership.` + the row animates out automatically (no manual refresh).

### Operator drill-in revoke handling (D-10, D-11)

1. Operator clicks a patient roster row → drill-in (Phase 10 will build the full drill-in surface; Phase 9 contract describes only the revoke handling).
2. Every drill-in data fetch hits an Edge Function that checks `memberships.revoked_at IS NULL` AND `memberships.consent_scope.{requested_resource} = true`.
3. If revoked or scope no longer permits: Edge Function returns 401 (revoked) or 403 (scope insufficient).
4. UI catches the status and:
   - 401 → toast `{patient first name} revoked access. Returning to roster.` + route back to `/clinic/{slug}` within 1 second (SC#5).
   - 403 → toast `{patient first name} updated what they share. This data is no longer available.` + clear the affected section in the drill-in (do NOT navigate away; other permitted sections stay visible).
5. **Realtime parallel path:** Operator's workspace home subscribes to a `memberships` channel filtered by `org_id`. On UPDATE with `revoked_at != null`, the roster row removes within ~100-300ms — toast `{patient first name} is no longer a member of this workspace.` surfaces. This is the UX layer; the Edge Function 401 in step 3 is the security floor.

### Clinic-scoped photo access (D-12, D-13)

1. Operator's drill-in (Phase 10) renders a `<ClinicPhoto />` component for each patient body photo.
2. Component mounts → fetches signed URL from Edge Function `GET /clinic/{orgId}/patient/{userId}/photo/{photoId}`.
3. Edge Function checks: (a) membership active for org, (b) operator's role has `patient_photos.read`, (c) patient's `consent_scope.photos === true`, then mints a 5-minute signed URL via Supabase Storage.
4. Component renders `<img src={signedUrl} />`. On 401/403, renders the existing "no access" placeholder.
5. **5-minute TTL tradeoff (D-13):** Component does NOT pre-fetch or cache signed URLs. Each photo render triggers one Edge Function call. Stale-URL window for already-loaded photos is up to 5 min post-revoke — explicitly accepted Phase 9 tradeoff documented in CONTEXT.md and visible in security review notes.
