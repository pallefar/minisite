# Phase 02.1 Plan 04: CI Regression Guards (lhci SPA targeting + chunk-size assertion) Summary

**One-liner:** Filtered the lighthouse CI job to the SPA Vercel preview via `wait-for-vercel-preview`'s `check_name` input, and wired the Wave 1 vendor-react chunk-size assertion script into the test-e2e job — closing the two CI bugs that allowed Phase 2 to ship at Lighthouse Performance 0.74 without any guard rail catching it.

## What Shipped

Two atomic edits to `.github/workflows/ci.yml`:

1. **Lighthouse job now targets the SPA project specifically.** Added `check_name: 'leanshot-app – Vercel'` to the `wait-for-vercel-preview@v1.3.2` step. Previously the action returned the first preview URL it discovered, and `leanshot-marketing` alphabetises before `leanshot-app` — so lhci had been silently scoring the marketing site (~1.00) instead of the SPA (~0.74). The CI badge was green while SPA performance failed SC#1.

2. **Vendor-react chunk-size assertion runs on every PR.** Inserted a new step into the `test-e2e` job that runs `bash scripts/assert-vendor-react-size.sh` immediately after the production build. The script is non-skippable (no `continue-on-error`); if vendor-react gz drops below the floor — for example, by reverting `vite.config.ts` from function-form to object-form `manualChunks` — the PR fails before merge.
