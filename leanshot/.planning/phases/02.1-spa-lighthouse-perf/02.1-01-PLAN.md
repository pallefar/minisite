## Trust Boundaries

| Boundary | Description |

| CI script → developer machine | `assert-vendor-react-size.sh` runs locally during pre-flight checks; arbitrary input via the chunk filename glob |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.1-01 | Tampering | manualChunks regex | mitigate | Anchored regex (`/node_modules\/(...)(\/|$)/`) prevents project source paths or unrelated packages (`@use-gesture/react`, `preact`, etc.) from being routed into vendor chunks per RESEARCH P1 |
| T-02.1-02 | Denial-of-Service | Build pipeline | mitigate | Preserve the typecheck pre-step (`tsc -b` ahead of `vite build`) — a malformed manualChunks signature breaks the build BEFORE deployment; CI's typecheck job catches it earlier still |
| T-02.1-03 | Information Disclosure | Source maps | accept | Sentry plugin's `filesToDeleteAfterUpload: ['./dist/**/*.map']` continues to short-circuit on missing token (Preview); `sourcemap: 'hidden'` ensures no public `sourceMappingURL` even if a `.map` slips past — UNCHANGED FROM PHASE 2, this plan does not weaken it |
| T-02.1-04 | Spoofing | Chunk-size assertion | mitigate | Script uses `find -type f -name 'vendor-react-*.js' -not -name '*.map'` to disambiguate chunk vs source map; floor (30 kB gz) is well above the scheduler-only ride-along (~3 kB gz); ceiling (80 kB gz) catches accidental over-bundling beyond the predicted 50-60 kB gz; index ceiling (50 kB gz) pins the topology so partial collapses are caught even if vendor-react stays in the floor-ceiling band |
