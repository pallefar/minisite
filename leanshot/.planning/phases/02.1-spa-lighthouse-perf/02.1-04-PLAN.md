<objective>
Fix two CI bugs that allowed the Phase 2 regression to ship without any guard rail catching it. **These fixes land independent of which performance lever (Wave 1 / 2 / 3) ultimately reaches Lighthouse 0.90** — they protect against future regressions of this exact class.

Two CI improvements bundled into one plan because both touch the single file `.github/workflows/ci.yml`:

**Fix 1 — Lighthouse CI scores the SPA, not marketing (RESEARCH P6 / SC#1).**
Today, `wait-for-vercel-preview@v1.3.2` returns the FIRST preview URL it discovers, and `leanshot-marketing` alphabetises before `leanshot-app`. So the lhci job has been silently scoring marketing (~1.00) instead of the SPA (~0.74). The CI badge says green; the actual SPA performance was failing the SC#1 floor. Fix the action's filtering so it targets the SPA project's GitHub check name.

**Fix 2 — Chunk-size assertion runs in CI on every PR (SC#2).**
Wave 1 created `leanshot/scripts/assert-vendor-react-size.sh`. CI must invoke it after `npm run build` so any future PR that breaks the chunking topology (e.g., reverts function-form to object-form, or refactors imports in a way that pulls react-dom out of vendor-react) fails the PR before merge.

Purpose: Make the regression class structurally impossible to ship silently again. Phase 2 shipped at 0.74 because (a) CI was scoring the wrong project and (b) there was no chunk-shape guard. This plan fixes both.

Output:
- Updated `.github/workflows/ci.yml` lighthouse job filtered to the SPA project
- New step (in test-e2e job, which already runs `npm run build`) OR new dedicated job that invokes the chunk-size assertion script
</objective>
