         return {

           apply: 'build',
           transformIndexHtml: {

             handler(html, ctx) {

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Build pipeline → CDN | The plugin runs at build time and emits a static `<link>` in `dist/index.html`; the link's URL is derived from Vite's bundle map (no user input) |
| Browser → CDN | Browser parses the modulepreload link and issues a same-origin GET; CSP `script-src 'self'` enforces same-origin |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.1-05 | Tampering | Plugin html.replace | mitigate | Replacement target is the literal string `</head>` (only one occurrence in a well-formed Vite-emitted HTML); injected href is taken from Vite's `ctx.bundle` (build-time data, no user input) — no template injection vector |
| T-02.1-06 | Information Disclosure | Modulepreload link | accept | The link reveals the hashed chunk filename, but Vercel serves the same chunk filename in the entry's `<script>` tag regardless. No new disclosure surface. |
| T-02.1-07 | DoS via duplicate link | Browser preload cache | mitigate | Idempotency check (`html.includes(\`href="${href}"\`)`) prevents double-injection if Vite auto-emits the link. Browsers also deduplicate same-href modulepreload links per the HTML spec, providing defense-in-depth |
| T-02.1-08 | CSP bypass | script-src enforcement | accept | `script-src 'self'` allows same-origin modulepreload (RESEARCH §"CSP × modulepreload"); future move to nonce-based CSP would require updating the plugin to inject a nonce attribute (carry-forward note in SUMMARY) |
</threat_model>
