# Milestone: v1.5 — Best-in-Class

## Goal

Elevate LeanShot from launch-ready to best-in-class by closing the five structural blind spots surfaced in the 9-dimension multi-agent audit of 2026-06-01: crash resilience (no error boundary anywhere), shared-primitive accessibility debt (81 Modal/Sheet sites without focus trap), headline-feature observability and test gaps, silently broken production Sentry symbolication, and a 100%-client-rendered public content surface that is invisible to crawlers and LLMs. A dedicated eighth phase addresses the 646-finding backend performance advisory (`auth_rls_initplan` rewrite, FK indexes, redundant-policy consolidation). This milestone derives from `BEST-IN-CLASS-AUDIT-2026-06-01.md`.

**Prerequisite**: v1.4 UAT gate (Phase 70) passed and `main` branch deployed.

**Quick-wins branch**: Several Phase 1 and Phase 2 starters were shipped in `feat/v1.5-resilience-a11y-quickwins` as safe now changes. Specifically: `MotionConfig reducedMotion="user"` in `src/App.tsx`, skip-to-content link in `src/components/layout/AppShell.tsx`, `role="log"` + `aria-live="polite"` on `AIChatPanel.tsx`, Sentry `release` wiring in `src/lib/telemetry-defer.ts`, dangling `·` separator fix in `src/components/layout/GreetingStrip.tsx:51-56`, offline banner truthful copy in `src/components/pwa/OfflineBanner.tsx`, and root + per-tab error boundary scaffold. These items are marked **[started]** in the phase scopes below — do not double-count them.

**Scope**:

- `src/App.tsx:1597`, `src/lib/pwa/register.ts` — capture discarded `updateSW` return value; PWA "New version" toast becomes actionable (`updateSW(true)`) **[started]**
- `src/components/pwa/OfflineBanner.tsx`, `src/lib/pwa/offline-store.ts` — truthful offline copy + delete dead `disableLogging()` gate **[started]**
- `src/lib/sync.ts` — permanent (4xx) cloud-sync failures currently silently drop the queued op; add `captureException` + one-time user toast
- `src/components/dashboard/ai/AIChatPanel.tsx` — AI-coach retry affordance (degradation collapses error types with no retry path)
- `scripts/assert-bundle-budget.sh` — bump `admin-shell` ceiling 137→138, drop stale `cancellation`/`WhatsNewDrawer` chunk-name entries so E2E merge gate is green

**Success Criteria** (what must be TRUE):

### Phase 79 — DB Performance (Backend)

**Goal**: Close the 520 highest-ROI backend performance findings from the Supabase advisor (`get_advisors` run 2026-06-01 against project `ytnsipxxmzgaebkqmokp`): rewrite `auth_rls_initplan` policies to evaluate `auth.uid()` once per query, add covering indexes on 106 unindexed foreign keys, consolidate 135 redundant overlapping RLS policies, and drop the 126 unused-index dead weight. All changes are migration-only; no app-layer code changes required.

**Scope**:
- **279 `auth_rls_initplan` rewrites** — every RLS policy using `auth.uid()` directly instead of `(select auth.uid())` re-evaluates on every row; wrapping in a scalar subquery promotes it to a single plan-time evaluation. Mechanical find-and-replace across all `supabase/migrations/`; must test on a local branch before `db push`. Highest-ROI single change in the entire audit.
- **106 unindexed foreign keys** — each missing index slows JOINs and cascades (the test-account purge cascade being the example at risk); add `CREATE INDEX CONCURRENTLY IF NOT EXISTS` migrations for each FK, grouped by table
- **135 redundant / multiple-permissive policies** — overlapping policies on the same table+role+action combination cause per-row overhead; consolidate to one policy per `(table, role, command)` tuple where safe
- **126 unused indexes** — remove drop candidates identified by the advisor; each drop must be verified against the query plan of any RPC or direct query that might use it (consult `pg_stat_user_indexes.idx_scan`)
- **1 leaked-password protection** — operator-only 1-click: enable "Leaked password protection" in Supabase Auth dashboard (not a migration; document in operator runbook)
- **2 always-true RLS policies** — investigate the 2 advisor findings for potential data over-exposure; fix or document justification
- **4 listable public buckets** — review for intended vs accidental list access; restrict or document

**Success Criteria** (what must be TRUE):
1. `get_advisors` re-run on `ytnsipxxmzgaebkqmokp` post-migration shows `auth_rls_initplan` count reduced to 0
2. `get_advisors` shows unindexed FK count reduced by ≥90 (some may legitimately be low-traffic FKs; document exceptions)
3. `get_advisors` shows multiple-permissive-policies count reduced by ≥100
4. `get_advisors` shows unused-index count reduced by ≥80 (conservative; retain indexes with recent idx_scan activity)
5. All migrations apply cleanly via `supabase db push` on a branch database before remote push
6. Operator runbook documents leaked-password-protection enable step + the 2 always-true policy dispositions

**Depends on**: Phase 72 recommended (error capture operational before DB changes ship to prod); independent of Phases 73-78
**Effort**: ~5 plans (migration-heavy; each plan covers one finding category with careful `CONCURRENTLY` + rollback notes) | `autonomous: true`
